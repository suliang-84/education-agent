## 1. 产品一句话定义与核心假设

### 1.1 产品定义

> **MESH 是一款面向初中至高中生的数理化 AI 认知训练平台，通过五力认知诊断驱动个性化学习，让每位学生获得了解自己思维短板的专属 AI 老师。**

### 1.2 核心假设（产品成立的前提）

| 假设 | 描述 | 风险等级 |
|------|------|----------|
| **假设 H-01** | 中学生数理化学习困难的根本原因是认知能力薄弱，而非知识积累不足 | 🟡 中（需真实数据验证） |
| **假设 H-02** | 五力模型（洞察/建构/推演/调适/迁移）能有效区分不同学生的认知差异 | 🟠 中高（需算法科学性论证） |
| **假设 H-03** | 学生愿意用文字与 AI 对话解题，而不仅仅是看答案 | 🟡 中（需 UX 测试验证） |
| **假设 H-04** | 五力画像驱动的个性化选题，比随机选题有显著更好的学习效果 | 🟠 中高（需 A/B 测试） |

### 1.3 与竞品的核心差异

| 维度 | 普通 AI 答题工具 | MESH |
|------|----------------|------|
| 核心逻辑 | 学生提问 → AI 给答案 | 学生答错 → AI 改变介入位置和方式 |
| 个性化方式 | 按知识点匹配题目 | 按知识点 × 五力画像 × 优势入口匹配 |
| AI 目标 | 做对这道题 | 训练对应认知能力 |
| 评估标准 | 答题正确率 | 五力成长变化 |

## 2. V1.0 交付范围与最小可行版本

### 2.1 V1.0 必须完成（P0）

```
核心验收链路：
注册/登录 → 五力测试（20题）→ 生成五力画像 → 选择知识点训练
→ AI 定向指导（RAG） → 保存训练结果 → 再测对比成长
```

| 功能 | 模块 | 优先级 | 说明 |
|------|------|--------|------|
| 微信授权登录 + 手机号绑定 | 01_登录 | P0 | 无需家长双验证 |
| 五力认知测试 20 题 | 02_五力测试 | P0 | 含测试中断/恢复 |
| 五力画像生成（三层输出） | 02_五力测试 | P0 | ability/preference/final |
| 雷达图展示 + 文字解读 | 02_五力测试 | P0 | AI 异步生成文字分析 |
| 知识点四级导航（学科→年级→章节→知识点） | 03_训练 | P0 | 需题库支持 |
| 五力权重选题算法 | 03_训练 | P0 | 依赖五力画像 |
| 训练题目展示 + 答题交互 | 03_训练 | P0 | 含答对/答错判定 |
| RAG 解题思路生成（答错后） | 03_训练 | P0 | 双路召回 + 降级 |
| 训练结果保存 + 训练画像更新 | 03_训练 | P0 | 异步处理 |
| AI 助教自由提问（文字对话） | 04_助教 | P0 | 含启发策略 |
| AI 主动介入（连续答错≥2次） | 04_助教 | P0 | 与 03 协同 |
| 错题集管理 | 03+04 | P0 | 跨模块状态机 |
| 五力成长对比（再测） | 02_五力测试 | P0 | 双色雷达图叠加 |
| 管理后台：题库管理 | 后台 | P0 | 题目录入、五力标注审核 |
| 管理后台：数据看板 | 后台 | P0 | 基础数据展示 |

### 2.2 V1.0 不做（延后至 V1.1 或 V2.0）

| 功能 | 原因 |
|------|------|
| 家长端查看报告 | P1，不阻断核心链路 |
| 教师端班级学情 | P2，V1.1 引入 |
| OCR 拍照上传题目 | P1，V1.1 引入 |
| 策略有效性画像对学生展示（学习风格） | V1.1 |
| 每日推送与时长提醒 | V1.1 |
| 高中选修模块题库 | 暂不建设 |

### 2.3 V1.0 目标种子用户

- **目标：** 首批 500 名真实学生用户完成完整学习闭环
- **优先覆盖：** 初三数学 + 高一数学（其余学科在题库建设后开放）
- **验证目标：** 五力画像能否有效区分不同学生的认知差异

## 3. 完整用户旅程（端到端）

### 3.1 用户旅程全景

```
Phase 1：入门
┌──────────────────────────────────────────────────────────┐
│  打开小程序                                               │
│    ↓                                                     │
│  [首次] 微信授权 → 手机号验证 → 账号创建                  │
│  [再次] 静默登录（wx.login + Token 校验）                 │
│    ↓                                                     │
│  检查：是否有 five_power_profiles 记录？                   │
│    ├── 无 → 全屏引导页，强引导完成五力测试               │
│    └── 有 → 进入首页（Tab 1 默认选中）                   │
└──────────────────────────────────────────────────────────┘

Phase 2：诊断（首次必经，重测可选）
┌──────────────────────────────────────────────────────────┐
│  五力认知测试（20 题）                                    │
│    ↓                                                     │
│  计算三层输出：                                           │
│    ability_score（能力分）= 标准答案题得分                │
│    preference_score（入口分）= 选项权重累加归一化          │
│    final_score（综合分）= ability×70% + preference×30%   │
│    ↓                                                     │
│  生成五力画像（AI 异步文字解读）                           │
│    ↓                                                     │
│  展示雷达图 + 学习模式推荐卡：                            │
│    有薄弱力：推荐 TRAIN_WEAKNESS（补足你的力）              │
│    均衡型：推荐 LEARN_BY_STRENGTH（一通百通）              │
│    ↓                                                     │
│  [开始个性化训练] 或 [先和 AI 聊聊]                       │
└──────────────────────────────────────────────────────────┘

Phase 3：学习（高频，每日）
┌──────────────────────────────────────────────────────────┐
│  首页（三 Tab）                                           │
│  ┌────────┬──────────┬──────────┐                        │
│  │Tab 1   │Tab 2     │Tab 3     │                        │
│  │个性化训练│AI 助教   │我的五力  │                        │
│  └────────┴──────────┴──────────┘                        │
│                                                          │
│  [路径A：Tab 1 个性化训练]                                │
│    选择知识点 → 生成 5 题专属题卷                         │
│    逐题作答：                                             │
│      答对 → 沉默，进入下题                               │
│      答错 → RAG 生成解题思路（≤8s，超时降级）             │
│           → 连续答错≥2次 + 满足5条件 → 04模块悬浮介入    │
│    训练结束 → 生成小结 → 异步更新五力训练画像              │
│                                                          │
│  [路径B：Tab 2 AI 助教]                                  │
│    自由提问 → AI 多维启发（9种策略）                      │
│    错题复盘 → 苏格拉底式对话                              │
│    产生理解突破 → 成就感反馈                              │
│    AI 推荐实战检验 → 微训练（2~3题）浮层                  │
└──────────────────────────────────────────────────────────┘

Phase 4：成长闭环
┌──────────────────────────────────────────────────────────┐
│  Tab 3 我的五力                                           │
│    查看五力历史成长曲线                                   │
│    选择两次测试对比 → 双色叠加雷达图                      │
│    查看各力详细分析 + 训练建议                            │
│    ↓                                                     │
│  重测五力测试（间隔≥30天推荐）                            │
│    生成新画像 → 自动与历史对比 → 展示成长                 │
└──────────────────────────────────────────────────────────┘
```

### 3.2 跨模块数据流

```
[五力测试完成]
      │ 写入 five_power_profiles（is_latest=true）
      ↓
[个性化训练开始]
      │ 读取 five_power_profiles + five_power_training_profiles
      │ 计算五力权重 → 生成题卷 → 写入 training_sessions
      ↓
[答题过程]
      │ 写入 training_answer_records（每题）
      │ 答错 → 异步写入 wrong_answer_records（review_status=unreview）
      │ 答错 → 异步触发 RAG（Queue-C）
      │ 连续答错≥2 → 触发 ai_chat_sessions 创建
      ↓
[训练结束]
      │ 异步更新 five_power_training_profiles（衰减系数0.30）
      │ 生成训练小结
      ↓
[AI 助教对话]
      │ 读取 five_power_profiles + wrong_answer_records
      │ 写入 ai_chat_messages
      │ 产生理解突破 → 更新 wrong_answer_records（review_status=aha_achieved）
      │ 异步更新 ai_student_strategy_profiles（策略有效性）
      ↓
[五力画像综合查询]
      │ training_score × 0.6 + test_score × 0.4 = 综合五力得分
      └─ 用于下次选题权重计算
```

## 4. 用户旅程断点与修复方案

### 4.1 断点 D-01：新用户跳过五力测试

**场景：** 新用户点击"稍后再说"后进入首页，没有五力画像，无法使用 Tab 1。

**修复方案：**

```
进入 Tab 1（无五力画像时）：
  展示引导占位页，而非空白或报错
  ┌────────────────────────────────────────────┐
  │                                            │
  │     🧠  先了解一下你的学习方式              │
  │                                            │
  │  完成 5 分钟五力测试，AI 才能为你           │
  │  生成专属训练方案                           │
  │                                            │
  │        [开始五力测试]                      │
  │                                            │
  └────────────────────────────────────────────┘
```

**规格补充（补充至 02_五力认知测试模块 §7.1）：**
- 无五力画像时，Tab 1 显示引导占位页（不展示知识点选择器）
- 顶部五力状态卡在无数据时显示"完成测试解锁" + 测试入口

---

### 4.2 断点 D-03：知识点选择器中可用/不可用的区分

**场景：** 学生选择某知识点，但该知识点可用题目不足 5 道（未达到开放门槛）。

**修复方案：**

```
知识点选择器 UI 规格：
  ✅ 可用知识点（题目≥5道）：正常显示，可点击
  ⚠️ 建设中知识点（题目1~4道）：灰色显示，点击弹出提示
     "该知识点题库建设中（已有X道），预计XX日开放"
  ❌ 未建知识点（题目=0道）：隐藏（不显示）

数据接口：
  GET /api/knowledge-points?subject=math&grade=g9
  返回字段新增：{ available: true, question_count: 12 }
```

**规格补充（补充至 03_个性化AI训练模块 §7.1）：**
- 知识点选择器接口返回 `available` 和 `question_count` 字段
- 前端按可用性分类展示

### 4.3 断点 D-04：RAG 答错展示的降级体验

**场景：** 学生答错，RAG 超时（>8s），从"AI 正在思考…"突然切换为"展示静态解析"，心理落差大。

**修复方案（完整降级流程）：**

```
T=0：学生提交答案
T=0 + 200ms：前端展示 "❌ 回答错误"，同时启动骨架屏
  骨架屏文案："AI 正在从你的薄弱维度分析解题思路…"

T=3s：骨架屏加上进度条（视觉告知正在处理）

T=8s：如 RAG 未返回：
  ├─ 后台触发降级
  ├─ 查询 questions.solution 字段
  ├─ 如 solution 存在：
  │   展示参考解析，角落标注"⚡ 参考解析"（区分于 AI 回复样式）
  │   文案："AI 助手暂时繁忙，这是题目参考解析供参考"
  └─ 如 solution 不存在：
      展示"AI 助手暂时繁忙，建议查看教材对应章节"
      提供[重新生成]按钮（3次机会）

T=15s：RAG 若仍未返回，彻底放弃，清除骨架屏

视觉区分：
  AI 实时回复 → 蓝色背景，"🤖 AI 解题思路"标题
  静态降级   → 浅灰背景，"⚡ 参考解析"标题
```

---

### 4.4 断点 D-05：04 模块悬浮介入的交互细节

**场景：** 学生连续答错≥2次，04 模块要主动介入，但目前仅定义"展示悬浮条"，缺乏完整交互规格。

**修复方案：**

```
悬浮条样式：
┌─────────────────────────────────┐
│  💬 AI 助教有话说               │
│  "你在这道题上遇到困难了，我来   │
│   帮你分析一下条件？"           │
│             [展开对话] [稍后]   │
└─────────────────────────────────┘
位置：答题卡下方，不遮挡题目内容

[展开对话]：
  → 在当前页面弹出内嵌浮层（底部抽屉式，占屏幕50%）
  → 浮层内是 AI 助教对话界面
  → 可以一边查看题目一边对话
  → [收起]按钮折叠浮层，回到纯做题视图

[稍后]：
  → 悬浮条收起，设置 silence_mode=true（当前知识点）
  → 在训练结束小结页提醒："AI 有为你准备解析，查看错题集"

用户主动召唤：
  → 任何时候点击右下角"💬"按钮 → 打开 Tab 2 AI 助教
  → 或长按答题界面 → 弹出"向 AI 提问"快捷入口
```

### 4.5 断点 D-06：跨 Tab 切换的训练状态保持

**场景：** 学生在 Tab 1 训练到第 3 题，切换到 Tab 2 聊天，再切回 Tab 1，训练会话是否还在？

**修复方案：**

```
训练会话持久化规则：
  1. training_session 存储于服务端，状态 = active
  2. 切换 Tab 不影响会话，前端重新渲染时恢复当前题目
  3. 退出小程序后：
     ├─ 如已答题但未完成：training_session 保持 active，保留 72h
     └─ 重新进入时：提示"你上次训练进行到第 X 题，继续吗？"

前端实现要求：
  - Tab 1 的组件状态使用全局状态管理（Vuex/Pinia）
  - 切 Tab 时不销毁 Tab 1 组件，仅隐藏
  - 页面路由使用 keep-alive 保留答题进度
```

### 4.6 断点 D-08：五力训练画像异步更新的用户感知

**场景：** 学生完成训练，五力画像异步更新，但下次训练用的还是旧画像（5分钟内）。

**修复方案：**

```
前端提示规范：
  训练结束时，在小结页展示：
  "🔄 你的五力数据正在更新，通常在 5 分钟内完成"

  更新完成后，推送微信模板消息（可选）：
  "你的五力数据已更新，查看最新画像 →"

  若学生在 5 分钟内开始新训练：
  ├─ 使用旧画像（可接受，数据更新频率本就不是实时的）
  └─ 在训练入口提示"正在使用上次的能力数据"（小字）

SLA 要求（补充至性能约束）：
  五力训练画像异步更新延迟：目标 ≤ 5 分钟（P95）
```

### 4.7 断点 D-10：学生提前结束训练

**场景：** 学生只想做 3 题，但系统固定为 5 题，没有"提前结束"机制。

**修复方案（补充至 03 模块 §7.3）：**

```
训练界面新增"结束训练"按钮（右上角）：
  点击后弹出确认：
  ┌────────────────────────────────────┐
  │  确认结束训练？                     │
  │  当前进度：3/5 题（已完成 3 题）   │
  │  已答题目的数据将保存               │
  │                                    │
  │    [确认结束]  [继续做题]           │
  └────────────────────────────────────┘

提前结束的处理：
  - session_status → completed（标记为提前结束）
  - total_questions 字段写入实际完成题数（3）
  - 生成"训练进度小结"（而非完整小结）
  - 已答题目的数据正常写入 training_answer_records
  - 五力训练画像异步更新（按实际完成题数）
```

## 5. 模块依赖关系与启动顺序

### 5.1 技术依赖关系

```
依赖层级（从底层到上层）：

Level 0：基础设施（最先搭建）
  ├─ 微信小程序框架
  ├─ 后端服务（Node.js/Java）
  ├─ 关系型数据库（MySQL/PostgreSQL）
  ├─ 向量数据库（Milvus 或 Chroma）
  └─ 对象存储（图片、PDF 报告）

Level 1：身份认证（其他模块的前提）
  └─ 01_登录模块（JWT 签发、角色权限）

Level 2：核心数据（其他功能的数据基础）
  ├─ 02_五力认知测试模块（生成五力画像）
  └─ 题库建设（独立工程，并行进行）

Level 3：核心业务（依赖 Level 1+2）
  └─ 03_个性化AI训练模块（依赖：登录 + 五力画像 + 题库）

Level 4：增强体验（依赖 Level 3）
  └─ 04_智能助教模块（依赖：登录 + 五力画像 + 错题集）

Level 5：数据沉淀（依赖 Level 3+4）
  └─ 学习记录与反馈（训练数据 + 成长报告）
```

### 5.2 开发启动顺序建议

## 6. 题库冷启动方案（V1.0最大风险）

> ⚠️ **客户文档明确标注："有待解决：题库！"**
> 这是 V1.0 上线的头号风险，必须在开发启动前确定方案。

### 6.1 V1.0 最小可行题库规模

```
优先覆盖（Phase 1）：
  学科：数学
  年级：初三（G9）+ 高一（G10）
  章节：每年级覆盖 10 个核心章节
  知识点：每章节 5~8 个知识点

题目要求：
  每个知识点：8~10道题（超过5道开放门槛，预留替换空间）
  五力覆盖：每个知识点各力各≥2道题（满足选题算法）

初期目标规模：
  G9（初三）数学：80 个知识点 × 8 题 = 640 题
  G10（高一）数学：80 个知识点 × 8 题 = 640 题
  合计：~1280 道数学题（Phase 1 交付目标）
```

### 6.2 题库建设方案

| 方案 | 优点 | 缺点 | 建议 |
|------|------|------|------|
| **人工录入** | 质量可控，五力标注准确 | 速度慢，人力成本高 | 优先用于核心知识点 |
| **AI 辅助生成** | 速度快，成本低 | 需要人工审核，可能有错误 | 用于扩充题量，降低门槛 |
| **从合规教材/题库采购** | 题目质量高 | 版权成本、五力标注需人工完成 | 选 1~2 家合规来源 |
| **AI 自动标注 + 人工审核** | 降低标注成本 | 置信度<0.60 的题需全人工 | 推荐：AI先标注，人工审核高风险题 |

**推荐方案（综合）：**
1. 人工录入核心知识点题目（保证质量）
2. AI 标注智能体（已在03模块设计中）自动打五力标签
3. 管理员审核：置信度≥0.85批量确认，0.60~0.85逐题审核，<0.60强制人工
4. 采购 1~2 家合规题库扩充题量（确认版权）

### 6.3 题库建设里程碑

| 里程碑 | 内容 | 时间节点 |
|--------|------|----------|
| M-01 | 确定题库来源方案与版权协议 | 开发启动前 |
| M-02 | 完成题库录入工具（后台管理） | Sprint 2 完成 |
| M-03 | 完成 G9 数学 400 道初步题库 | Sprint 3 中期 |
| M-04 | 完成 G9+G10 数学 1200 道题库 | Sprint 5 前 |
| M-05 | AI 标注覆盖率≥90%，人工审核完成 | Sprint 6 前 |

### 6.4 题库不足时的前端处理

```
知识点选择器状态：
  ✅ 可用（题目≥5道，五力覆盖率≥80%）：正常绿色
  ⚠️ 建设中（题目1~4道）：浅灰色 + "建设中"标签 + 题目数量提示
  🔒 未建（题目=0道）：隐藏（不展示在选择器中）

Phase 1 期间：
  物理、化学知识点全部隐藏（未建）
  数学仅展示 G9+G10 的已建知识点
  其余年级知识点以"灰色+即将开放"展示
```

## 8. 数据架构与关键表关系

### 8.1 核心数据表 ER 关系

```
students（学生账号）
  │
  ├── five_power_profiles（测试五力画像，每次测试一条）
  │     └── is_latest=true 的为当前有效画像
  │
  ├── five_power_training_profiles（训练五力画像，滚动更新）
  │     └── 与 five_power_profiles 独立，综合查询时 0.6/0.4 融合
  │
  ├── training_sessions（训练会话，每次训练一条）
  │     ├── training_focus_power（本次主训练力）
  │     ├── training_mode（TRAIN_WEAKNESS / LEARN_BY_STRENGTH）
  │     ├── preferred_force（优势入口力）
  │     └── five_power_snapshot（训练开始时的五力快照）
  │           └── training_answer_records（每题答题记录，一对多）
  │
  ├── wrong_answer_records（错题记录，跨模块共享）
  │     ├── source_module（training / test）
  │     └── review_status（unreview → reviewing → aha_achieved）
  │
  └── ai_chat_sessions（AI对话会话）
        ├── session_mode（free_chat / wrong_review / training_error_guidance）
        ├── linked_question_id（关联题目）
        ├── parent_training_session_id（关联训练会话）
        └── ai_chat_messages（对话消息，一对多）
              └── strategy_id（使用的启发策略）

ai_student_strategy_profiles（策略有效性画像，每学生每策略一条）
  └── effectiveness_score（有效性分数，动态更新）
```

### 8.2 关键数据流的事务性要求

| 数据操作 | 事务要求 | 说明 |
|----------|----------|------|
| 学生答题 → 写 training_answer_records | 同步，事务内 | 核心答题记录不允许丢失 |
| 答错 → 写 wrong_answer_records | 异步，事务外（Queue-D） | 允许延迟，失败后重试 |
| 答错 → 触发 RAG | 异步，事务外（Queue-C） | 允许延迟，失败则降级 |
| 训练结束 → 更新 five_power_training_profiles | 异步，目标≤5min | 允许延迟，但必须最终一致 |
| AI对话 → 写 ai_chat_messages | 同步，事务内 | 对话记录不允许丢失 |
| 理解突破 → 更新 wrong_answer_records.review_status | 同步 | 防止并发冲突（行级锁） |

## 9. AI调用成本预估与控制

### 9.1 单次学习会话 Token 消耗估算

```
场景：一次标准训练（5题，2题答错，1次AI介入）

03_模块 RAG（每题答错触发）：
  Prompt: ~1300 Token × 2次 = 2600 Token
  Completion: ~400 Token × 2次 = 800 Token
  小计：3400 Token

04_模块 AI对话（1次主动介入，3轮对话）：
  Prompt: ~1050 Token × 3次 = 3150 Token
  Completion: ~800 Token × 3次 = 2400 Token
  小计：5550 Token

单次学习会话总计：~8950 Token（约9K Token）

按 GPT-4o-mini 定价（~0.15$/1M Token in）：
  9000 Token ≈ 0.00135 美元/次会话 ≈ 0.01 元人民币/次会话
  1000次会话/天 = 10元/天 = 300元/月（极低成本）

按通义千问价格（更低）：
  成本更低，基本可忽略不计
```

### 9.2 成本控制措施

| 措施 | 预期节省 |
|------|----------|
| 答对时完全不调用 AI（沉默原则） | 节省 ~60% 的 RAG 调用 |
| 选择题答错使用预置解析（不触发 RAG） | 节省 ~30% 的 RAG 调用 |
| 对话上下文裁剪（10轮→5轮时） | 节省 ~300 Token/次对话 |
| 主动介入次数限制（每会话≤3次） | 限制 04 模块调用上限 |
| 静态降级（RAG超时后展示预置内容） | 避免重试成本 |
