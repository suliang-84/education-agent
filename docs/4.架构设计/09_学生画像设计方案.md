# 学生画像设计方案

> 版本：v0.1（设计稿，待确认后开发）　日期：2026-11-04
> 入口：管理后台「学生管理 → 画像」页（现有「学生详情」页升级），同时向学生端小程序、家长端开放各自可见的部分。

## 1. 目标与原则

| 目标 | 说明 |
|---|---|
| 一眼看懂 | 顶部给出「综合评估 + 预警」，细节在下方分模块展开 |
| 数据可追溯 | 每个结论都能点到依据（题目、对话、测试），并显示更新时间 |
| 用已有数据 | 指标全部来自现有表；确需新增的数据在第 7 节列出 |
| 服务对象 | 目前只有管理员；AI 助教和智能训练继续使用各自的信号，不直接读取画像页 |
| 预警可配置 | 触发条件、阈值、级别都在「配置管理」里调整 |

## 2. 可见范围

画像页只对管理员开放（2026-11-04 确认）：学生端、家长端暂不展示画像，因此敏感内容（【敏感】标记的洞察、情绪类预警原文）也先不做角色过滤。后续如果开放给学生或家长，再按「谁能看到什么」补充过滤规则，接口层需要新增对应视图。

## 3. 页面设计（学生管理 → 画像）

```
┌────────────────────────────────────────────────────────────────────┐
│ ← 返回   [头像] 吴彦祖 · 九年级 上学期 · 未成年        [摘要] [导出]   │
├────────────────────────────────────────────────────────────────────┤
│ ① 综合评估                                                           │
│  状态：稳步提升        学习投入 78 分     近4周正确率 62% ↑ 6%         │
│  建议：推演力偏弱，建议本周多做「按知识点训练」中的推演类题目         │
├────────────────────────────────────────────────────────────────────┤
│ ② 预警（2）      [重点] 连续 8 天未训练   [关注] 方程应用题连续答错   │
│                                         [标为已处理] [查看依据]       │
├────────────────────────────────────────────────────────────────────┤
│  标签页： 认知能力 │ 学业掌握 │ 学习行为 │ AI 互动 │ 个人特质          │
```

- 「摘要」按钮进入现有的 AI 助教摘要页（学习信息摘要、个人洞察摘要、System Prompt 预览）。
- 页面风格沿用现有玻璃卡片：模块标题主题色，子标题文字色，右上角文字按钮。

## 4. 画像维度与指标

### 4.1 基础档案
| 指标 | 来源 |
|---|---|
| 昵称、头像、年级、学期、是否未成年 | `students` |
| 绑定的家长及绑定时间 | `parent_student_bindings` |
| 注册时间、最近登录、近 30 天活跃天数 | `students`、日汇总表 |

### 4.2 认知能力（五力）
| 指标 | 来源 / 口径 |
|---|---|
| 五力得分雷达图（能力 / 偏好 / 综合三层可切换） | `five_power_profiles.*_ability / _preference / _final` |
| 最强项、最弱项、次弱项 | `primary_strength / primary_weakness / secondary_weakness` |
| 画像可信度 | `profile_confidence` |
| 五力训练趋势：跟随时间范围——近一周按天（某天某力答题少于 2 道不画点），近一个月按周（某周某力答题少于 3 道不画点），每点是该力的做题正确率；取代原来的「测试成长曲线」——测试次数太少、得分经历史衰减平滑，曲线没有信息量 | 答题记录 `power_type` |
| 训练表现 vs 测试得分 | `five_power_training_profiles` 与测试得分的差值 |
| 认知洞察（跟随时间范围） | 每一力在所选范围内的：实战正确率、较前一段同样长度时间的变化（两段各 ≥ 5 道题）、做题量占比、空答率、平均用时、与测试得分的差距；某一力答题少于 6 道时评价为「做题太少」，不比较 |
| 评价标签 | 实战正确率比测试综合得分低 ≥ 15 个百分点为「发挥不稳」，高 ≥ 10 为「实战更强」，其余「与测试相符」 |
| 洞察条目（最多 5 条，需要关注的在前） | ① 测试最弱的一力却只占做题量 < 12%（训练偏向了其他能力，范围内至少 20 道题）；② 实战落差最大的一力（空答率 ≥ 30% 时点明「没作答就提交」）；③ 某力正确率比前一段时间升 / 降 ≥ 10 个百分点；④ 较上次（成绩不同的）测试某力变化 ≥ 3 分；⑤ 五力得分相差 ≥ 25 分为偏科明显、≤ 12 分为比较均衡；⑥ 实战中最稳的一力（正确率 ≥ 60%）；实战强于测试的一力 |
| 能力标签 | 规则生成：偏好显著高于能力 →「兴趣大于实力」；训练表现持续低于测试 →「发挥不稳定」 |

### 4.3 学业掌握
| 指标 | 来源 / 口径 |
|---|---|
| 科目整体正确率、做题量 | `training_answer_records` |
| 知识点掌握热力图（章节 → 知识点，按错误率着色） | `student_kp_stats` |
| 薄弱 / 强项知识点 Top 5 | 平滑错误率，口径同智能训练（先验 1:2，半衰期 14 天） |

| 难度表现（基础、进阶、挑战） | 答题记录 × `questions.difficulty` |
| 错题情况：待攻克数、已攻克数、攻克率 | `wrong_answer_records` |
| 顽固错题：同一道题错 ≥ 3 次 | 答题记录统计 |
| 当前学期进度：练过的知识点 / 学期知识点总数 | 答题记录 × `knowledge_points` |
| 收藏：收藏数、集中的知识点 | `question_favorites` |

| 指标 | 来源 / 口径 |

| 学习时段分布（上午 / 下午 / 晚上 / 深夜） | `training_answer_records.answered_at` |

| 偏好的训练方式 | `training_dimension` 分布 |

| 指标 | 来源 |
|---|---|

| 兴趣、性格、学习偏好标签 | 洞察文字抽取为标签（后续迭代） |
| 敏感内容标记 | 摘要中的【敏感】前缀 |

### 4.6.1 时间范围

画像页顶部是**日期范围**组件，默认**近 7 天**（含今天），可自选起止日期（北京时间，含起止两天，不能晚于今天，最长 90 天）；组件里有「近一周」「近一个月」快捷项。接口参数 `start_date`、`end_date`（`YYYY-MM-DD`），不传则为近 7 天。

- 随时间范围变化：答题量与正确率、题型 / 难度 / 科目表现、学习行为（用时、完成度、「快而错」、时段、训练方式）、五力训练趋势、答题诊断（空答、错因构成）、题序疲劳、AI 互动的发言数、学习投入度各项、学习状态与近期正确率趋势。
- 不随时间范围变化（当前状态或需要看全部历史）：错题（待攻克 / 已攻克 / 顽固）、薄弱 / 强项知识点、学期进度、五力测试、个人特质、预警、「同一道题反复做」「看过智能解答」「总选同一个答案」、连续学习天数。
- 口径随所选天数 N 折算：
  - 趋势：N ≤ 14 按天（N 个点）；更长按周（从开始日起每 7 天一格，最后一格可能不满一周）。五力趋势同理，按天时某力某天答题少于 2 道、按周时少于 3 道不画点。
  - 学习状态：N ≤ 14 用「所选范围 vs 前一段同样长度」的正确率差（≥ 5 个百分点算提升 / 下降，两段各需 ≥ 10 道题）；更长用每周正确率的变化斜率（> 2 / < −2 个百分点）。训练次数对比：N ≤ 14 比所选范围和前一段同样长度；更长比范围后半段（⌈N/2⌉ 天）和再前同样长度的一段。
  - 样本门槛：范围内至少答 max(8, min(20, ⌊2N/3⌉)) 道题才下结论（7 天 8 道，30 天 20 道）。
  - 学习投入度：训练频次满分 = ⌈12N/30⌉ 次（7 天 3 次，30 天 12 次）；错题集训练满分 = max(1, ⌊4N/30⌉) 次（7 天 1 次，30 天 4 次）。
  - 连续天数、最近训练日以所选范围的结束日为准；「距上次训练」也是距结束日的天数。

### 4.7 综合评估
| 指标 | 口径 |
|---|---|
| 学习状态标签 | 规则判定，见 5.1 |
| 学习投入度（0~100） | 训练频次 35% + 连续天数 15% + 答题完成度 20% + 认真作答 15% + 错题复盘 15%（可在配置管理修改）。认真作答 = 1 − 「快而错」占比 ÷ 40%，下限 0；错题复盘 = 错题攻克率 × 60% + 所选范围内用「错题集」训练次数 ÷ 满分次数（30 天 4 次，按天数折算，上限 1）× 40%；训练频次满分为 30 天 12 次，按天数折算。带用时的答题不足 20 道、错题记录不足 3 道时，对应项不计入，其余各项按权重比例折算到 100 分；旧配置没有「错题复盘」权重时按 0 处理 |
| 进步趋势 | 近 4 周周正确率的斜率；五力得分较上次测试的变化 |
| 推荐行动 | 取最弱知识点 / 最弱五力 / 最需处理的预警，生成 1~3 条建议 |

### 5.1 学习状态标签

| 状态 | 判定（默认） |
|---|---|
| 稳步提升 | 近 4 周正确率斜率 > 0，且近 14 天有训练 |
| 状态平稳 | 斜率在 ±2 个百分点之间 |
| 遇到瓶颈 | 近 14 天训练 ≥ 5 次，但正确率下降或无提升 |
| 近期懈怠 | 近 14 天训练次数低于此前 14 天的一半，或连续未训练 ≥ 7 天 |
| 数据不足 | 近 30 天答题 < 20 道，不下结论 |

## 5. 预警规则（可配置）

在「配置管理」页新增「画像预警」卡片，每条规则可独立启停、改阈值、改级别。

| 规则编码 | 触发条件（默认阈值） | 默认级别 |
|---|---|---|
| NO_TRAIN | 连续 N 天未训练（3 / 7 / 14 天各一档） | 提醒 / 关注 / 重点 |
| ACC_DROP | 近 2 周正确率比前 2 周下降超过 X 个百分点（10） | 关注 |
| KP_STREAK_WRONG | 同一知识点连续答错 N 次（3） | 关注 |
| STUBBORN_WRONG | 同一道题错 ≥ N 次（3） | 提醒 |
| COMPLETION_LOW | 近 14 天作答题数占发放题数的比例低于 X%（40，且至少发放 20 题） | 提醒 |
| LATE_NIGHT | 近 14 天 22 点后答题占比超过 X%（30），且学生为未成年 | 关注 |
| FAST_WRONG | 近 14 天「快而错」题占比超过 X%（40） | 提醒 |
| TEST_MISSING | 未完成五力测试 | 提醒 |
| PROFILE_STALE | 五力画像超过 N 天未更新（90） | 提醒 |
| CHAT_NEGATIVE | 近 14 天大模型对学生聊天的情绪判断：最近连续 N 次（默认 1）达到「明显低落」；判为「需要重点关注」立即触发 | 重点 |

- **级别**：提醒（蓝）、关注（琥珀）、重点（红）。
- **状态**：未处理 → 已处理（管理员点击，可填备注）→ 自动关闭（条件不再成立）。
- **去重**：同一学生同一规则，处理或关闭之前只保留一条；再次触发间隔至少 7 天。
- **情绪类预警**只对管理员展示原文依据，对家长只显示「近期情绪需要关注」。

## 6. 数据与接口

### 6.1 新增表

| 表 | 作用 | 主要字段 |
|---|---|---|
| `student_daily_stats` | 学生日汇总，支撑频次、连续天数、时段、趋势 | `student_id, stat_date, sessions, answered, correct, time_spent_sec, night_answered, quit_count, fast_wrong, chat_messages, active` |
| `student_profile_snapshots` | 每周快照，画像趋势用 | `student_id, snapshot_date, kp_stats(JSONB), accuracy, five_power(JSONB), engagement_score` |
| `student_warnings` | 预警记录 | `id, student_id, rule_code, level, status, detail(JSONB), triggered_at, handled_by, handled_at, note` |
| `profile_warning_rules` | 规则配置（也可放 `system_configs` 的 JSON） | `rule_code, enabled, threshold(JSONB), level` |

扩展已有表：
- `ai_chat_messages` 增加 `intent_type`（提问类型分类）；
- `five_power_profiles` 保留历史版本（不再只用 `is_latest`）。

### 6.2 计算方式
- **每日凌晨任务**：汇总前一天的 `student_daily_stats`，计算预警，每周一生成快照。
- **实时部分**：基础档案、最新五力、待攻克数、最近聊天等直接查表，不走汇总。
- **画像接口**读缓存：画像结果缓存 10 分钟，管理员点击「刷新」可重新计算。

### 6.3 接口（草案）

| 接口 | 说明 |
|---|---|
| `GET /admin/students/{id}/profile` | 完整画像（管理员视图） |
| `GET /admin/students/{id}/warnings` | 预警列表，可按状态筛选 |
| `POST /admin/students/{id}/warnings/{wid}/handle` | 标记已处理，附备注 |
| `GET/PUT /admin/profile-rules` | 预警规则配置 |
| `GET /miniapp/profile/me` | 学生视图（按第 2 节过滤） |
| `GET /parent/children/{id}/profile` | 家长视图（按第 2 节过滤，需校验绑定关系） |

响应统一按维度分块：`basic / cognitive / mastery / behavior / ai_interaction / traits / summary / warnings`，每块带 `updated_at`；视图过滤在服务端完成，前端不做权限判断。

## 7. 现有数据的缺口

| 缺口 | 影响 | 处理 |
|---|---|---|
| 没有按天汇总的数据 | 频次、连续天数、时段、趋势都要实时扫表 | 新增 `student_daily_stats` |
| 五力测试历史只用 `is_latest` | 看不到成长曲线 | 保留历史，补一条历史查询 |
| 没有聊天提问类型 | 无法做提问结构分析 | 退出助教时的摘要流程里顺带分类 |
| 没有结构化情绪标签 | 情绪预警只能靠关键词 | 用摘要流程里的大模型判定，写入预警 |
| 没有学习目标 / 家长期望 | 无法做目标达成度 | 本期不做 |
| 家长端尚未实现 | 家长视图无入口 | 本期先做接口，页面后续 |

## 10. 一期实现说明

- 页面：`学生管理 → 画像`（路由 `/students/:id`，`StudentProfileView.vue`），原学生详情页已替换。
- 接口：`GET /api/v1/admin/students/{id}/profile`，现算，不依赖日汇总表；后端 `app/services/profile_service.py`。

  标记「已处理」（可填备注）后同一规则 7 天内不再重复触发；同一学生同一规则未处理的预警最多一条。
- **画像页预警区**：按级别（重点 → 关注 → 提醒）排序展示，附最近处理过的预警和处理备注。
- 「学习行为」「进步趋势」在一期已按实时查询做完。

与原设计的差异：
- `QUIT_RATE_HIGH`（中途退出率）改为 `COMPLETION_LOW`（答题完成度低）：退出训练视为放弃是正常流程，不能用退出率判断。
- `CHAT_NEGATIVE` 用大模型判断（2026-11-05 由关键词匹配改成）：每次对话摘要更新后额外调用一次大模型（约几百 token），只发学生自己说的话，结果只存等级和一句依据；没有判断记录的学生不触发；大模型失败时保持上一次记录不变。
- **没有建日汇总表和周快照表**：现在是对单个学生实时查询，数据量小、响应够快；等学生量上来、需要「全部学生预警总览」时再建。
- 预警在管理员打开某个学生的画像页时同步计算；同时后端启动 60 秒后及之后每 6 小时自动扫描全部学生，学生管理列表据此显示预警标记，也可手动点「刷新预警」。还没有独立的「预警总览」页面。

## 12. 答题诊断（数据挖掘，2026-11-05）

在真实答题数据上做探索后，新增「学习行为」页的「答题诊断」：

| 指标 | 口径 | 价值 |
|---|---|---|
| 没作答就提交的比例（总体 + 按题型） | `student_answer` 为空就提交 | 比「快而错」更准：快而错里混着大量空答；填空、应用题 100% 空答说明学生在跳过需要动笔的题 |
| 错题是怎么错的 | 错题里：没作答就提交 / 3 秒内答完就错 / 认真做了仍然错 | 区分「不投入」和「真不会」：前者要先了解原因，后者才适合针对性讲解 |
| 同一道题反复做有没有进步 | 同一题第 1 次、第 2 次、第 3 次及以后的正确率 | 反复做没提高，说明缺的是讲解而不是练习，建议走智能解答 / AI 助教 |

页面会在数据足够时给一句结论（错题 ≥ 10 道、重复做的题 ≥ 5 道），样本少时只展示数字，不下结论。
3 秒这个「秒答」阈值目前写在代码里（`RUSH_SECONDS`）。

## 13. 提分行动与知识点处方（数据挖掘，2026-11-05）

目标：把画像里的数据翻成「老师 / 家长明天就能去做的事」。

**知识点处方**（学业掌握页薄弱知识点表）：每个知识点增加三项——
- 错因构成：没作答就提交 / 3 秒内答完就错 / 认真做了仍然错的道数；
- 走向：把该知识点的答题按时间分成前后两半，后半正确率比前半高 15 个百分点以上为「在进步」，低 15 个以上为「在退步」，其余「没起色」；至少做过 6 次才判断；
- 建议（由错因和走向决定）：空答为主 → 先让学生愿意动笔；秒答为主 → 提醒读题；认真做仍错且没起色 → 不要再刷题，先安排讲解；认真做仍错但在进步 → 继续巩固。
薄弱知识点只收错误率 ≥ 40% 的，强项只收错误率 ≤ 40% 的（整体都做得不好时强项为空，不再把「相对没那么差」的算强项）。

**提分行动**（综合评估里的「建议」，最多 5 条，按重要程度排序，每条带数据依据）：
1. 尚未完成五力测试 / 近期懈怠；
2. 没作答就提交的比例 ≥ 40%（指出最严重的题型）；
3. 薄弱知识点的针对性建议（总体已提示「不动笔」时，不再逐个知识点重复）；
4. 同一道题反复做没有进步 → 先讲解再做；
5. 已攻克的错题再遇到时正确率 < 60% → 隔几天再复习（至少 5 次再遇到才判断）；
6. 学习时段：最好和最差时段正确率差 ≥ 15 个百分点（每个时段至少 10 道题）→ 把重点训练放在最好的时段；
7. 某题型答错比答对快得多（< 60%）→ 可能没读清题；
8. 错题集还有待攻克的题；五力最弱项。

「学习行为」页的学习时段分布增加了各时段的正确率。

## 14. 更多发现（2026-11-05）

「学习行为」页「答题诊断」下方新增「更多发现」，学业掌握页的薄弱知识点表新增「可能的前置」：

| 发现 | 口径 | 给出结论的门槛 |
|---|---|---|
| 题序疲劳 | 同一次训练（每次抽 4 题以上）里，题序在前半段 vs 后半段的正确率和没作答率 | 前后半段各至少 10 道题；后半段正确率低 10 个百分点，或没作答率高 15 个百分点 |
| 智能解答有没有用 | 每道题第一次看过智能解答（有解答内容记录）之前和之后的答题正确率 | 看过之后再做的至少 5 道 |
| 概念性误解 | 同一道选择 / 判断题答错 ≥ 3 次，其中 ≥ 70% 都选同一个错误答案 | 同左 |
| 选项倾向 | 单选 / 判断题里同一个答案占 ≥ 60%（单选题选哪个字母、判断题对错哪边） | 至少答了 10 道 |
| 可能的前置薄弱点 | 同一单元里排在前面、同样薄弱（错误率 ≥ 40%，做过 ≥ 3 次）的知识点 | 前置知识点样本 ≥ 3 次 |

这些发现的结论同样会进入综合评估的「建议」（总数仍最多 5 条）。

**局限（需要知道）**
- 「可能的前置」没有真正的知识点先修关系，只是用单元内的先后顺序近似；知识点的排序字段目前基本都是 0，所以用 id（录入顺序，约等于教材顺序）兜底。
- 「看过智能解答」只能认出有解答内容的记录，看了没生成记录的认不出来；学生可能因为题难才去看解答，所以「看解答前后」不是严格的因果。
- 助教聊天与做题的关系（聊过某个知识点后正确率有没有提高）仍然没做：聊天信号目前只保存最近一次的困惑，没有历史，无法做前后对比。

**暂时没做（数据不够 / 需要更多业务数据）**：助教聊天前后同一知识点的变化。
