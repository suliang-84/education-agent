# 学生画像设计方案

> 版本：v0.1（设计稿，待确认后开发）　日期：2026-11-04
> 入口：管理后台「学生管理 → 画像」页（现有「学生详情」页升级），同时向学生端小程序、家长端开放各自可见的部分。

## 1. 目标与原则

| 目标 | 说明 |
|---|---|
| 一眼看懂 | 顶部给出「综合评估 + 预警」，细节在下方分模块展开 |
| 数据可追溯 | 每个结论都能点到依据（题目、对话、测试），并显示更新时间 |
| 用已有数据 | 指标全部来自现有表；确需新增的数据在第 7 节列出 |
| 服务对象 | 目前只有管理员；AI 助教和智能训练继续使用各自的信号，不直接读取画像页 |
| 预警可配置 | 触发条件、阈值、级别都在「配置管理」里调整 |

## 2. 可见范围

画像页只对管理员开放（2026-11-04 确认）：学生端、家长端暂不展示画像，因此敏感内容（【敏感】标记的洞察、情绪类预警原文）也先不做角色过滤。后续如果开放给学生或家长，再按「谁能看到什么」补充过滤规则，接口层需要新增对应视图。

## 3. 页面设计（学生管理 → 画像）

```
┌────────────────────────────────────────────────────────────────────┐
│ ← 返回   [头像] 吴彦祖 · 九年级 上学期 · 未成年        [摘要] [导出]   │
├────────────────────────────────────────────────────────────────────┤
│ ① 综合评估                                                           │
│  状态：稳步提升        学习投入 78 分     近4周正确率 62% ↑ 6%         │
│  建议：推演力偏弱，建议本周多做「按知识点训练」中的推演类题目         │
├────────────────────────────────────────────────────────────────────┤
│ ② 预警（2）      [重点] 连续 8 天未训练   [关注] 方程应用题连续答错   │
│                                         [标为已处理] [查看依据]       │
├────────────────────────────────────────────────────────────────────┤
│  标签页： 认知能力 │ 学业掌握 │ 学习行为 │ AI 互动 │ 个人特质          │
├────────────────────────────────────────────────────────────────────┤
│  （当前标签页内容，见第 4 节）                                        │
└────────────────────────────────────────────────────────────────────┘
```

- 「摘要」按钮进入现有的 AI 助教摘要页（学习信息摘要、个人洞察摘要、System Prompt 预览）。
- 页面风格沿用现有玻璃卡片：模块标题主题色，子标题文字色，右上角文字按钮。

## 4. 画像维度与指标

### 4.1 基础档案
| 指标 | 来源 |
|---|---|
| 昵称、头像、年级、学期、是否未成年 | `students` |
| 绑定的家长及绑定时间 | `parent_student_bindings` |
| 注册时间、最近登录、近 30 天活跃天数 | `students`、日汇总表 |

### 4.2 认知能力（五力）
| 指标 | 来源 / 口径 |
|---|---|
| 五力得分雷达图（能力 / 偏好 / 综合三层可切换） | `five_power_profiles.*_ability / _preference / _final` |
| 最强项、最弱项、次弱项 | `primary_strength / primary_weakness / secondary_weakness` |
| 画像可信度 | `profile_confidence` |
| 测试成长曲线：历次五力得分变化 | `five_power_profiles` 历史版本（需保留，见第 7 节） |
| 训练表现 vs 测试得分 | `five_power_training_profiles` 与测试得分的差值 |
| 能力标签 | 规则生成：偏好显著高于能力 →「兴趣大于实力」；训练表现持续低于测试 →「发挥不稳定」 |

### 4.3 学业掌握
| 指标 | 来源 / 口径 |
|---|---|
| 科目整体正确率、做题量 | `training_answer_records` |
| 知识点掌握热力图（章节 → 知识点，按错误率着色） | `student_kp_stats` |
| 薄弱 / 强项知识点 Top 5 | 平滑错误率，口径同智能训练（先验 1:2，半衰期 14 天） |
| 题型正确率（单选、多选、判断、填空、应用） | 答题记录 × `questions.question_type` |
| 难度表现（基础、进阶、挑战） | 答题记录 × `questions.difficulty` |
| 错题情况：待攻克数、已攻克数、攻克率 | `wrong_answer_records` |
| 顽固错题：同一道题错 ≥ 3 次 | 答题记录统计 |
| 当前学期进度：练过的知识点 / 学期知识点总数 | 答题记录 × `knowledge_points` |
| 收藏：收藏数、集中的知识点 | `question_favorites` |

### 4.4 学习行为
| 指标 | 来源 / 口径 |
|---|---|
| 近 7 / 30 天训练次数、连续学习天数 | `training_sessions`、日汇总表 |
| 学习时段分布（上午 / 下午 / 晚上 / 深夜） | `training_answer_records.answered_at` |
| 平均单题用时、平均每次训练时长 | `time_spent_sec` |
| 作答风格：快而错 / 慢而对 / 稳定 | 用时中位数 × 正确率的象限 |
| 求助习惯：平均提示级别、使用「智能解答」次数 | `hint_level_used`、解析请求 |
| 完成习惯：完成率、中途退出率 | `training_sessions.session_status`、`training_interrupts` |
| 偏好的训练方式 | `training_dimension` 分布 |

### 4.5 AI 互动
| 指标 | 来源 / 口径 |
|---|---|
| 聊天活跃度：消息数、最近聊天时间 | `ai_chat_messages` |
| 启发策略效果：每种策略的效果分、使用次数、点赞 / 点踩 | `ai_student_strategy_profiles` |
| 最受用的 3 种策略、不受用的策略 | 同上，按效果分排序 |
| 顿悟次数、集中的知识点 | `aha_count`、`is_aha_trigger` |
| 提问类型占比：概念不懂 / 思路不懂 / 计算出错 / 想要答案 / 闲聊 | 新增：对用户消息做分类（见第 7 节） |
| 近期困惑知识点 | `student_learning_signals` |

### 4.6 个人特质
| 指标 | 来源 |
|---|---|
| 个人洞察摘要（管理员确认部分 + AI 补充部分） | `student_ai_prompt_summaries` |
| 兴趣、性格、学习偏好标签 | 洞察文字抽取为标签（后续迭代） |
| 敏感内容标记 | 摘要中的【敏感】前缀 |

### 4.7 综合评估
| 指标 | 口径 |
|---|---|
| 学习状态标签 | 规则判定，见 5.1 |
| 学习投入度（0~100） | 训练频次 40% + 连续天数 20% + 完成率 25% + 提示依赖度 15% |
| 进步趋势 | 近 4 周周正确率的斜率；五力得分较上次测试的变化 |
| 推荐行动 | 取最弱知识点 / 最弱五力 / 最需处理的预警，生成 1~3 条建议 |

### 5.1 学习状态标签

| 状态 | 判定（默认） |
|---|---|
| 稳步提升 | 近 4 周正确率斜率 > 0，且近 14 天有训练 |
| 状态平稳 | 斜率在 ±2 个百分点之间 |
| 遇到瓶颈 | 近 14 天训练 ≥ 5 次，但正确率下降或无提升 |
| 近期懈怠 | 近 14 天训练次数低于此前 14 天的一半，或连续未训练 ≥ 7 天 |
| 数据不足 | 近 30 天答题 < 20 道，不下结论 |

## 5. 预警规则（可配置）

在「配置管理」页新增「画像预警」卡片，每条规则可独立启停、改阈值、改级别。

| 规则编码 | 触发条件（默认阈值） | 默认级别 |
|---|---|---|
| NO_TRAIN | 连续 N 天未训练（3 / 7 / 14 天各一档） | 提醒 / 关注 / 重点 |
| ACC_DROP | 近 2 周正确率比前 2 周下降超过 X 个百分点（10） | 关注 |
| KP_STREAK_WRONG | 同一知识点连续答错 N 次（3） | 关注 |
| STUBBORN_WRONG | 同一道题错 ≥ N 次（3） | 提醒 |
| QUIT_RATE_HIGH | 近 14 天中途退出率超过 X%（30） | 关注 |
| LATE_NIGHT | 近 14 天 22 点后答题占比超过 X%（30），且学生为未成年 | 关注 |
| FAST_WRONG | 近 14 天「快而错」题占比超过 X%（40） | 提醒 |
| TEST_MISSING | 未完成五力测试 | 提醒 |
| PROFILE_STALE | 五力画像超过 N 天未更新（90） | 提醒 |
| CHAT_NEGATIVE | 近 14 天聊天出现负面情绪内容（大模型判定，置信度 ≥ 0.7） | 重点 |

- **级别**：提醒（蓝）、关注（琥珀）、重点（红）。
- **状态**：未处理 → 已处理（管理员点击，可填备注）→ 自动关闭（条件不再成立）。
- **去重**：同一学生同一规则，处理或关闭之前只保留一条；再次触发间隔至少 7 天。
- **情绪类预警**只对管理员展示原文依据，对家长只显示「近期情绪需要关注」。

## 6. 数据与接口

### 6.1 新增表

| 表 | 作用 | 主要字段 |
|---|---|---|
| `student_daily_stats` | 学生日汇总，支撑频次、连续天数、时段、趋势 | `student_id, stat_date, sessions, answered, correct, time_spent_sec, night_answered, quit_count, fast_wrong, chat_messages, active` |
| `student_profile_snapshots` | 每周快照，画像趋势用 | `student_id, snapshot_date, kp_stats(JSONB), accuracy, five_power(JSONB), engagement_score` |
| `student_warnings` | 预警记录 | `id, student_id, rule_code, level, status, detail(JSONB), triggered_at, handled_by, handled_at, note` |
| `profile_warning_rules` | 规则配置（也可放 `system_configs` 的 JSON） | `rule_code, enabled, threshold(JSONB), level` |

扩展已有表：
- `ai_chat_messages` 增加 `intent_type`（提问类型分类）；
- `five_power_profiles` 保留历史版本（不再只用 `is_latest`）。

### 6.2 计算方式
- **每日凌晨任务**：汇总前一天的 `student_daily_stats`，计算预警，每周一生成快照。
- **实时部分**：基础档案、最新五力、待攻克数、最近聊天等直接查表，不走汇总。
- **画像接口**读缓存：画像结果缓存 10 分钟，管理员点击「刷新」可重新计算。

### 6.3 接口（草案）

| 接口 | 说明 |
|---|---|
| `GET /admin/students/{id}/profile` | 完整画像（管理员视图） |
| `GET /admin/students/{id}/warnings` | 预警列表，可按状态筛选 |
| `POST /admin/students/{id}/warnings/{wid}/handle` | 标记已处理，附备注 |
| `GET/PUT /admin/profile-rules` | 预警规则配置 |
| `GET /miniapp/profile/me` | 学生视图（按第 2 节过滤） |
| `GET /parent/children/{id}/profile` | 家长视图（按第 2 节过滤，需校验绑定关系） |

响应统一按维度分块：`basic / cognitive / mastery / behavior / ai_interaction / traits / summary / warnings`，每块带 `updated_at`；视图过滤在服务端完成，前端不做权限判断。

## 7. 现有数据的缺口

| 缺口 | 影响 | 处理 |
|---|---|---|
| 没有按天汇总的数据 | 频次、连续天数、时段、趋势都要实时扫表 | 新增 `student_daily_stats` |
| 五力测试历史只用 `is_latest` | 看不到成长曲线 | 保留历史，补一条历史查询 |
| 没有聊天提问类型 | 无法做提问结构分析 | 退出助教时的摘要流程里顺带分类 |
| 没有结构化情绪标签 | 情绪预警只能靠关键词 | 用摘要流程里的大模型判定，写入预警 |
| 没有学习目标 / 家长期望 | 无法做目标达成度 | 本期不做 |
| 家长端尚未实现 | 家长视图无入口 | 本期先做接口，页面后续 |

## 8. 分期

| 期 | 内容 | 依赖 |
|---|---|---|
| 一期 | 画像页框架 + 综合评估（简化版）+ 基础档案、认知能力、学业掌握、AI 互动（均为已有数据） | 无 |
| 二期 | 日汇总表 + 学习行为 + 预警规则配置 + 预警列表 + 进步趋势 | 日汇总 |
| 三期 | 导出报告、提问类型与情绪识别（学生端、家长端视图暂不做） | 二期 |

## 9. 已确认事项（2026-11-04）

1. 画像页只对管理员开放，敏感内容的角色过滤暂不考虑。
2. 预警默认阈值按本方案第 5 节，管理员可在「配置管理」里修改（二期做）。
3. 学习投入度权重 40/20/25/15 认可；一期写在代码里，二期放进配置管理。
4. 一期先升级现有「学生详情」页为「学生画像」页，保留「摘要」入口。

## 10. 一期实现说明

- 页面：`学生管理 → 画像`（路由 `/students/:id`，`StudentProfileView.vue`），原学生详情页已替换。
- 接口：`GET /api/v1/admin/students/{id}/profile`，现算，不依赖日汇总表；后端 `app/services/profile_service.py`。
- 知识点掌握按答题记录现算：`student_kp_stats` 表目前没有被维护（0 条记录），不能作为数据来源。
- 「答题完成度」用「作答题数 / 发放题数」：退出训练即放弃是正常流程，不能用「完成的训练 / 全部训练」。
- 部分旧题的 `knowledge_point_ids` 里存的是知识点名称而不是 ID，统计时跳过，不会报错。
- 五力里「能力」「偏好」两组分值量纲不同（偏好总和约 100），所以没有做「兴趣大于实力」这类对比标签。
