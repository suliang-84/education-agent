## 1. 产品总览

### 1.1 产品定位

MESH 是一款面向初中至高中生的数理化 AI 认知训练平台，以"五力认知诊断"为核心，通过个性化选题与 AI 全程陪伴，培养学生底层认知能力。

### 1.2 小程序整体结构

```
微信小程序
├── 登录注册（全屏引导页，首次进入）
│
├── Tab 1：个性化训练（默认选中）
│   ├── 训练首页（知识点导航）
│   ├── 训练答题页
│   ├── RAG 解题页（浮层）
│   └── 训练小结页
│
├── Tab 2：AI 助教
│   ├── 会话列表页
│   └── 对话页
│
└── Tab 3：我的五力
    ├── 五力画像页
    ├── 历史成长页
    └── 错题集页
```

### 1.3 首页导航规则

| 场景 | 跳转行为 |
|------|----------|
| 首次登录，无五力画像 | 全屏引导页 → 强引导完成五力测试 |
| 已有五力画像 | 进入首页，默认 Tab 1（个性化训练） |
| Tab 1 无画像时点击训练 | 弹出引导卡："先完成五力测试，解锁专属训练" |

### 1.4 顶部五力状态卡（Tab 1 常驻）

```
┌──────────────────────────────────────────────┐
│  最弱维度摘要（常驻顶部，可点击展开完整画像）   │
│  建构力 47↓   调适力 55↓   [去测试 >]         │
└──────────────────────────────────────────────┘
```

- **数据来源**：`five_power_profiles`（is_latest=true）
- **点击行为**：跳转 Tab 3 我的五力
- **无数据时**：显示"完成五力测试，解锁专属训练"+ 按钮

### 2.3 系统交互

```
微信登录流程：
  用户点击"微信一键登录"
    ↓ 调用 wx.login() 获取 code
    ↓ POST /api/v1/auth/wx-login（携带 code）
    ↓ 后端 code2session → 获取 openid
    ↓ 查询 students 表（by openid_hash）
    ├─ 新用户 → 返回 temp_token + is_new_user=true
    │   ↓ 前端跳转手机号绑定页
    │   ↓ 发送短信验证码（POST /api/v1/auth/sms/send）
    │   ↓ 提交绑定（POST /api/v1/auth/bind-phone）
    │   ↓ 返回 access_token + refresh_token
    │   ↓ 跳转首页（引导五力测试）
    └─ 老用户 → 返回 access_token + refresh_token
        ↓ 跳转首页
```

```
静默续期流程：
  小程序启动
    ↓ 读取本地 access_token
    ↓ POST /api/v1/auth/token/validate
    ├─ 有效 → 直接进入首页
    ├─ 已过期可刷新 → POST /api/v1/auth/token/refresh → 更新 Token
    └─ 完全失效 → 弹出"请重新登录"提示
```

### 2.4 约束条件

| 约束项 | 规则 |
|--------|------|
| 短信发送频率 | 同号每 60 秒限发 1 次，每日最多 10 次 |
| 验证码有效期 | 5 分钟，错误超 5 次作废 |
| Token 有效期 | access_token 7 天，refresh_token 30 天 |
| 手机号唯一性 | 同一手机号只能注册一个账号 |
| 邀请码有效期 | 48 小时，一次性使用 |
| 每学生最多绑定家长数 | 2 人（应用层控制） |
| 账号注销 | 30 天内可恢复，期满后自动清除 AI 对话等隐私数据 |

### 3.3 系统交互

```
测试完整流程：

[引导页] → 点击"开始测试"
    ↓ GET /api/v1/test/questions
    ↓ 返回 session_id + 20道题（打散顺序）

[逐题答题]
    ↓ 学生选择选项
    ↓ POST /api/v1/test/answer（每题提交）
    ↓ 记录 selected_option, time_spent_sec, modify_count
    ↓ 更新进度条

[最后一题] → 点击"提交"
    ↓ 确认弹窗："确认提交测试吗？"
    ↓ POST /api/v1/test/complete
    ↓ 后端同步评分（≤3秒）
    ↓ 写入 five_power_profiles（is_latest=true）
    ↓ 触发 Celery Queue-E（异步AI分析）

[结果展示]
    ↓ 前端接收三层评分数据
    ↓ 展示雷达图 + 分数
    ↓ ai_analysis_status = pending → 骨架屏占位
    ↓ 轮询 GET /api/v1/test/result/{profile_id}（每3秒）
    ↓ ai_analysis_status = completed → 填充AI分析文字

[中断恢复]
    用户中途退出
    ↓ 重新进入小程序
    ↓ 检测到 session_status = in_progress
    ↓ 弹窗："检测到上次未完成测试（已完成7/20题）"
    ├─ [继续] → 从第8题开始，保留已答答案
    └─ [重新开始] → 旧session标记abandoned，重新创建
```

### 3.4 约束条件

| 约束项 | 规则 |
|--------|------|
| 题目数量 | 固定 20 道（不可增减） |
| 重测间隔 | 推荐≥30天，强制无限制 |
| 中断恢复窗口 | 72 小时内有效，超时标记 expired |
| 评分时间 | 同步评分≤3秒，AI分析异步5~30秒 |
| 仓促答题标记 | time_spent_sec < 5 秒，自动标记 is_rushed |
| 答案修改 | 允许，覆盖提交，记录 modify_count |
| 前台不显示"测什么" | 题目不显示对应的五力维度 |

### 4.3 系统交互

```
完整训练流程：

[知识点选择]
    ↓ GET /api/v1/knowledge/points?grade_id=7
    ↓ 展示三态知识点列表（可用/建设中/隐藏）

[点击知识点] → [训练说明页]
    ↓ POST /api/v1/training/session
    ↓ 后端读取五力画像 → 运行选题算法 → 返回5题
    ↓ 写入 training_sessions（status=active）

[逐题答题]
    ↓ 学生提交答案（POST /api/v1/training/answer）
    ↓ 后端同步判题
    ├─ 答对 → is_correct=true，沉默，自动进入下题
    └─ 答错 → is_correct=false
        ↓ 写入 wrong_answer_records（review_status=unreview）
        ↓ 触发 Celery Queue-C（RAG生成）
        ↓ 返回 rag_status=pending
        ↓ 前端展示骨架屏（"AI正在分析..."）
        ↓ 轮询 GET /api/v1/training/rag-status/{answer_record_id}
        ├─ completed → 展示 rag_content（AI解题思路）
        ├─ degraded  → 展示 static_solution（参考解析）+ 重试按钮
        └─ 连续≥2次答错且满足5前置条件
            ↓ proactive_trigger=true
            ↓ 前端展示AI悬浮条

[完成/提前结束]
    ↓ POST /api/v1/training/complete
    ↓ 计算小结数据（accuracy, power_breakdown）
    ↓ 触发 Celery Queue-P（训练画像异步更新≤5分钟）
    ↓ 展示训练小结页

[RAG降级时序]
    T=0：学生答错，前端展示骨架屏
    T=3s：骨架屏加进度条动画
    T=8s：超时触发降级
        ├─ 若有 static_solution → 展示参考解析
        └─ 若无 → 展示"AI暂时忙碌，建议查看教材" + 重试按钮
    重试：最多3次，每次等待时限逐次延长（8s→12s→15s）
```

```
    ↓ 选择历史有效性最高的未使用策略
    ↓ 若无历史数据 → 按默认优先级顺序
```

```
     │   review_status → aha_achieved（终态，不可更改）
     └─ 对话结束但未突破
            ↓
         review_status → pending_consolidation（待巩固）
              ↓
           学生再次点击复盘 → 重入 reviewing
```

### 7.4 约束条件

| 约束项 | 规则 |
|--------|------|
| 错题自动生成 | 训练/测试答错时自动创建，无需手动操作 |
| aha_achieved 为终态 | 一旦突破，状态不可退回 |
| 复盘摘要长度 | AI 生成≤100字 |
| 错题软删除 | 不提供手动删除（保护学习记录完整性） |

> **版本变更说明（v1.2.0）：** 新增题目全生命周期管理能力——支持新增、编辑、发布、下架操作，题目状态由原 `is_active` 布尔值升级为 `draft / published / archived` 三态流转机制。测试功能依赖"已发布题目恰好为20道"的约束保障数据一致性。
>
> **版本变更说明（v1.3.0）：** 新增/编辑题目表单重构——去除「目标维度」字段，新增动态答案配置功能：每条答案手动填写内容，选项编号（A/B/C/D…）自动生成，并为每个选项独立配置五力权重分布（洞察力/建构力/推演力/调适力/迁移力）。答案数量支持动态增删（2~8条）。`option_scores` 简单得分字段废弃，统一改用五力权重向量 `option_force_weights` 覆盖所有题目类型。
>
> **版本变更说明（v1.4.0）：** 进一步简化新增/编辑表单——基础信息只保留「参考时间」和「题目描述」（管理员用元数据字段，不展示给学生）；由于五力测试题所有答案均无唯一正确选项，去除「题目类型」（OBJECTIVE/PREFERENCE）区分，统一为单一模型；同步移除「最优答案」（correct_option）相关逻辑。

### 11.1 功能点列表

| 功能点 | 说明 |
|--------|------|
| 题目列表查看 | 分状态标签页展示全部测试题，支持按状态、题目类型筛选 |
| 新增题目 | 创建草稿题目，填写参考时间、题目描述、题干、答案及五力权重后保存为 `draft` 状态 |
| 编辑题目 | 修改草稿或已发布题目的题目描述、题干、答案列表、各答案五力权重、参考时间等全部字段 |

### 11.2 题目状态流转

```
           新增
            │
            ▼
         [draft]  ──编辑──▶  [draft]
            │
           发布
            │
            ▼
        [published]  ──编辑──▶  [published]
            │
           下架
            │
            ▼
        [archived]  ──编辑──▶  [archived]
            │
       重新发布（修改后可直接发布）
            │
            ▼
        [published]
```

| 状态 | 含义 | 可执行操作 |
|------|------|-----------|
| `draft`（草稿） | 已创建但未上线，不参与测试 | 编辑、发布、删除 |
| `published`（已发布） | 参与学生测试组卷，已发布总数 = 20 时测试生效 | 编辑、下架 |
| `archived`（已下架） | 不参与新测试，可在此状态下编辑修改内容，满足条件后重新发布 | **编辑、重新发布** |

> **历史成绩保护机制：** 每次测试会话创建时，系统会对当前已发布题目的内容（题干、答案、权重）生成不可变快照，存储在 `test_sessions.config_snapshot` 中。此后对题目的任何修改（包括下架编辑后重新发布）**均不影响已完成的历史测试会话及其评分结果**，历史成绩永远基于测试时的快照版本计算。
>
> **约束：** 同一时刻已发布题目数 **至少需要10道**，测试功能才对学生开放。不足10道时，小程序端发起测试将返回 `TEST-005` 错误。

### 11.4 约束条件

| 约束项 | 规则 |
|--------|------|
| 测试触发条件 | 已发布题目数 = 20 道时，学生测试功能开启；不足20道时自动暂停并提示 |
| 发布上限 | 已发布题目数 < 20 时方可发布；已达20道时拒绝发布，提示需先下架旧题 |
| 答案数量 | 每题最少 2 个答案，最多 8 个答案 |
| 选项编号 | 选项字母（A/B/C/D…）按添加顺序自动生成，删除后重新排序 |
| 权重规则 | 每个答案的五力权重向量之和必须 ≈ 1.0（允许 ±0.01 浮点误差） |
| 题目描述 | 管理员用元数据，记录该题测量意图，**不展示给学生**，建议填写但非必填 |
| 编辑生效范围 | 对 `published` 或 `archived` 题目的修改均只影响修改后**新创建**的测试会话；历史会话基于创建时的内容快照计算，永不受影响 |
| 下架后可编辑 | `archived` 状态题目支持编辑（修改题干、答案内容、五力权重、参考时间、题目描述）；编辑后可直接重新发布 |
| 重新发布不影响历史 | `archived` 题目编辑后重新发布，历史测试成绩依然基于该题当时被引用时的快照版本，成绩不变 |
| 草稿删除 | 仅 `draft` 状态题目可物理删除；`published` 和 `archived` 题目不可删除 |
| 修改留痕 | 所有新增、编辑、状态变更操作均写入 `admin_audit_logs`，含变更前后字段快照 |
| 重新发布条件 | `archived` 题目重新发布需满足当前已发布数 < 20 的条件 |

### 15.2 用户角色与账号体系

#### 15.2.1 三类用户说明

| 角色 | 存储位置 | 登录方式 | 使用端 | 说明 |
|------|---------|---------|--------|------|
| 学生（STUDENT） | `students` 表，`user_type='STUDENT'` | 微信OAuth + 手机绑定 | 小程序 | 核心学习用户，拥有五力画像、训练记录 |
| 家长（PARENT） | `students` 表，`user_type='PARENT'` | 微信OAuth + 手机绑定 | 小程序 | 通过绑定关系查看子女学习情况，无训练数据 |
| 管理员（ADMIN） | `admin_users` 表 | 用户名/密码 + 短信2FA | 后台管理系统 | 运营/内容管理，可管理所有用户数据 |

#### 15.2.2 家长-学生绑定方式

家长与学生之间的绑定是系统核心关联关系，支持三种绑定途径：

| 方式 | 发起方 | 流程描述 | bind_method 值 |
|------|--------|---------|----------------|
| **学生邀请家长** | 学生 | 学生在小程序生成8位邀请码 → 家长在小程序输入邀请码 → 绑定立即生效 | `INVITE_CODE` |
| **家长主动绑定** | 家长 | 家长在小程序输入学生手机号 → 系统向学生手机发送确认短信 → 学生确认后绑定生效 | `PARENT_SELF` |
| **管理员后台绑定** | 管理员 | 管理员在后台搜索学生 → 输入家长手机号（不存在则自动创建家长账号）→ 立即绑定 | `ADMIN` |

**绑定约束：**
- 每位学生最多绑定 **2 位家长**
- 每位家长最多绑定 **5 位学生**
- 家长和学生均须已注册小程序账号（管理员绑定时若家长未注册，系统自动创建待激活账号）

### 15.4 学生画像设计

#### 15.4.1 设计思路

用户画像面向管理员，目标是让管理员在最短时间内全面了解一名学生的**认知能力现状、学习行为模式、AI 辅导效果**，从而支撑运营决策（如：题库内容优化、AI 策略调整、异常学生关怀）。画像分为六大维度：

| 画像维度 | 核心问题 | 数据来源 |
|----------|----------|----------|
| **基础信息** | 这个学生是谁？绑定了哪些家长？ | `students`、`parent_student_bindings` |
| **五力认知画像** | 认知能力现状如何？哪里最弱最强？ | `five_power_profiles`、`five_power_training_profiles` |
| **学习行为画像** | 有多勤奋？训练习惯如何？ | `training_sessions`、`training_answer_records` |
| **AI 助教互动画像** | 和 AI 的交互质量如何？是否产生了理解突破？ | `ai_chat_sessions`、`ai_strategy_events` |
| **错题薄弱画像** | 反复在哪里出错？哪些知识点是盲区？ | `wrong_answer_records` |
| **成长轨迹** | 是否在进步？五力成长趋势如何？ | `five_power_profiles`（历史多条） |

#### 15.4.2 画像包含信息详细说明

**一、基础信息**

| 信息项 | 说明 |
|--------|------|
| 学生昵称 / ID | 唯一标识 |
| 年级 | G7~G12 |
| 学科偏好 | 数学 / 物理 / 化学（多选）|
| 是否未成年 | 影响内容安全策略 |
| 注册时间 | 用户生命周期起点 |
| 最后活跃时间 | 判断是否流失 |
| 绑定家长 | 已绑定家长列表（0~2位），含绑定方式和绑定时间 |
| 累计登录天数 | 学习粘性基础指标 |

**二、五力认知画像**

| 信息项 | 说明 |
|--------|------|
| 五力雷达图（当前） | 洞察/建构/推演/调适/迁移五维综合分（测试×40% + 训练×60%）|
| 各维度能力分（ability_score） | 来自五力测试，反映真实能力 |
| 各维度认知入口分（preference_score） | 习惯从哪个维度进入新知识，指导教学路径 |
| 当前最弱力 | primary_weakness，训练主要目标 |
| 当前优势入口力 | preferred_force，借强补弱的切入点 |
| 推荐训练模式 | TRAIN_WEAKNESS / LEARN_BY_STRENGTH |
| AI 个性化分析摘要 | 测试后 AI 生成的 150 字学情描述 |
| 测试次数 / 最近测试时间 | 了解测试参与情况 |

**三、学习行为画像**

| 信息项 | 说明 |
|--------|------|
| 累计训练会话数 | 整体学习投入程度 |
| 累计答题数 | 练习总量 |
| 整体答题正确率 | 综合掌握水平 |
| 各五力维度训练正确率 | 哪个维度练得最好/最差 |
| 最近 7 天训练天数 | 近期活跃度 |
| 平均单次训练时长（分钟）| 专注力指标 |
| 训练完成率 | 正常完成 vs 提前结束 vs 放弃 占比 |
| 最常训练的知识点 Top 3 | 学习偏好与薄弱集中点 |

**四、AI 助教互动画像**

| 信息项 | 说明 |
|--------|------|
| 累计对话会话数 | AI 使用深度 |
| 累计对话轮次 | 学习深度指标 |
| 理解突破（aha）次数 | 核心效果指标——AI 是否真正帮助了学生 |
| 突破率（aha/总会话） | AI 教学有效性 |
| 最常使用的会话模式 | 自由提问 / 错题复盘 / 训练介入 |
| 最有效启发策略 Top 3 | 该生对哪种策略最容易产生突破 |
| 沉默模式触发次数 | 学生主动拒绝 AI 介入的频次 |

**五、错题薄弱画像**

| 信息项 | 说明 |
|--------|------|
| 累计错题数 | 总难点量 |
| 错题按五力维度分布 | 哪个维度出错最多 |
| 错题复盘率 | 错题中已复盘的比例 |
| 错题突破率 | 已复盘错题中达到 aha_achieved 的比例 |
| 未复盘错题数 | 待处理的学习盲点数量 |
| 高频错题知识点 Top 5 | 精准定位盲区 |

**六、成长轨迹**

| 信息项 | 说明 |
|--------|------|
| 五力历次测试趋势折线图 | 各维度成绩随时间变化，直观展示成长 |
| 最近两次测试对比 | 双色叠加雷达图，量化成长幅度 |
| 训练正确率趋势 | 近 30 天按周统计，反映练习效果 |
| 系统参与天数 | 注册以来的实际活跃天数 |

### 15.5 交互规范

| 交互点 | 规则 |
|--------|------|
| Tab 切换 | 学生/家长/管理员三个 Tab 独立分页，互不干扰 |
| 画像入口 | 学生列表每行点击「画像」按钮，跳转至学生画像详情页 |
| 家长(N) 标注 | 学生列表中「家长(N)」按钮点击展开已绑定家长浮层，N为已绑定数 |
| 绑定操作 | 管理员点击「绑」→ 弹出绑定弹窗，输入家长手机号即可 |
| 解绑操作 | 需二次确认弹窗，解绑为软删除（保留历史记录）|
| 管理员停用 | 停用后该管理员当前 Token 立即失效，无法继续操作后台 |
| 时间维度 | 学习行为、AI互动数据支持切换时间范围（全部/近30天/近7天）|
| 导出报告 | 支持导出学生完整画像 PDF（V1.1）|

### 15.6 数据来源说明

| 管理员列表 | `admin_users` |

| AI 助教互动 | `ai_chat_sessions`、`ai_chat_messages`、`ai_strategy_events` |

| 错题统计 | `wrong_answer_records`（review_status 分组）|
| 训练正确率趋势 | `training_answer_records`（按日/周聚合 is_correct）|
