## 1. 产品总览

### 1.1 产品定位

MESH 是一款面向初中至高中生的数理化 AI 认知训练平台，以"五力认知诊断"为核心，通过个性化选题与 AI 全程陪伴，培养学生底层认知能力。

### 1.2 小程序整体结构

```
微信小程序
├── 登录注册（全屏引导页，首次进入）
│
├── Tab 1：个性化训练（默认选中）
│   ├── 训练首页（知识点导航）
│   ├── 训练答题页
│   ├── RAG 解题页（浮层）
│   └── 训练小结页
│
├── Tab 2：AI 助教
│   ├── 会话列表页
│   └── 对话页
│
└── Tab 3：我的五力
    ├── 五力画像页
    ├── 历史成长页
    └── 错题集页
```

### 1.3 首页导航规则

| 场景 | 跳转行为 |
|------|----------|
| 首次登录，无五力画像 | 全屏引导页 → 强引导完成五力测试 |
| 已有五力画像 | 进入首页，默认 Tab 1（个性化训练） |
| Tab 1 无画像时点击训练 | 弹出引导卡："先完成五力测试，解锁专属训练" |

### 1.4 顶部五力状态卡（Tab 1 常驻）

```
┌──────────────────────────────────────────────┐
│  最弱维度摘要（常驻顶部，可点击展开完整画像）   │
│  建构力 47↓   调适力 55↓   [去测试 >]         │
└──────────────────────────────────────────────┘
```

- **数据来源**：`five_power_profiles`（is_latest=true）
- **点击行为**：跳转 Tab 3 我的五力
- **无数据时**：显示"完成五力测试，解锁专属训练"+ 按钮

### 2.3 系统交互

```
微信登录流程：
  用户点击"微信一键登录"
    ↓ 调用 wx.login() 获取 code
    ↓ POST /api/v1/auth/wx-login（携带 code）
    ↓ 后端 code2session → 获取 openid
    ↓ 查询 students 表（by openid_hash）
    ├─ 新用户 → 返回 temp_token + is_new_user=true
    │   ↓ 前端跳转手机号绑定页
    │   ↓ 发送短信验证码（POST /api/v1/auth/sms/send）
    │   ↓ 提交绑定（POST /api/v1/auth/bind-phone）
    │   ↓ 返回 access_token + refresh_token
    │   ↓ 跳转首页（引导五力测试）
    └─ 老用户 → 返回 access_token + refresh_token
        ↓ 跳转首页
```

```
静默续期流程：
  小程序启动
    ↓ 读取本地 access_token
    ↓ POST /api/v1/auth/token/validate
    ├─ 有效 → 直接进入首页
    ├─ 已过期可刷新 → POST /api/v1/auth/token/refresh → 更新 Token
    └─ 完全失效 → 弹出"请重新登录"提示
```

### 2.4 约束条件

| 约束项 | 规则 |
|--------|------|
| 短信发送频率 | 同号每 60 秒限发 1 次，每日最多 10 次 |
| 验证码有效期 | 5 分钟，错误超 5 次作废 |
| Token 有效期 | access_token 7 天，refresh_token 30 天 |
| 手机号唯一性 | 同一手机号只能注册一个账号 |
| 邀请码有效期 | 48 小时，一次性使用 |
| 每学生最多绑定家长数 | 2 人（应用层控制） |
| 账号注销 | 30 天内可恢复，期满后自动清除 AI 对话等隐私数据 |

### 3.3 系统交互

```
测试完整流程：

[引导页] → 点击"开始测试"
    ↓ GET /api/v1/test/questions
    ↓ 返回 session_id + 20道题（打散顺序）

[逐题答题]
    ↓ 学生选择选项
    ↓ POST /api/v1/test/answer（每题提交）
    ↓ 记录 selected_option, time_spent_sec, modify_count
    ↓ 更新进度条

[最后一题] → 点击"提交"
    ↓ 确认弹窗："确认提交测试吗？"
    ↓ POST /api/v1/test/complete
    ↓ 后端同步评分（≤3秒）
    ↓ 写入 five_power_profiles（is_latest=true）
    ↓ 触发 Celery Queue-E（异步AI分析）

[结果展示]
    ↓ 前端接收三层评分数据
    ↓ 展示雷达图 + 分数
    ↓ ai_analysis_status = pending → 骨架屏占位
    ↓ 轮询 GET /api/v1/test/result/{profile_id}（每3秒）
    ↓ ai_analysis_status = completed → 填充AI分析文字

[中断恢复]
    用户中途退出
    ↓ 重新进入小程序
    ↓ 检测到 session_status = in_progress
    ↓ 弹窗："检测到上次未完成测试（已完成7/20题）"
    ├─ [继续] → 从第8题开始，保留已答答案
    └─ [重新开始] → 旧session标记abandoned，重新创建
```

### 3.4 约束条件

| 约束项 | 规则 |
|--------|------|
| 题目数量 | 固定 20 道（不可增减） |
| 重测间隔 | 推荐≥30天，强制无限制 |
| 中断恢复窗口 | 72 小时内有效，超时标记 expired |
| 评分时间 | 同步评分≤3秒，AI分析异步5~30秒 |
| 仓促答题标记 | time_spent_sec < 5 秒，自动标记 is_rushed |
| 答案修改 | 允许，覆盖提交，记录 modify_count |
| 前台不显示"测什么" | 题目不显示对应的五力维度 |

### 5.3 系统交互

```
自由提问流程：
  学生点击"新对话" 或 Tab 2 入口
    ↓ POST /api/v1/assistant/session（session_mode=free_chat）
    ↓ 系统检查是否有 active 会话 → 若有则关闭旧会话
    ↓ 创建新 ai_chat_sessions
    ↓ AI 生成开场白（写入 ai_chat_messages）
    ↓ 展示对话页

  学生发送消息：
    ↓ POST /api/v1/assistant/message（content≤500字）
    ↓ 内容安全检查 → 违规返回 ASST-002
    ↓ 组装学习状态快照（五力摘要+错题+对话历史，≤1200 Token）
    ↓ 选择启发策略（查询历史有效性档案）
    ↓ 调用 LLM 生成回复（流式输出，≤400字）
    ↓ 理解突破检测
    ├─ 检测到突破 → is_aha_moment=true，生成成就感反馈
    └─ 无突破 → 普通回复
    ↓ 写入 ai_chat_messages（学生 + AI 各一条）
    ↓ 更新 proactive_count（若AI主动介入）

策略切换逻辑：
  同一策略连续2次使用 + 学生无明显理解进展
    ↓ 查询 ai_student_strategy_profiles
    ↓ 选择历史有效性最高的未使用策略
    ↓ 若无历史数据 → 按默认优先级顺序
    ↓ 写入 ai_strategy_events（event_type=strategy_switch）

结束对话：
  用户点击"结束对话" 或 达到30轮限制
    ↓ POST /api/v1/assistant/session/{session_id}/end
    ↓ AI 生成会话摘要（≤100字）
    ↓ 更新 ai_chat_sessions（status=completed）
    ↓ 若有错题复盘产生突破 → 更新 wrong_answer_records.review_status
    ↓ 异步更新 ai_student_strategy_profiles
    ↓ 展示会话总结
```

### 5.4 约束条件

## 9. 题库管理模块

> **版本变更说明（v1.2.0）：** 题库管理流程全面重构，改为"录入题干 → 大模型分析 → 管理员审核（可修改）→ 发布/驳回"的统一闭环流程，审核功能集成于本模块，无独立的审核页面。

### 9.1 功能点列表

| 功能点 | 说明 |
|--------|------|
| 题目列表 | 多条件过滤、游标分页，展示题目状态（草稿/分析中/待审核/已发布/已归档）|
| 录入题干 | 管理员仅需填写题干文本和可选配图，保存后进入草稿状态 |
| 模型分析 | 管理员点击「模型分析」按钮，系统异步调用大模型对题干进行分析 |
| 审核分析结果 | 查看大模型返回的全部分析结果，支持对任意字段进行修改 |
| 发布 | 审核通过后点击「发布」，题目变为已发布状态，可用于学生训练 |
| 驳回 | 审核不通过时填写驳回意见，系统将驳回意见+题干重新提交大模型重新分析 |
| 下架 | 已发布题目下架为 `archived`，停止出现在训练推荐中 |
| 软删除 | `deleted_at` 标记，ChromaDB 同步停用对应向量 |
| 批量导入 | 批量导入题干列表，每道题目均自动触发模型分析 |

### 9.2 题目生命周期与状态流转

```
管理员录入题干
      │
      ▼
   [draft] ─── 点击「模型分析」 ──→ [analyzing] ─── 分析完成 ──→ [pending_review]
                                                                        │
                                                               ┌────────┴────────┐
                                                               │                 │
                                                            发布              驳回（填意见）
                                                               │                 │
                                                               ▼                 ▼
                                                          [published]       [analyzing]（重新分析）
                                                               │                 │
                                                            下架            分析完成
                                                               │                 │
                                                               ▼                 ▼
                                                          [archived]       [pending_review]
```

| 状态 | 说明 | 可执行操作 |
|------|------|-----------|
| `draft`（草稿） | 题干已保存，尚未触发模型分析 | 编辑题干、触发模型分析、软删除 |
| `analyzing`（分析中） | 大模型正在处理，异步执行 | 等待（约10~30秒），不可编辑 |
| `pending_review`（待审核） | 模型分析完成，等待管理员审核 | 查看并修改分析结果、发布、驳回 |
| `published`（已发布） | 题目上线，参与训练推荐 | 下架、查看 |
| `archived`（已归档） | 题目下线，不再参与训练 | 查看 |

**驳回后重新分析机制：**

管理员填写驳回意见后，系统将以下内容一起提交给大模型：
- 原始题干（stem）
- 驳回意见（rejection_reason）
- 上一次分析结果摘要（作为修正参考）

大模型收到反馈后重新输出修订后的分析结果，题目状态回到 `pending_review`，分析轮次（analysis_round）自动 +1。

### 9.3 大模型分析内容说明

管理员点击「模型分析」后，大模型对题干进行全面分析，输出以下结构化结果：

| 分析项 | 说明 | 示例 |
|--------|------|------|
| **科目** | 该题所属学科 | 数学 / 物理 / 化学 |
| **年级** | 该题所属年级 | 九年级（G9）|
| **学期** | 该题所属学期 | 上学期（S1）/ 下学期（S2）|
| **单元** | 该题所属单元 | 第三章：方程与方程组 |
| **知识点** | 该题涉及的知识点（支持多个） | [二元一次方程组, 应用题建模] |
| **题目类型** | 题目的作答形式 | 单选题 / 多选题 / 填空题 / 判断题 / 应用题 |
| **题目答案** | 该题的标准答案（依题型结构化返回） | 见下方答案格式说明 |
| 难度 | 题目难度等级 | 基础 / 进阶 / 挑战 |
| 参考解析 | 完整解题过程（面向学生展示，与答案互补） | 设人数为x，总价为y... |
| 典型错误 | 学生最常犯的错误描述 | 把盈余关系写反（400x+3400=y） |
| 五力训练思路 | 各维度对应的训练切入点 | 见下表 |
| 五力训练权重 | 各维度对该题的权重（总分10分） | 建构力:5, 洞察力:2... |
| 迁移方向 | 该题可迁移的应用场景 | [班级活动收费, 租车收费] |

> **五级体系字段设计意图：** 管理员录入题干后，大模型根据题目内容自动判断归属的五级知识体系节点（科目→年级→学期→单元→知识点），供管理员审核确认（可修改）。最终确认的归属信息存储于题目记录，驱动左侧知识体系树的五级节点筛选功能。

**题目类型说明：**

| 类型值 | 中文名 | 适用场景 |
|--------|--------|---------|
| `SINGLE_CHOICE` | 单选题 | 四个选项，唯一正确答案 |
| `MULTIPLE_CHOICE` | 多选题 | 多个选项，两个及以上正确答案 |
| `FILL_BLANK` | 填空题 | 填写具体数值、表达式或短语 |
| `TRUE_FALSE` | 判断题 | 对 / 错二选一 |
| `APPLICATION` | 应用题 | 综合解答，含推导过程和最终结论 |

**题目答案格式说明（依题型结构化返回）：**

| 题目类型 | 答案结构 | 示例 |
|---------|---------|------|
| 单选题 | `{"type": "SINGLE_CHOICE", "correct": "B"}` | 正确选项字母 |
| 多选题 | `{"type": "MULTIPLE_CHOICE", "correct": ["A", "C"]}` | 正确选项字母数组 |
| 填空题 | `{"type": "FILL_BLANK", "correct": ["33", "9800"], "accept_range": null}` | 标准答案列表（多空对应多答案）|
| 判断题 | `{"type": "TRUE_FALSE", "correct": true}` | `true`=对，`false`=错 |
| 应用题 | `{"type": "APPLICATION", "final_answer": "x=33，y=9800", "key_steps": ["设人数x，总价y", "联立方程"]}` | 最终结论 + 关键步骤要点 |

> 答案字段用于训练判题和学生完成后的答案对照展示；参考解析（`solution`）用于 AI 辅导引导和 RAG 召回，两者互补，均由大模型生成后供管理员审核修改。

**五力训练权重说明（总计10分，示例）：**

```
洞察力: 2  建构力: 5  推演力: 2  调适力: 1  迁移力: 0
```

> 权重用于学生训练时的题目推荐排序：优先推荐弱力维度权重较高的题目，精准强化弱项。

| 题干必填 | 不可为空，其他字段（含归属五级体系）均由大模型填充 |
| 分析异步执行 | `analyzing` 状态下不可编辑，前端每隔5秒轮询状态，完成后自动刷新 |
| 驳回必填意见 | 驳回意见为必填字段，不可空提交 |
| 驳回自动重分析 | 驳回后无需手动再次触发，系统自动提交大模型新一轮分析 |
| 权重合计 | 五力训练权重总分必须等于10分 |
| 发布触发向量化 | 发布（`published`）后异步触发 Celery Queue-A 进行题目向量化入库 ChromaDB |
| 内容修改重置向量化 | 修改 stem 或 solution 后 `embedding_status` 重置为 `pending` |
| 删除为软删除 | `deleted_at` 标记，不物理删除，ChromaDB 同步停用 |

### 11.2 题目状态流转

```
           新增
            │
            ▼
         [draft]  ──编辑──▶  [draft]
            │
           发布
            │
            ▼
        [published]  ──编辑──▶  [published]
            │
           下架
            │
            ▼
        [archived]  ──编辑──▶  [archived]
            │
       重新发布（修改后可直接发布）
            │
            ▼
        [published]
```

| 状态 | 含义 | 可执行操作 |
|------|------|-----------|
| `draft`（草稿） | 已创建但未上线，不参与测试 | 编辑、发布、删除 |
| `published`（已发布） | 参与学生测试组卷，已发布总数 = 20 时测试生效 | 编辑、下架 |
| `archived`（已下架） | 不参与新测试，可在此状态下编辑修改内容，满足条件后重新发布 | **编辑、重新发布** |

> **历史成绩保护机制：** 每次测试会话创建时，系统会对当前已发布题目的内容（题干、答案、权重）生成不可变快照，存储在 `test_sessions.config_snapshot` 中。此后对题目的任何修改（包括下架编辑后重新发布）**均不影响已完成的历史测试会话及其评分结果**，历史成绩永远基于测试时的快照版本计算。
>
> **约束：** 同一时刻已发布题目数 **至少需要10道**，测试功能才对学生开放。不足10道时，小程序端发起测试将返回 `TEST-005` 错误。

### 15.2 用户角色与账号体系

#### 15.2.1 三类用户说明

| 角色 | 存储位置 | 登录方式 | 使用端 | 说明 |
|------|---------|---------|--------|------|
| 学生（STUDENT） | `students` 表，`user_type='STUDENT'` | 微信OAuth + 手机绑定 | 小程序 | 核心学习用户，拥有五力画像、训练记录 |
| 家长（PARENT） | `students` 表，`user_type='PARENT'` | 微信OAuth + 手机绑定 | 小程序 | 通过绑定关系查看子女学习情况，无训练数据 |
| 管理员（ADMIN） | `admin_users` 表 | 用户名/密码 + 短信2FA | 后台管理系统 | 运营/内容管理，可管理所有用户数据 |

#### 15.2.2 家长-学生绑定方式

家长与学生之间的绑定是系统核心关联关系，支持三种绑定途径：

| 方式 | 发起方 | 流程描述 | bind_method 值 |
|------|--------|---------|----------------|
| **学生邀请家长** | 学生 | 学生在小程序生成8位邀请码 → 家长在小程序输入邀请码 → 绑定立即生效 | `INVITE_CODE` |
| **家长主动绑定** | 家长 | 家长在小程序输入学生手机号 → 系统向学生手机发送确认短信 → 学生确认后绑定生效 | `PARENT_SELF` |
| **管理员后台绑定** | 管理员 | 管理员在后台搜索学生 → 输入家长手机号（不存在则自动创建家长账号）→ 立即绑定 | `ADMIN` |

**绑定约束：**
- 每位学生最多绑定 **2 位家长**
- 每位家长最多绑定 **5 位学生**
- 家长和学生均须已注册小程序账号（管理员绑定时若家长未注册，系统自动创建待激活账号）

### 15.4 学生画像设计

#### 15.4.1 设计思路

用户画像面向管理员，目标是让管理员在最短时间内全面了解一名学生的**认知能力现状、学习行为模式、AI 辅导效果**，从而支撑运营决策（如：题库内容优化、AI 策略调整、异常学生关怀）。画像分为六大维度：

| 画像维度 | 核心问题 | 数据来源 |
|----------|----------|----------|
| **基础信息** | 这个学生是谁？绑定了哪些家长？ | `students`、`parent_student_bindings` |
| **五力认知画像** | 认知能力现状如何？哪里最弱最强？ | `five_power_profiles`、`five_power_training_profiles` |
| **学习行为画像** | 有多勤奋？训练习惯如何？ | `training_sessions`、`training_answer_records` |
| **AI 助教互动画像** | 和 AI 的交互质量如何？是否产生了理解突破？ | `ai_chat_sessions`、`ai_strategy_events` |
| **错题薄弱画像** | 反复在哪里出错？哪些知识点是盲区？ | `wrong_answer_records` |
| **成长轨迹** | 是否在进步？五力成长趋势如何？ | `five_power_profiles`（历史多条） |

#### 15.4.2 画像包含信息详细说明

**一、基础信息**

| 信息项 | 说明 |
|--------|------|
| 学生昵称 / ID | 唯一标识 |
| 年级 | G7~G12 |
| 学科偏好 | 数学 / 物理 / 化学（多选）|
| 是否未成年 | 影响内容安全策略 |
| 注册时间 | 用户生命周期起点 |
| 最后活跃时间 | 判断是否流失 |
| 绑定家长 | 已绑定家长列表（0~2位），含绑定方式和绑定时间 |
| 累计登录天数 | 学习粘性基础指标 |

**二、五力认知画像**

| 信息项 | 说明 |
|--------|------|
| 五力雷达图（当前） | 洞察/建构/推演/调适/迁移五维综合分（测试×40% + 训练×60%）|
| 各维度能力分（ability_score） | 来自五力测试，反映真实能力 |
| 各维度认知入口分（preference_score） | 习惯从哪个维度进入新知识，指导教学路径 |
| 当前最弱力 | primary_weakness，训练主要目标 |
| 当前优势入口力 | preferred_force，借强补弱的切入点 |
| 推荐训练模式 | TRAIN_WEAKNESS / LEARN_BY_STRENGTH |
| AI 个性化分析摘要 | 测试后 AI 生成的 150 字学情描述 |
| 测试次数 / 最近测试时间 | 了解测试参与情况 |

**三、学习行为画像**

| 信息项 | 说明 |
|--------|------|
| 累计训练会话数 | 整体学习投入程度 |
| 累计答题数 | 练习总量 |
| 整体答题正确率 | 综合掌握水平 |
| 各五力维度训练正确率 | 哪个维度练得最好/最差 |
| 最近 7 天训练天数 | 近期活跃度 |
| 平均单次训练时长（分钟）| 专注力指标 |
| 训练完成率 | 正常完成 vs 提前结束 vs 放弃 占比 |
| 最常训练的知识点 Top 3 | 学习偏好与薄弱集中点 |

**四、AI 助教互动画像**

| 信息项 | 说明 |
|--------|------|
| 累计对话会话数 | AI 使用深度 |
| 累计对话轮次 | 学习深度指标 |
| 理解突破（aha）次数 | 核心效果指标——AI 是否真正帮助了学生 |
| 突破率（aha/总会话） | AI 教学有效性 |
| 最常使用的会话模式 | 自由提问 / 错题复盘 / 训练介入 |
| 最有效启发策略 Top 3 | 该生对哪种策略最容易产生突破 |
| 沉默模式触发次数 | 学生主动拒绝 AI 介入的频次 |

**五、错题薄弱画像**

| 信息项 | 说明 |
|--------|------|
| 累计错题数 | 总难点量 |
| 错题按五力维度分布 | 哪个维度出错最多 |
| 错题复盘率 | 错题中已复盘的比例 |
| 错题突破率 | 已复盘错题中达到 aha_achieved 的比例 |
| 未复盘错题数 | 待处理的学习盲点数量 |
| 高频错题知识点 Top 5 | 精准定位盲区 |

**六、成长轨迹**

| 信息项 | 说明 |
|--------|------|
| 五力历次测试趋势折线图 | 各维度成绩随时间变化，直观展示成长 |
| 最近两次测试对比 | 双色叠加雷达图，量化成长幅度 |
| 训练正确率趋势 | 近 30 天按周统计，反映练习效果 |
| 系统参与天数 | 注册以来的实际活跃天数 |

### 15.8 AI助教提示词摘要

#### 15.8.1 设计思路

提示词摘要是一份动态维护的学生画像文本，专门用于注入大模型的系统提示词（System Prompt），使 AI 助教能以更贴近该学生的方式进行辅导互动。摘要分为两大模块：

| 模块 | 内容 | 来源 |
|------|------|------|
| **学习信息摘要** | 年级学期、科目偏好、五力画像、核心薄弱点、高频错题知识点、近期训练错误率 | 系统自动生成，定期刷新 |
| **个人洞察摘要** | 学生近期状态、心情、兴趣爱好、重要生活事件、与AI聊天中透露的关键个人信息 | AI从对话中提取，管理员可手动补充/修正 |

**更新机制：**
- **学习信息摘要**：训练会话结束后、五力测试完成后，由系统异步重新生成（基于 `student_kp_stats`、`five_power_profiles` 等结构化数据）
- **个人洞察摘要**：AI助教在每次对话会话结束时，从 `session_summary` 中提取关键个人信息，追加或更新到摘要中；管理员可在后台手动编辑

#### 15.8.3 个人洞察提取规则

AI助教在每次对话会话结束后，对 `session_summary` 进行二次分析，提取以下类型的关键信息：

| 信息类型 | 提取示例 | 触发场景 |
|---------|---------|---------|
| 兴趣爱好 | "喜欢打篮球、湖人球迷" | 自由对话中学生主动提及 |
| 近期心情/状态 | "期中考试压力大，感到焦虑" | 学生表达情绪时 |
| 重要生活事件 | "下周有体育考试" | 学生描述近期安排 |
| 有效类比偏好 | "游戏RPG类比效果好" | AI使用某类比后出现aha时刻 |
| 家庭背景线索 | "爸爸比较严格" | 学生在对话中透露 |
| 学习心态 | "对数学有畏难情绪" | AI策略分析时识别 |

**提取原则：**
- 仅提取学生主动表达的信息，不推断或臆测
- 涉及隐私的内容（家庭纠纷、心理问题等）标记为「敏感」，仅管理员可见，不注入Prompt
- 信息有时效性：超过30天未更新的条目自动降权，超过90天自动归档

#### 15.8.4 交互规范

| 交互点 | 规则 |
|--------|------|
| 摘要入口 | 学生列表每行「摘要」按钮，进入摘要查看/编辑页 |
| 重新生成 | 点击「重新生成学习摘要」按钮，异步重新生成学习信息模块（不影响个人洞察部分）|
| 手动编辑 | 管理员可在个人洞察摘要区域直接编辑，支持富文本，保存时写入 `admin_audit_logs` |
| 手动补充 | 点击「+ 手动补充信息」可新增一条洞察条目，来源标记为「管理员」|
| Prompt预览 | 「完整Prompt预览」区域展示最终注入大模型的合并文本，只读 |
| 历史记录 | 按时间倒序展示洞察条目的历史，显示来源（AI提取/管理员）|
