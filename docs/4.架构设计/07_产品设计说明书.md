## 1. 产品总览

### 1.1 产品定位

MESH 是一款面向初中至高中生的数理化 AI 认知训练平台，以"五力认知诊断"为核心，通过个性化选题与 AI 全程陪伴，培养学生底层认知能力。

### 1.2 小程序整体结构

```
微信小程序
├── 登录注册（全屏引导页，首次进入）
│
├── Tab 1：个性化训练（默认选中）
│   ├── 训练首页（知识点导航）
│   ├── 训练答题页
│   ├── RAG 解题页（浮层）
│   └── 训练小结页
│
├── Tab 2：AI 助教
│   ├── 会话列表页
│   └── 对话页
│
└── Tab 3：我的五力
    ├── 五力画像页
    ├── 历史成长页
    └── 错题集页
```

### 1.3 首页导航规则

| 场景 | 跳转行为 |
|------|----------|
| 首次登录，无五力画像 | 全屏引导页 → 强引导完成五力测试 |
| 已有五力画像 | 进入首页，默认 Tab 1（个性化训练） |
| Tab 1 无画像时点击训练 | 弹出引导卡："先完成五力测试，解锁专属训练" |

### 1.4 训练模块核心策略：借强补弱

MESH 训练系统的核心理念是**借强补弱**，而非直接暴露弱点：

- 五力测试完成后，系统识别学生的**优势入口力**（`preferred_force`）和**目标训练力**（`primary_weakness`）
- 训练时不将学生直接丢进最陌生的思维方式，而是以优势力为切入点，通过 AI 个性化引导，逐步过渡到目标力的训练
- 训练首页**不展示**"最弱两力"提示，避免给学生造成心理负担
- ~~进入训练会话后，顶部展示一条借强补弱提示横幅~~（**v2.3 起取消**：答题页不再展示提示盒子，借强补弱的引导体现在 AI 解析与助教对话中）

### 2.3 系统交互

```
微信登录流程：
  用户点击"微信一键登录"
    ↓ 调用 wx.login() 获取 code
    ↓ POST /api/v1/auth/wx-login（携带 code）
    ↓ 后端 code2session → 获取 openid
    ↓ 查询 students 表（by openid_hash）
    ├─ 新用户 → 返回 temp_token + is_new_user=true
    │   ↓ 前端跳转手机号绑定页
    │   ↓ 发送短信验证码（POST /api/v1/auth/sms/send）
    │   ↓ 提交绑定（POST /api/v1/auth/bind-phone）
    │   ↓ 返回 access_token + refresh_token
    │   ↓ 跳转首页（引导五力测试）
    └─ 老用户 → 返回 access_token + refresh_token
        ↓ 跳转首页
```

```
静默续期流程：
  小程序启动
    ↓ 读取本地 access_token
    ↓ POST /api/v1/auth/token/validate
    ├─ 有效 → 直接进入首页
    ├─ 已过期可刷新 → POST /api/v1/auth/token/refresh → 更新 Token
    └─ 完全失效 → 弹出"请重新登录"提示
```

### 2.4 约束条件

| 约束项 | 规则 |
|--------|------|
| 短信发送频率 | 同号每 60 秒限发 1 次，每日最多 10 次 |
| 验证码有效期 | 5 分钟，错误超 5 次作废 |
| Token 有效期 | access_token 7 天，refresh_token 30 天 |
| 手机号唯一性 | 同一手机号只能注册一个账号 |
| 邀请码有效期 | 48 小时，一次性使用 |
| 每学生最多绑定家长数 | 2 人（应用层控制） |
| 账号注销 | 30 天内可恢复，期满后自动清除 AI 对话等隐私数据 |

### 3.3 系统交互

```
测试完整流程：

[引导页] → 点击"开始测试"
    ↓ GET /api/v1/test/questions
    ↓ 返回 session_id + 20道题（打散顺序）

[逐题答题]
    ↓ 学生选择选项
    ↓ POST /api/v1/test/answer（每题提交）
    ↓ 记录 selected_option, time_spent_sec, modify_count
    ↓ 更新进度条

[最后一题] → 点击"提交"
    ↓ 确认弹窗："确认提交测试吗？"
    ↓ POST /api/v1/test/complete
    ↓ 后端同步评分（≤3秒）
    ↓ 写入 five_power_profiles（is_latest=true）
    ↓ 触发 Celery Queue-E（异步AI分析）

[结果展示]
    ↓ 前端接收三层评分数据
    ↓ 展示雷达图 + 分数
    ↓ ai_analysis_status = pending → 骨架屏占位
    ↓ 轮询 GET /api/v1/test/result/{profile_id}（每3秒）
    ↓ ai_analysis_status = completed → 填充AI分析文字

[中断恢复]
    用户中途退出
    ↓ 重新进入小程序
    ↓ 检测到 session_status = in_progress
    ↓ 弹窗："检测到上次未完成测试（已完成7/20题）"
    ├─ [继续] → 从第8题开始，保留已答答案
    └─ [重新开始] → 旧session标记abandoned，重新创建
```

### 3.4 约束条件

| 约束项 | 规则 |
|--------|------|
| 题目数量 | 固定 20 道（不可增减） |
| 重测间隔 | 推荐≥30天，强制无限制 |
| 中断恢复窗口 | 72 小时内有效，超时标记 expired |
| 评分时间 | 同步评分≤3秒，AI分析异步5~30秒 |
| 答案权重计算 | 每个答案含五力权重（非负整数，五项之和=10），学生选择某答案即累加该答案的五力分值，最终归一化为各维度综合分 |
| 仓促答题标记 | time_spent_sec < 5 秒，自动标记 is_rushed |
| 答案修改 | 允许，覆盖提交，记录 modify_count |
| 前台不显示"测什么" | 题目不显示对应的五力维度 |

**作答区按题型变化：**

| 题型 | 作答组件 | 提交内容 |
|------|---------|---------|
| 单选题 | 单选组件，每项显示 `A. xxx`；点击整行即选中，再次点选其他项则切换 | 选项字母，如 `C` |
| 多选题 | 复选框，每项显示 `A. xxx`；可多选，再次点击取消 | 选中的字母，如 `CD` |
| 判断题 | 单选组件，两项：「对」「错」 | `对` / `错` |
| 填空题 | 按空数逐行列出 `1. ______`、`2. ______`，每个空是下划线样式的单行输入框 | 按空作答的数组（`student_answers`） |
| 应用题 | 两栏：「解题过程」（多行，选填）+「最终答案」（单行，带单位提示） | 最终答案栏单独提交（`final_answer`），过程栏仅留作解析参考 |
| 简答题（预留） | 暂用多行文本框，题库暂无简答题 | 文本 |
| 选项拆分失败的选择题 / 无题型的题 | 退回多行文本框，提示"请输入选项字母" | 文本 |

**通用规则：**
- **选项来源：** 题库中选项写在题干文本里，由服务端下发时拆分为「纯题干 + 选项列表」；拆分不出来时退回文本框，不影响作答。
- **未作答可提交：** 任何题型都不拦截空提交，服务端按未作答判错；提交后作答区只读展示所选内容，未作答显示「（未作答）」。
- **符号快捷条：** 填空题输入框、应用题的两个输入框上方提供常用数学符号一键插入：`× ÷ ² ³ √ π ° ≤ ≥ ≠ ± ( )`，插入到当前光标处。服务端比对前会把 `x` `*` `^9` 等常见替代写法标准化（见接口设计说明书 §5.2），学生写 `1.4x10^9` 也能判对。
- **聚焦：** 点击作答区（标题行、留白、题目选项以外的位置）会让第一个输入框获得焦点；选择类题型无输入框，不触发。
- **题型提示：** 作答区标题行右侧给出该题型的简短格式提示（如「填空：共 2 个空，依次作答」「多选：选所有正确选项」）。
- **样式：** 作答区不使用渐变高亮边框和扫光；输入框无边框、背景与作答区一致，避免割裂。
- **题目类型标签：** 题目上方左侧展示该题的「题目类型」标签（图标 + 文字，淡色底 + 同色描边，颜色与后台训练题管理「题目类型」列一致，随亮 / 暗主题切换），替代原先的五力标签；右侧为收藏按钮（五角星图标，替代原来的题号进度 `2/5`）：点击收藏题目（星星变为实心金色），再点取消收藏；答题前、答题后、回看已答题时都可点击。题型缺失时不显示标签。
- **作答结果展示：** 提交后**不再弹出任何结果提示框**，而是让**答题卡（答题框）自身变色**：答对为绿色、答错为红色，**底色极淡（亮色约 4% / 暗色约 5% 透明度，只做淡淡的底、不遮住作答内容）、描边较实（约 40% 透明度）**，随亮 / 暗主题切换；答题框标题行**最右侧**显示结果图标（不带圆圈，与左侧图标同大同行居中）。图标仿复选框里「✓」的书法式写法：对勾左短右长、左细右粗并微微上扬；叉为一粗一细两笔略带弧度的交叉，线条不方正。
- **提交后的操作栏：** 完成作答后，底部三个按钮组成一个整体的分段按钮：「‹ 上一题」「✦ 智能解答」「下一题 ›」（最后一题为「完成训练」）。整体是一个胶囊：**两端按钮靠边侧是圆角，相邻的内侧是直角**。三个按钮合起来是一条**从左到右的连续渐变**（灰底 → 主色淡 → 主色），三个按钮之间**留 2px 间距**，每个按钮各画一段同一条渐变（按位置错开），拼起来仍是连续过渡；文字色随所在渐变段变化：「上一题」次要文字色，「智能解答」暗色白 / 亮色深蓝，「下一题」主按钮文字色。
  - **上一题：** 回到上一道题，已作答的题目以只读方式展示作答和判题结果；在第一题点击时提示「已经是第一题了」。
  - **智能解答：** 点击后才调用大模型（接口设计说明书 §5.3），按钮变为「生成中...」，题目下方出现「AI 正在生成解析」骨架屏，完成后显示「AI 参考解析」卡片；**答对、答错都可以点击**，答错后不会自动生成。已生成过的题目再点只滚动到解析卡片，不会重复调用；大模型不可用时显示题库静态「参考解析」，并提供「重新生成 AI 解析」按钮。
  - **下一题：** 下一题已作答过（先点过「上一题」回看）时，直接显示只读的作答；否则进入未作答状态。
- **选项选中效果：** 单选 / 多选 / 判断的选项选中时，底色为蓝色横向渐变（同后台下拉框选中项）、圆角 8px；底色比选项内容向左右各多伸出一段，使文字和圆圈不紧贴选中效果的边缘。

### 4.6.1 智能训练（v2.8 新增）

**入口：** 训练方式里「随机训练」上方的「智能训练」卡片，点击直接开始，不用选范围，范围固定为当前学期（缺年级学期时弹窗补充）。

**目标：** 根据学生的情况自动设计一套题，既巩固强项，又提高弱项。

**依据的信息：**

| 信息 | 用途 |
|------|------|
| 五力分布 | 偏向弱项五力的题；强项五力的题用于拓展 |
| 错题集 | 错得多的知识点、错得多的题型多出；待攻克的题优先巩固 |
| 收藏夹 | 收藏过的题 / 知识点适当回顾 |
| 做题历史 | 近期错误率高的知识点优先（越近权重越大）；已攻克的题按 1、3、7、14 天间隔到期复习；最近做过的题避开 |
| AI 助手聊天 | 学生说「最近老师讲的某某知识点不太懂」，大模型提取成知识点，该知识点的题至少出 1 道 |

**组卷：** 默认 5 题 = 弱项强化 3 + 强项拓展 1 + 复习与探索 1（配比、权重后续在管理系统配置）；每个槽位按分数加权随机抽，不是取最高分，保证每次不一样；同题型 / 同知识点不会扎堆。

**推荐理由：** 答题页题型标签右侧显示这道题的出题理由，如「薄弱知识点」「待攻克巩固」「你提到的困惑」「强项拓展」「到期复习」「收藏回顾」，方便学生理解，也方便评估算法。

**没有聊天信息时：** 聊天为空（还没和 AI 助手交流过）或大模型不可用，只是少一类信号，其余信息照常出题，不影响使用。

**隐私：** 只提取「困惑的知识点」和一段不超过 100 字的概括，不保存聊天原文。

**后台联动：** 学生管理 → 摘要 → 「学习信息摘要」由系统自动生成，内容包含五力、错题集 / 收藏概况、薄弱知识点和题型、近期向 AI 助手提到的困惑；分析聊天或完成训练后自动刷新，也可点「重新生成学习摘要」手动刷新。

### 4.7 约束条件

| 约束项 | 规则 |
|--------|------|

```
错题集训练里答对待攻克的题 ──→ 已攻克
其它训练里答对 ────────────→ 不改变状态
```

同一学生同一道题只有一条记录，重复答对 / 答错都合并，不重复计数。

### 7.4 约束条件

| 约束项 | 规则 |
|--------|------|
| 错题自动生成 | 训练答错时自动创建，无需手动操作 |
| 合并去重 | 同一学生同一道题只有一条记录（数据库唯一约束） |
| 攻克规则 | 在错题集训练里答对一次即归入已攻克（不再有「连续答对 N 次」） |
| 统计范围 | 只统计当前年级学期、后台已启用的题 |
| 错题软删除 | 不提供手动删除（保护学习记录完整性） |

### 7.5 收藏夹（v2.6 新增）

**入口：** 个性化训练选科目后，「错题集」下方的「收藏夹」卡片（显示「N 题收藏」）。

**收藏：** 答题页右上角五角星，点击收藏，再点取消收藏；同一道题只有一条收藏记录。

**收藏夹页面：** 样式同错题集，层级为「收藏夹 → 单元 → 知识点」，只含当前学期、后台已启用的题，每级右侧是题数（题目去重）。

```
┌──────────────────────────────────────┐
│  数学 · 初一 · 上学期        [修改]   │
│  共收藏 3 题                          │
│                                      │
│  收藏夹                     3 题    ⌄ │  ← 点行：从全部收藏的题里抽；点箭头：展开 / 收起
│  ──────────────────────────────────  │
│  第四章：几何图形初步        3 题    ⌄ │  ← 点行：只抽这一章
│      线段的比较与运算        2 题    › │  ← 点行：只抽这个知识点
└──────────────────────────────────────┘
```

**规则：**
- 点任意一级直接进入答题，默认 5 题（维度配置），按题型 / 难度比例抽取，尽量避开最近做过的题
- 取消收藏后该题立即从收藏夹去掉；在收藏夹训练里取消收藏，本轮训练照常继续
- 收藏夹训练里答错归入待攻克，答对不改变待攻克 / 已攻克状态
- 没有收藏题时点击提示「暂无收藏题目」；缺年级学期时弹窗补充

### 9.1 功能点列表

| 功能点 | 说明 |
|--------|------|
| 题目列表（未发布）| 展示草稿、分析中、待审核三种状态的题目，已发布/已停用题目不在此列表显示；支持难度筛选、关键词搜索与分页 |

| 编辑题干 | 对草稿状态题目修改题干内容，编辑完成后仍保持草稿状态 |
| 模型分析 | 管理员点击「模型分析」按钮，系统异步调用大模型对题干进行分析 |
| 审核分析结果 | 查看大模型返回的全部分析结果，支持对任意字段进行修改后发布 |
| 发布 | 两种方式：① 进入「审核结果」页面确认后点击发布；② 在列表对待审核题目点击「发布」直接快速发布（系统自动使用大模型分析结果）；发布后题目转至训练题管理模块（第10章） |
| 驳回 | 审核不通过时填写驳回意见，题目状态变为「草稿」，管理员可修改驳回意见后手动点击「AI分析」重新触发分析 |

| 批量模型分析 | 勾选多条题目，一键批量触发模型分析；仅 `draft` 状态题目参与，其他状态由后端跳过并在结果中说明。**由后端批量接口一次性处理**（接口设计说明书 §9.1.10.1） |
| 批量发布 | 勾选多条题目，一键批量发布；仅 `pending_review`（待审核）状态题目参与，直接使用大模型分析结果发布；分析数据不完整的题目不发布并在结果中说明。**由后端批量接口一次性处理**（接口设计说明书 §9.1.10.2） |
| 批量删除 | 勾选多条草稿题目，一键批量软删除；仅 `draft` 状态题目参与。后端接口已提供（接口设计说明书 §9.1.10.3），当前版本页面暂未开放入口 |

### 9.1.1 批量操作交互说明

> **v1.9.0 调整：** 批量操作改为**由后端批量接口处理**，前端只提交勾选的题目 ID 列表，不再循环调用单题接口；新增「批量发布」；批量按钮常驻于列表顶部工具栏（不再使用勾选后才出现的批量操作栏）。

**按钮位置与顺序：** 列表顶部工具栏右侧，从左到右依次为 `[批量发布] [批量分析] [批量导入] [+ 录入题干]`。列表表格首列为复选框选择列，支持单行勾选或表头全选。

**点击批量按钮后的判断流程（批量分析 / 批量发布通用）：**

| 勾选情况 | 系统响应 |
|---------|---------|
| 未勾选任何题目 | 提示「请先勾选需要分析 / 发布的题目」，不发请求、不弹窗 |
| 勾选项中不含可处理状态 | 提示「所选题目中不包含草稿 / 待审核状态的题目，仅…可以…」，不发请求、不弹窗 |
| 勾选项中含可处理状态 | 弹窗确认，管理员确认后调用后端批量接口 |

**可处理状态：** 批量分析仅 `draft`（草稿）；批量发布仅 `pending_review`（待审核）。其他状态的题目不会被处理。

**确认弹窗文案：**

- 全部符合：
  - 批量分析：「已勾选 N 道草稿题目，将依次提交大模型分析。是否继续？」
  - 批量发布：「已勾选 N 道待审核题目，将直接使用大模型分析结果依次发布，发布后题目将参与训练推荐。是否继续？」
- 部分符合：「已勾选 N 道题目，其中 M 道为草稿 / 待审核状态，将…；其余 K 道状态不符，会被跳过。是否继续？」（N = M + K）
- 按钮：批量分析为「开始分析 / 取消」；批量发布为「确认发布 / 取消」

**执行逻辑：**
- 确认后前端**一次性**调用后端批量接口（请求次数恒为 1 次，与勾选数量无关），提交勾选的全部题目 ID（单次最多 200 条）
- 请求期间对应按钮显示加载状态，防止重复提交
- 资格校验、状态流转、并发与限流由后端负责；前端的预校验仅用于交互优化，最终以后端返回为准
- 批量分析为异步：接口返回表示任务已提交，题目状态变为「分析中」，完成后变为「待审核」，需刷新列表查看
- 批量发布为同步：接口返回即为发布结果，发布成功的题目转至训练题管理模块

**结果提示（依据接口返回的汇总计数）：**

| 结果 | 提示 |
|------|------|
| 全部成功 | 「已提交 / 已发布 N 道题目…」（成功提示） |
| 存在跳过或失败 | 「已… X 道；Y 道状态不符被跳过；Z 道…失败 / 分析数据不完整，请进入『审核结果』页面补充后再发布」（警告提示，只列出数量大于 0 的项） |

完成后自动清空勾选并刷新列表和统计数据。

**设计说明：** 勾选量较大时（如 100 条），逐条调用单题接口会产生 100 次（批量发布为 200 次）请求，耗时线性增长，中途中断还会出现不可见的部分完成状态，也无法由后端统一限流与审计；故改为后端批量接口。接口约定见接口设计说明书 §9.1.10。

### 9.2 题目生命周期与状态流转

```
管理员录入题干
      │
      ▼
   [draft] ─── 点击「模型分析」 ──→ [analyzing] ─── 分析完成 ──→ [pending_review]
                                                                        │
                                                               ┌────────┴────────┐
                                                               │                 │
                                                            发布              驳回（填意见）
                                                               │                 │
                                                               ▼                 ▼
                                                          [published]         [draft]（手动点击AI分析）
                                                               │                 │
                                                            停用            分析完成
                                                               │                 │
                                                               ▼                 ▼
                                                          [archived]       [pending_review]
```

| 状态 | 说明 | 可执行操作 |
|------|------|-----------|
| `draft`（草稿） | 题干已保存，尚未触发模型分析 | 编辑题干、触发模型分析、软删除 |
| `analyzing`（分析中） | 大模型正在处理，异步执行 | 等待（约10~30秒），不可编辑 |
| `pending_review`（待审核） | 模型分析完成，等待管理员审核 | 查看并修改分析结果、发布、驳回 |
| `published`（已发布） | 题目上线，参与训练推荐；在训练题管理模块可见 | 停用、查看 |
| `archived`（已停用） | 题目停用，不再参与训练推荐；在训练题管理模块可见 | 编辑、启用、查看 |

**驳回后重新分析机制：**

管理员填写驳回意见后，题目状态变为 `draft`，驳回意见保存在 `rejection_reason` 字段。管理员可查看驳回意见、修改后手动点击「AI分析」按钮重新触发分析。

重新触发分析时，系统将以下内容一起提交给大模型：
- 原始题干（stem）
- 驳回意见（rejection_reason，自动携带，无需手动填写）

大模型收到反馈后重新输出修订后的分析结果，题目状态回到 `pending_review`，分析轮次（analysis_round）自动 +1，`rejection_reason` 自动清空。

### 9.3 大模型分析内容说明

管理员点击「模型分析」后，大模型对题干进行全面分析，输出以下结构化结果：

| 分析项 | 说明 | 示例 |
|--------|------|------|
| **科目** | 该题所属学科 | 数学 / 物理 / 化学 |
| **年级** | 该题所属年级 | 九年级（G9）|
| **学期** | 该题所属学期 | 上学期（S1）/ 下学期（S2）|
| **单元** | 该题所属单元 | 第三章：方程与方程组 |
| **知识点** | 该题涉及的知识点（支持多个） | [二元一次方程组, 应用题建模] |
| **题目类型** | 题目的作答形式 | 单选题 / 多选题 / 填空题 / 判断题 / 应用题 |
| **题目答案** | 该题的标准答案（依题型结构化返回） | 见下方答案格式说明 |
| 难度 | 题目难度等级 | 基础 / 进阶 / 挑战 |
| 参考解析 | 完整解题过程（面向学生展示，与答案互补） | 设人数为x，总价为y... |
| 典型错误 | 学生最常犯的错误描述 | 把盈余关系写反（400x+3400=y） |
| 五力训练思路 | 各维度对应的训练切入点 | 见下表 |
| 五力训练权重 | 各维度对该题的权重（总分10分） | 建构力:5, 洞察力:2... |
| 迁移方向 | 该题可迁移的应用场景 | [班级活动收费, 租车收费] |

> **五级体系字段设计意图：** 管理员录入题干后，大模型根据题目内容自动判断归属的五级知识体系节点（科目→年级→学期→单元→知识点），供管理员审核确认（可修改）。最终确认的归属信息存储于题目记录，驱动左侧知识体系树的五级节点筛选功能。

**题目类型说明：**

| 类型值 | 中文名 | 适用场景 |
|--------|--------|---------|
| `SINGLE_CHOICE` | 单选题 | 四个选项，唯一正确答案 |
| `MULTIPLE_CHOICE` | 多选题 | 多个选项，两个及以上正确答案 |
| `FILL_BLANK` | 填空题 | 填写具体数值、表达式或短语 |
| `TRUE_FALSE` | 判断题 | 对 / 错二选一 |
| `APPLICATION` | 应用题 | 综合解答，含推导过程和最终结论 |

**题目答案格式说明（依题型结构化返回）：**

| 题目类型 | 答案结构 | 示例 |
|---------|---------|------|
| 单选题 | `{"type": "SINGLE_CHOICE", "correct": "B"}` | 正确选项字母 |
| 多选题 | `{"type": "MULTIPLE_CHOICE", "correct": ["A", "C"]}` | 正确选项字母数组 |
| 填空题 | `{"type": "FILL_BLANK", "correct": ["33", "9800"], "accept_range": null}` | 标准答案列表（多空对应多答案）|
| 判断题 | `{"type": "TRUE_FALSE", "correct": true}` | `true`=对，`false`=错 |
| 应用题 | `{"type": "APPLICATION", "final_answer": "x=33，y=9800", "key_steps": ["设人数x，总价y", "联立方程"]}` | 最终结论 + 关键步骤要点 |

> 答案字段用于训练判题和学生完成后的答案对照展示；参考解析（`solution`）用于 AI 辅导引导和 RAG 召回，两者互补，均由大模型生成后供管理员审核修改。

**五力训练权重说明（总计10分，示例）：**

```
洞察力: 2  建构力: 5  推演力: 2  调适力: 1  迁移力: 0
```

> 权重用于学生训练时的题目推荐排序：优先推荐弱力维度权重较高的题目，精准强化弱项。

### 9.5 约束条件

| 约束项 | 规则 |
|--------|------|
| 题干必填 | 不可为空，其他字段（含归属五级体系）均由大模型填充 |
| 分析异步执行 | `analyzing` 状态下不可编辑，前端每隔5秒轮询状态，完成后自动刷新 |
| 驳回必填意见 | 驳回意见为必填字段，不可空提交 |
| 驳回后手动重分析 | 驳回后题目回到草稿状态，管理员查看驳回意见后手动点击「AI分析」重新触发；重新分析时驳回意见自动携带给大模型 |
| 权重合计 | 五力训练权重总分必须等于10分 |
| 发布触发向量化 | 发布（`published`）后异步触发 Celery Queue-A 进行题目向量化入库 ChromaDB |
| 内容修改重置向量化 | 修改 stem 或 solution 后 `embedding_status` 重置为 `pending` |
| 删除为软删除 | `deleted_at` 标记，不物理删除，ChromaDB 同步停用 |

**批量启用 / 停用交互流程：**

```
勾选题目 → 点击「批量启用」或「批量停用」
  ├─ 未勾选任何题目            → 提示「请先勾选需要启用/停用的题目」，不发请求
  ├─ 勾选超过 200 条           → 提示「单次最多启用/停用 200 道题目，当前已勾选 N 道，请减少勾选后重试」，不发请求
  ├─ 勾选项中无可处理题目      → 提示「所选题目均已处于启用/停用状态」，不发请求
  └─ 存在可处理题目            → 弹窗确认
                                    文案含：可处理 X 道，将跳过 Y 道（状态已是目标状态）
                                    └─ 确认 → 一次调用批量接口 → 结果提示：
                                         全部成功                  → 成功提示「已启用/停用 N 道题目」
                                         存在 skipped / failed     → 警告提示，分别列出跳过数与失败数
                                       → 清空勾选，刷新列表
```

| 校验项 | 前端规则（仅交互优化） |
|--------|------------------------|
| 可处理判定 | 批量启用：行 `is_active === false`；批量停用：行 `is_active !== false` |
| 数量上限 | 勾选总数 ≤ 200（与后端 `QBATCH-002` 一致），超限直接提示 |
| 最终校验 | 以后端为准；前端数据可能过期，后端返回的 `skipped` / `failed` 统一在结果提示中体现 |
| 按钮状态 | 请求进行中对应按钮显示 loading，防止重复提交 |
| 勾选保留 | 翻页、筛选、切换知识树节点后清空勾选（勾选范围仅限当前页，避免用户误操作不可见的题目） |

### 10.3 约束条件

| 约束项 | 规则 |
|--------|------|
| 停用同步向量 | 停用（`archived`）后 ChromaDB 对应向量标记 `is_active=false`，不再参与题目推荐 |
| 启用同步向量 | 启用（重新 `published`）后 ChromaDB 对应向量标记 `is_active=true`，重新参与题目推荐 |
| 停用/启用不物理操作 | 两个操作均仅变更 `status` 字段，数据完整保留；`deleted_at` 不受影响 |
| 树计数仅统计已发布 | 知识体系树各节点括号内的数量仅统计 `status='published'` 的题目，已停用题目不计入 |
| 树过滤不区分状态 | 点击树节点过滤时，右侧列表同时展示该节点下的已发布和已停用题目 |
| 编辑仅限已停用 | 编辑功能仅对 `archived`（已停用）状态题目开放，`published` 状态题目不提供编辑入口 |
| 编辑不改变状态 | 「保存」操作仅更新题目内容字段，`status` 保持 `archived` 不变 |
| 保存并启用校验权重 | 「保存并启用」操作须校验五力权重合计等于10分，不满足则拒绝并提示 |
| 保存并启用同步向量 | 「保存并启用」成功后同步触发 ChromaDB 向量 `is_active=true`，题目重新参与训练推荐 |
| 批量由后端处理 | 批量启用 / 停用一次请求提交全部勾选 ID，**不循环调用**单题接口；资格校验与状态变更均在后端完成 |
| 批量数量限制 | 单次 1 ~ 200 条，重复 ID 由后端去重 |
| 批量部分成功 | 逐条独立处理，单题跳过或失败不影响其他题目；返回逐条结果 |
| 批量幂等 | 已处于目标状态的题目返回 `skipped`（`STATE_UNCHANGED`），不视为失败，不写变更 |
| 批量同步向量 | 与单题一致：启用 / 停用后 ChromaDB 对应向量批量标记 `is_active` |
| 批量审计 | 每次批量调用写 1 条汇总审计日志，不逐题写多条 |

### 11.1 功能点列表

| 功能点 | 说明 |
|--------|------|
| 题目列表查看 | 展示全部测试题（已启用 + 已停用）；筛选栏从左到右依次为：搜索题目、状态（已启用 / 已停用，可清空表示全部）；两个条件同时生效；列表**按创建时间倒序**排列（最新创建的在最前，同一时间按 ID 倒序） |
| 状态模型 | 只有两个状态：已启用（`published`）、已停用（`archived`），**无草稿**；新建题目默认已停用 |
| 列表列顺序 | 复选框、展开、序号、题目、状态、参考时间、操作；「状态」列位于「题目」列右侧 |
| 状态列样式 | 参考训练题管理「状态」列：「已启用」为绿色圆环对勾图标 + 文字，「已停用」为红色圆环叉图标 + 文字，文字颜色与图标一致 |

| 批量停用 | 勾选多条题目，一键批量停用；仅「已启用」题目参与，已停用的由后端跳过。停用后已启用不足 10 道时测试功能暂停并提示。**由后端批量接口一次性处理**（接口设计说明书 §9.3.7） |
| 新增题目 | 创建题目，填写参考时间、题目描述、题目、答案及五力权重；「保存题目」保存为已停用，「保存并启用」一步创建并启用 |
| 删除题目 | 仅已停用题目可软删除；已启用题目不可直接删除，需先停用 |
| 编辑题目 | 仅已停用题目可编辑题目描述、题目、答案列表、各答案五力权重、参考时间等全部字段；已启用题目需先停用 |
| 启用题目 | 将已停用题目启用并加入测试池；已启用题目数不超过 20 道，已启用 ≥ 10 道时测试功能开放 |
| 停用题目 | 将已启用题目停用，停止参与新测试；已启用不足 10 道时测试功能自动暂停 |
| 状态看板 | 顶部常驻已启用题目计数（N/20），直观展示测试功能是否可用 |

### 11.2 题目状态流转

```
        新增（保存题目）
              │
              ▼
    ┌──▶ [archived 已停用] ──编辑──▶ [archived 已停用]
    │         │
    │         │ 启用（保存并启用 / 列表启用 / 批量启用）
    │         ▼
    └──── [published 已启用]
     停用（列表停用 / 批量停用）
```

| 状态 | 含义 | 可执行操作 |
|------|------|-----------|
| `published`（已启用） | 参与学生测试组卷；已启用总数 ≥ 10 时测试功能开放，上限 20 道 | 停用 |
| `archived`（已停用） | 不参与新测试；新建题目的初始状态；可编辑修改内容，满足条件后启用 | **编辑、启用、删除** |

> **历史成绩保护机制：** 每次测试会话创建时，系统会对当前已启用题目的内容（题干、答案、权重）生成不可变快照，存储在 `test_sessions.config_snapshot` 中。此后对题目的任何修改（包括停用编辑后启用）**均不影响已完成的历史测试会话及其评分结果**，历史成绩永远基于测试时的快照版本计算。
>
> **约束：** 同一时刻已启用题目数 **至少需要10道**，测试功能才对学生开放。不足10道时，小程序端发起测试将返回 `TEST-005` 错误。

**批量启用 / 停用交互流程：**

```
勾选题目 → 点击「批量启用」或「批量停用」
  ├─ 未勾选任何题目            → 提示「请先勾选需要启用/停用的题目」，不发请求
  ├─ 勾选超过 200 条           → 提示「单次最多启用/停用 200 道题目，当前已勾选 N 道，请减少勾选后重试」，不发请求
  ├─ 勾选项中无可处理题目      → 提示原因，不发请求
  │     启用：无「已停用」题目 → 「所选题目中不包含已停用的题目，仅已停用题目可以启用」
  │     停用：无「已启用」题目 → 「所选题目中不包含已启用的题目，仅已启用题目可以停用」
  ├─ 批量启用且已启用数已达 20 → 提示「已启用题目已达上限（20/20），请先停用部分题目」，不发请求
  └─ 存在可处理题目            → 弹窗确认
                                    文案含：可处理 X 道，将跳过 Y 道
                                    启用时可处理数 > 剩余名额 → 追加「剩余名额 N 个，将按勾选顺序启用前 N 道」
                                    └─ 确认 → 一次调用批量接口 → 结果提示：
                                         全部成功                  → 成功提示「已启用/停用 N 道题目」
                                         存在 skipped / failed     → 警告提示，分别列出跳过数与失败数
                                         返回 test_available=false → 追加「已启用不足 10 道，测试功能已暂停」
                                       → 清空勾选，刷新列表与顶部看板计数
```

| 校验项 | 前端规则（仅交互优化） |
|--------|------------------------|
| 可处理判定 | 批量启用：行 `status === 'archived'`；批量停用：行 `status === 'published'` |
| 数量上限 | 勾选总数 ≤ 200（与后端 `CBATCH-002` 一致） |
| 启用名额 | 批量启用前依据顶部已启用计数估算剩余名额（20 − 已启用数），仅用于提示，**最终以后端为准** |
| 最终校验 | 以后端为准；前端数据可能过期，后端返回的 `skipped` / `failed` 统一在结果提示中体现 |
| 按钮状态 | 请求进行中对应按钮显示 loading，防止重复提交 |

### 11.4 约束条件

| 约束项 | 规则 |
|--------|------|
| 测试触发条件 | 已启用题目数 = 20 道时，学生测试功能开启；不足20道时自动暂停并提示 |
| 启用上限 | 已启用题目数 < 20 时方可启用；已达20道时拒绝启用，提示需先停用旧题 |
| 答案数量 | 每题最少 2 个答案，最多 8 个答案 |
| 选项编号 | 选项字母（A/B/C/D…）按添加顺序自动生成，删除后重新排序 |
| 权重规则 | 每个答案的五力权重向量之和必须 ≈ 1.0（允许 ±0.01 浮点误差） |
| 题目描述 | 管理员用元数据，记录该题测量意图，**不展示给学生**，建议填写但非必填 |
| 编辑生效范围 | 对 `archived` 题目的修改，启用后均只影响修改后**新创建**的测试会话；历史会话基于创建时的内容快照计算，永不受影响 |
| 停用后可编辑 | `archived` 状态题目支持编辑（修改题干、答案内容、五力权重、参考时间、题目描述）；编辑后可直接启用 |
| 启用不影响历史 | `archived` 题目编辑后启用，历史测试成绩依然基于该题当时被引用时的快照版本，成绩不变 |
| 删除规则 | 仅 `archived`（已停用）状态题目可软删除（`deleted_at` 标记，数据保留可追溯）；`published`（已启用）题目不可删除，需先停用 |
| 修改留痕 | 所有新增、编辑、状态变更操作均写入 `admin_audit_logs`，含变更前后字段快照 |
| 启用条件 | `archived` 题目启用需满足当前已启用数 < 20 的条件 |
| 批量由后端处理 | 批量启用 / 停用一次请求提交全部勾选 ID，**不循环调用**单题接口；资格校验与状态变更均在后端完成 |
| 批量数量限制 | 单次 1 ~ 200 条，重复 ID 由后端去重 |
| 批量参与范围 | 批量启用仅 `archived` 参与，批量停用仅 `published` 参与；仅这两个状态，无草稿 |
| 批量启用上限 | 批量启用同样受 20 道启用上限约束；名额按勾选顺序分配，用尽后其余题目跳过（`PUBLISH_LIMIT_REACHED`），不整体失败 |
| 批量部分成功 | 逐条独立处理，单题跳过或失败不影响其他题目；返回逐条结果 |
| 批量幂等 | 已处于目标状态的题目返回 `skipped`（`STATE_UNCHANGED`），不视为失败 |
| 批量审计 | 每次批量调用写 1 条汇总审计日志，不逐题写多条 |

### 12.5 约束条件

| 约束项 | 规则 |

### 15.2 用户角色与账号体系

#### 15.2.1 三类用户说明

| 角色 | 存储位置 | 登录方式 | 使用端 | 后台权限说明 |
|------|---------|---------|--------|-------------|
| 学生（STUDENT） | `students` 表，`user_type='STUDENT'` | 微信OAuth + 手机绑定 | 小程序 | — |
| 家长（PARENT） | `students` 表，`user_type='PARENT'` | 微信OAuth + 手机绑定 | 小程序 | — |
| 超级管理员（SUPER_ADMIN） | `admin_users` 表，`role='SUPER_ADMIN'` | 用户名/密码 + 2FA | 后台管理系统 | 全部功能 + 管理员账号管理（创建/停用/重置/删除）|
| 普通管理员（ADMIN） | `admin_users` 表，`role='ADMIN'` | 用户名/密码 + 2FA | 后台管理系统 | 除「管理员账号」Tab 外的全部功能；可重置学生/家长密码 |

**内置超级管理员：** 账号 `admin`，系统唯一，不可删除，不可自我停用。

#### 15.2.2 家长-学生绑定方式

家长与学生之间的绑定是系统核心关联关系，支持三种绑定途径：

| 方式 | 发起方 | 流程描述 | bind_method 值 |
|------|--------|---------|----------------|
| **学生邀请家长** | 学生 | 学生在小程序生成8位邀请码 → 家长在小程序输入邀请码 → 绑定立即生效 | `INVITE_CODE` |
| **家长主动绑定** | 家长 | 家长在小程序输入学生手机号 → 系统向学生手机发送确认短信 → 学生确认后绑定生效 | `PARENT_SELF` |
| **管理员后台绑定** | 管理员 | 管理员在后台搜索学生 → 输入家长手机号（不存在则自动创建家长账号）→ 立即绑定 | `ADMIN` |

**绑定约束：**
- 学生侧绑定家长数**无上限限制**
- 每位家长最多绑定 **5 位学生**
- 管理员后台绑定时若家长手机号未注册，系统自动创建家长账号（`is_confirmed=false`，待家长首次登录激活）

### 15.4 学生画像设计

#### 15.4.1 设计思路

用户画像面向管理员，目标是让管理员在最短时间内全面了解一名学生的**认知能力现状、学习行为模式、AI 辅导效果**，从而支撑运营决策（如：题库内容优化、AI 策略调整、异常学生关怀）。画像分为六大维度：

| 画像维度 | 核心问题 | 数据来源 |
|----------|----------|----------|
| **基础信息** | 这个学生是谁？绑定了哪些家长？ | `students`、`parent_student_bindings` |
| **五力认知画像** | 认知能力现状如何？哪里最弱最强？ | `five_power_profiles`、`five_power_training_profiles` |
| **学习行为画像** | 有多勤奋？训练习惯如何？ | `training_sessions`、`training_answer_records` |
| **AI 助教互动画像** | 和 AI 的交互质量如何？是否产生了理解突破？ | `ai_chat_sessions`、`ai_strategy_events` |
| **错题薄弱画像** | 反复在哪里出错？哪些知识点是盲区？ | `wrong_answer_records` |
| **成长轨迹** | 是否在进步？五力成长趋势如何？ | `five_power_profiles`（历史多条） |

#### 15.4.2 画像包含信息详细说明

**一、基础信息**

| 信息项 | 说明 |
|--------|------|
| 学生昵称 / ID | 唯一标识 |
| 年级 | G7~G12 |
| 学科偏好 | 数学 / 物理 / 化学（多选）|
| 是否未成年 | 影响内容安全策略 |
| 注册时间 | 用户生命周期起点 |
| 最后活跃时间 | 判断是否流失 |
| 绑定家长 | 已绑定家长列表（0~2位），含绑定方式和绑定时间 |
| 累计登录天数 | 学习粘性基础指标 |

**二、五力认知画像**

| 信息项 | 说明 |
|--------|------|
| 五力雷达图（当前） | 洞察/建构/推演/调适/迁移五维综合分（测试×40% + 训练×60%）|
| 各维度能力分（ability_score） | 来自五力测试，反映真实能力 |
| 各维度认知入口分（preference_score） | 习惯从哪个维度进入新知识，指导教学路径 |
| 当前最弱力 | primary_weakness，训练主要目标 |
| 当前优势入口力 | preferred_force，借强补弱的切入点 |
| 推荐训练模式 | TRAIN_WEAKNESS / LEARN_BY_STRENGTH |
| AI 个性化分析摘要 | 测试后 AI 生成的 150 字学情描述 |
| 测试次数 / 最近测试时间 | 了解测试参与情况 |

**三、学习行为画像**

| 信息项 | 说明 |
|--------|------|
| 累计训练会话数 | 整体学习投入程度 |
| 累计答题数 | 练习总量 |
| 整体答题正确率 | 综合掌握水平 |
| 各五力维度训练正确率 | 哪个维度练得最好/最差 |
| 最近 7 天训练天数 | 近期活跃度 |
| 平均单次训练时长（分钟）| 专注力指标 |
| 训练完成率 | 正常完成 vs 提前结束 vs 放弃 占比 |
| 最常训练的知识点 Top 3 | 学习偏好与薄弱集中点 |

**四、AI 助教互动画像**

| 信息项 | 说明 |
|--------|------|
| 累计对话会话数 | AI 使用深度 |
| 累计对话轮次 | 学习深度指标 |
| 理解突破（aha）次数 | 核心效果指标——AI 是否真正帮助了学生 |
| 突破率（aha/总会话） | AI 教学有效性 |
| 最常使用的会话模式 | 自由提问 / 错题复盘 / 训练介入 |
| 最有效启发策略 Top 3 | 该生对哪种策略最容易产生突破 |
| 沉默模式触发次数 | 学生主动拒绝 AI 介入的频次 |

**五、错题薄弱画像**

| 信息项 | 说明 |
|--------|------|
| 累计错题数 | 总难点量 |
| 错题按五力维度分布 | 哪个维度出错最多 |
| 错题复盘率 | 错题中已复盘的比例 |
| 错题突破率 | 已复盘错题中达到 aha_achieved 的比例 |
| 未复盘错题数 | 待处理的学习盲点数量 |
| 高频错题知识点 Top 5 | 精准定位盲区 |

**六、成长轨迹**

### 15.8 AI助教提示词摘要

#### 15.8.1 设计思路

提示词摘要是一份动态维护的学生画像文本，专门用于注入大模型的系统提示词（System Prompt），使 AI 助教能以更贴近该学生的方式进行辅导互动。摘要分为两大模块：

| 模块 | 内容 | 来源 |
|------|------|------|
| **学习信息摘要** | 年级学期、五力画像、核心薄弱点、高频错题知识点、近期训练错误率 | 系统自动生成，定期刷新 |
| **个人洞察摘要** | 学生近期状态、心情、兴趣爱好、重要生活事件、与AI聊天中透露的关键个人信息 | AI从对话中提取，管理员可手动补充/修正 |

**更新机制：**
- **学习信息摘要**：训练会话结束后、五力测试完成后，由系统异步重新生成（基于 `student_kp_stats`、`five_power_profiles` 等结构化数据）
- **个人洞察摘要**：AI助教在每次对话会话结束时，从 `session_summary` 中提取关键个人信息，追加或更新到摘要中；管理员可在后台手动编辑

#### 15.8.3 个人洞察提取规则

AI助教在每次对话会话结束后，对 `session_summary` 进行二次分析，提取以下类型的关键信息：

| 信息类型 | 提取示例 | 触发场景 |
|---------|---------|---------|
| 兴趣爱好 | "喜欢打篮球、湖人球迷" | 自由对话中学生主动提及 |
| 近期心情/状态 | "期中考试压力大，感到焦虑" | 学生表达情绪时 |
| 重要生活事件 | "下周有体育考试" | 学生描述近期安排 |
| 有效类比偏好 | "游戏RPG类比效果好" | AI使用某类比后出现aha时刻 |
| 家庭背景线索 | "爸爸比较严格" | 学生在对话中透露 |
| 学习心态 | "对数学有畏难情绪" | AI策略分析时识别 |

**提取原则：**
- 仅提取学生主动表达的信息，不推断或臆测
- 涉及隐私的内容（家庭纠纷、心理问题等）标记为「敏感」，仅管理员可见，不注入Prompt
- 信息有时效性：超过30天未更新的条目自动降权，超过90天自动归档
