## 2. 数据库规范

### 2.1 命名规范

| 规则 | 格式 | 示例 |
|------|------|------|
| 表名 | 小写蛇形，复数 | `training_sessions` |
| 字段名 | 小写蛇形 | `student_id`, `created_at` |
| 主键 | `id`（BIGSERIAL）或 `id`（UUID）| — |
| 外键 | `{关联表单数}_{id}` | `student_id`, `session_id` |
| 布尔字段 | `is_` 前缀 | `is_active`, `is_latest` |
| 时间字段 | `_at` 后缀 | `created_at`, `deleted_at` |
| 索引 | `idx_{表名}_{字段名}` | `idx_students_openid` |
| 唯一索引 | `uniq_{表名}_{字段名}` | `uniq_students_phone_hash` |

### 2.2 全局字段约定

**所有业务表必须包含：**

```sql
created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()  -- 创建时间
updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()  -- 最后更新时间
```

**软删除表额外包含：**

```sql
deleted_at  TIMESTAMPTZ DEFAULT NULL  -- NULL=未删除，非NULL=已删除时间
```

**软删除查询必须加过滤：**
```sql
WHERE deleted_at IS NULL
```

### 2.3 ID 类型选择策略

| 表类型 | 主键类型 | 说明 |
|--------|---------|------|
| 核心业务表（学生、题目等） | `BIGSERIAL` | 自增整型，查询效率高 |
| 会话类表（训练、对话会话） | `UUID` | 防枚举、支持分布式生成 |
| 日志类表 | `BIGSERIAL` | 高频写入，自增最优 |
| 配置类表 | 业务主键（VARCHAR）| 如 `strategy_id` |

### 2.4 时区规范

所有时间字段统一使用 `TIMESTAMPTZ`（带时区的时间戳），存储 UTC 时间，应用层按用户时区显示。

## 4. 模块一：用户与认证

### 4.1 students（用户账户表）

> **v1.2.0 变更：** 本表从"学生账户表"改为"用户账户表"，统一存储**学生**和**家长**两类小程序用户。新增 `user_type` 字段区分角色，家长账号的学科偏好等学习字段允许为 NULL。

```sql
-- 小程序端用户账户表（统一存储学生与家长两类角色）
CREATE TABLE students (
    id              BIGSERIAL       PRIMARY KEY,
    openid          VARCHAR(64)     NOT NULL,                -- 微信 openid（AES可逆加密后存储）
    openid_hash     VARCHAR(64)     NOT NULL,                -- SHA256 哈希，用于唯一性查询
    phone           VARCHAR(64),                             -- 手机号（AES加密存储）
    phone_hash      VARCHAR(64),                             -- SHA256哈希，用于唯一性查询
    nickname        VARCHAR(50),                             -- 微信昵称
    avatar_url      VARCHAR(512),                            -- 头像URL
    -- v1.2.0 新增：用户类型，区分学生账号与家长账号
    user_type       VARCHAR(10)     NOT NULL DEFAULT 'STUDENT'
                    CHECK (user_type IN ('STUDENT', 'PARENT')),
                                                             -- STUDENT: 学习用户，有五力画像/训练记录
                                                             -- PARENT:  家长用户，通过绑定关系查看子女数据
    -- 以下字段仅学生有效，家长账号允许为 NULL
    grade           VARCHAR(10),                             -- G7/G8/G9/G10/G11/G12（家长为NULL）
    subject_prefs   JSONB           NOT NULL DEFAULT '[]',  -- ["MATH","PHYSICS","CHEMISTRY"]（家长为[]）
    is_minor        BOOLEAN         NOT NULL DEFAULT TRUE,   -- 是否未成年（<18岁），影响内容安全策略
    is_active       BOOLEAN         NOT NULL DEFAULT TRUE,   -- 账号是否有效
    is_confirmed    BOOLEAN         NOT NULL DEFAULT TRUE,   -- 账号是否已激活（管理员创建的家长账号初始为FALSE）
    last_login_at   TIMESTAMPTZ,                             -- 最后登录时间
    created_at      TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    deleted_at      TIMESTAMPTZ     DEFAULT NULL             -- 软删除，注销30天后物理删除AI记录
);

-- 索引
CREATE UNIQUE INDEX uniq_students_openid_hash   ON students(openid_hash);
CREATE UNIQUE INDEX uniq_students_phone_hash    ON students(phone_hash) WHERE phone_hash IS NOT NULL;
CREATE INDEX        idx_students_created_at     ON students(created_at DESC);
CREATE INDEX        idx_students_user_type      ON students(user_type, is_active);  -- 按角色分类查询
```

**业务说明：**
- `openid` 和 `phone` 均加密存储，查询使用 hash 字段
- `user_type = 'STUDENT'`：完整的学习用户，拥有五力测试、训练、AI对话等所有功能
- `user_type = 'PARENT'`：家长用户，无学习功能，仅通过 `parent_student_bindings` 查看绑定子女的学习数据
- `is_confirmed = FALSE`：管理员后台绑定时若家长账号不存在则自动创建，初始为待激活状态，家长首次登录小程序后自动置为 TRUE
- 软删除后 30 天内：前台不可用，数据保留；30 天后物理删除 `ai_chat_messages`

### 4.2 admin_users（管理员账户表）

```sql
CREATE TABLE admin_users (
    id                  BIGSERIAL       PRIMARY KEY,
    username            VARCHAR(50)     NOT NULL,            -- 仅字母、数字、下划线
    password_hash       VARCHAR(255)    NOT NULL,            -- bcrypt哈希，cost=12
    display_name        VARCHAR(50)     NOT NULL,
    email               VARCHAR(100)    NOT NULL,
    phone               VARCHAR(64)     NOT NULL,            -- 加密存储，2FA验证用
    role                VARCHAR(20)     NOT NULL DEFAULT 'SUPER_ADMIN',
    is_active           SMALLINT        NOT NULL DEFAULT 2,  -- 0=禁用 1=启用 2=待首次登录
    login_fail_count    SMALLINT        NOT NULL DEFAULT 0,  -- 连续失败次数
    locked_until        TIMESTAMPTZ,                         -- 锁定截止时间
    password_changed_at TIMESTAMPTZ,                         -- 密码最后修改时间
    last_login_at       TIMESTAMPTZ,
    last_login_ip       VARCHAR(50),
    created_by          BIGINT          REFERENCES admin_users(id),
    created_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);

CREATE UNIQUE INDEX uniq_admin_users_username   ON admin_users(username);
CREATE UNIQUE INDEX uniq_admin_users_email      ON admin_users(email);
```

**业务说明：**
- 密码连续错误 5 次，锁定 30 分钟
- 密码默认 90 天过期（可通过 `system_configs` 配置）
- `is_active=2` 首次登录前必须修改密码

### 4.3 sms_codes（短信验证码表）

```sql
CREATE TABLE sms_codes (
    id          BIGSERIAL       PRIMARY KEY,
    phone_hash  VARCHAR(64)     NOT NULL,                    -- 手机号 SHA256 哈希
    code        VARCHAR(6)      NOT NULL,                    -- 6位数字验证码
    purpose     VARCHAR(20)     NOT NULL,                    -- REGISTER/LOGIN/TWO_FA/BIND_PHONE
    expires_at  TIMESTAMPTZ     NOT NULL,                    -- 有效期5分钟
    is_used     BOOLEAN         NOT NULL DEFAULT FALSE,
    fail_count  SMALLINT        NOT NULL DEFAULT 0,          -- 校验失败次数，>5则此码作废
    created_at  TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_sms_codes_phone_hash   ON sms_codes(phone_hash, created_at DESC);
CREATE INDEX idx_sms_codes_expires_at   ON sms_codes(expires_at);  -- 定时清理过期记录用
```

**业务说明：**
- 同一手机号同一用途，每 60 秒仅允许发送 1 次
- 每日最多发送 10 次（合并所有用途）
- 校验失败超 5 次，该验证码立即作废，需重新发送

### 4.5 parent_student_bindings（家长-学生绑定表）

> **v1.2.0 变更：** `bind_method` 新增 `PARENT_SELF` 值（家长主动发起绑定）；新增 `bind_status` 字段支持绑定申请的待确认状态（PARENT_SELF 方式需学生确认）。

```sql
CREATE TABLE parent_student_bindings (
    id              BIGSERIAL       PRIMARY KEY,
    student_id      BIGINT          NOT NULL REFERENCES students(id),
    parent_id       BIGINT          NOT NULL REFERENCES students(id), -- 家长账号（user_type='PARENT'）
    bind_method     VARCHAR(20)     NOT NULL
                    CHECK (bind_method IN ('INVITE_CODE', 'PARENT_SELF', 'ADMIN')),
                                                             -- INVITE_CODE:  学生生成邀请码，家长使用后立即绑定
                                                             -- PARENT_SELF:  家长主动输入学生手机号发起，需学生确认
                                                             -- ADMIN:        管理员后台操作，立即绑定
    bind_status     VARCHAR(20)     NOT NULL DEFAULT 'active'
                    CHECK (bind_status IN ('pending', 'active', 'rejected')),
                                                             -- pending:  待学生确认（仅 PARENT_SELF 方式使用）
                                                             -- active:   绑定生效
                                                             -- rejected: 学生拒绝（仅 PARENT_SELF 方式使用）
    is_active       BOOLEAN         NOT NULL DEFAULT TRUE,   -- FALSE 表示已解绑（软删除替代）
    created_by_admin_id BIGINT      REFERENCES admin_users(id), -- 管理员操作时记录操作人（ADMIN方式）
    confirmed_at    TIMESTAMPTZ,                             -- 绑定生效时间（PARENT_SELF 方式为学生确认时间）
    expires_at      TIMESTAMPTZ,                             -- 绑定请求过期时间（PARENT_SELF pending状态有效期24h）
    created_at      TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    deleted_at      TIMESTAMPTZ     DEFAULT NULL             -- 软删除（解绑不物理删除）
);

CREATE UNIQUE INDEX uniq_parent_student ON parent_student_bindings(student_id, parent_id)
    WHERE deleted_at IS NULL;
CREATE INDEX idx_parent_bindings_student ON parent_student_bindings(student_id) WHERE deleted_at IS NULL;
CREATE INDEX idx_parent_bindings_parent  ON parent_student_bindings(parent_id)  WHERE deleted_at IS NULL;
```

**业务说明：**
- 每个学生最多绑定 2 个家长（应用层控制）
- 每个家长最多关联 5 个学生（应用层控制）
- 解绑操作为软删除，保留历史

## 5. 模块二：知识点与题库

### 5.0 题库存储架构说明

#### 5.0.1 两类题目，两种存储策略

项目中存在性质不同的两类题目，存储方式有所差异：

| 类型 | 数量 | 查询特征 | 主存储 | 向量存储 |
|------|------|----------|--------|---------|
| **五力认知测试题** | 固定 20 道 | 按题号精确查找，固定顺序展示 | PostgreSQL | ❌ 不需要 |
| **训练题库** | V1.0 约 1280 道，持续增长 | 按知识点+五力+难度精确过滤选题 | PostgreSQL（主存储）| ✅ ChromaDB（RAG 语义索引）|

**设计原则：PostgreSQL 是唯一的 Source of Truth，ChromaDB 是可随时重建的派生索引。**

#### 5.0.2 PostgreSQL 负责所有结构化存储

训练题库的**选题算法**是多字段精确过滤，不是语义相似度检索。PostgreSQL 加复合索引完全胜任：

```sql
-- 选题算法核心查询，完全不需要向量数据库
SELECT id FROM questions
WHERE knowledge_point_id = ?       -- 精确匹配知识点
  AND primary_power = 'STRUCTURE'  -- 精确匹配训练五力
  AND difficulty = 'basic'         -- 精确匹配难度
  AND status = 'published'
  AND deleted_at IS NULL
  AND id NOT IN (...)              -- 近期去重窗口
ORDER BY RANDOM() LIMIT 2;

-- 覆盖以上查询的复合索引（已在 questions 表定义）
CREATE INDEX idx_questions_selection
    ON questions(knowledge_point_id, primary_power, difficulty, status)
    WHERE status = 'published' AND deleted_at IS NULL;
```

#### 5.0.3 ChromaDB 仅服务于 RAG 语义检索

ChromaDB 只在**一个场景**下被调用：学生答错题目后，RAG 生成解题思路时的语义召回。

```
两个 ChromaDB Collection：
  mesh_question_solutions   —— 题目+解析+训练点的语义向量（1280 个向量）
  mesh_five_power_strategies —— 五力解题方法论文档的语义向量（20~30 个向量）

向量化触发时机：
  管理员将题目状态 draft → published 时
  → API 层推送 Celery 异步任务（Queue-A）
  → Embedding API 生成 1536 维向量
  → 写入 ChromaDB，同时回写 embedding_status = 'completed' 到 PostgreSQL

数据规模（V1.0）：
  1280 道题 × 6KB/向量 = ~7.5MB + 策略文档 ~180KB ≈ 总计 8MB
  ChromaDB 单节点完全胜任，无需 Milvus
```

#### 5.0.4 向量数据库的分阶段介入

```
Sprint 1~2（开发调试阶段）
  题库：30 道种子题存 PostgreSQL
  ChromaDB：不启动
  RAG：展示 questions.solution 静态内容
  目标：跑通选题→答题→判题→训练小结主流程

Sprint 3（RAG 正式介入）
  ChromaDB 容器启动
  题目发布自动触发向量化（Celery Queue-A）
  五力策略文档预置向量化（初始化脚本）
  RAG 双路召回正式生效

Sprint 4+（正式题库建设）
  1280 道正式题陆续发布，自动入库 ChromaDB
  embedding_status 字段追踪向量化状态
```

#### 5.0.5 两库协作数据流

```
学生答错题目 X
  │
  ├── 【ChromaDB】语义召回
  │    路径1：以题目X题干为query，召回相似题解析（过滤薄弱五力）
  │    路径2：以"弱力名称+解题策略"为query，召回方法论文档
  │
  ├── 【PostgreSQL】精确查询
  │    题目X完整内容（stem/solution/common_error）
  │    学生最新五力画像（five_power_profiles）
  │
  └── 组装 Prompt → 调用 LLM → 生成解题思路
       结果写回 training_answer_records.rag_content
```

### 5.6 question_analyses（题目大模型分析记录表）

> **v1.2.0 重构：** 原 `question_annotations`（AI标注）表已重命名并重构为 `question_analyses`。字段从"主五力标注+置信度"扩展为"完整分析结果"（含知识点、难度、五力解题思路、训练权重、迁移方向、驳回上下文等）。每次触发分析（含驳回重分析）均生成新记录，完整保留分析历史。

```sql
-- 大模型分析记录表（每次分析调用产生一条记录，含驳回重分析的历史）
CREATE TABLE question_analyses (
    id                      BIGSERIAL       PRIMARY KEY,
    question_id             BIGINT          NOT NULL REFERENCES questions(id),
    round                   SMALLINT        NOT NULL,            -- 分析轮次（第1次=1，驳回后重分析=2...）
    -- 本次分析的输入上下文
    stem_snapshot           TEXT            NOT NULL,            -- 本次提交的题干内容
    rejection_reason_used   TEXT,                                -- 驳回意见（首次分析为NULL）
    -- 大模型输出结果
    -- AI 识别的归属体系（对应 questions 表的 subject_id/grade_id/chapter_id）
    ai_subject_id           INT             REFERENCES subjects(id),     -- AI识别的所属科目
    ai_grade_id             INT             REFERENCES grades(id),       -- AI识别的所属年级
    ai_chapter_id           BIGINT          REFERENCES chapters(id),     -- AI识别的所属章节
    ai_knowledge_point_ids  JSONB           NOT NULL DEFAULT '[]', -- AI建议知识点ID列表
    ai_difficulty           VARCHAR(20),                         -- basic/advanced/challenge
    ai_solution             TEXT,                                -- AI生成的参考解析
    ai_common_error         TEXT,                                -- AI识别的典型错误
    -- 各维度训练思路（同 questions.power_solutions 格式）
    ai_power_solutions      JSONB,
    -- 五力训练权重（同 questions.five_power_weights 格式，总计10分）
    ai_five_power_weights   JSONB,
    -- 迁移方向建议
    ai_transfer_directions  JSONB           NOT NULL DEFAULT '[]',
    -- 大模型分析理由/推理过程（内部使用）
    ai_reasoning            TEXT,
    -- 分析任务状态
    analysis_status         VARCHAR(20)     NOT NULL DEFAULT 'pending'
                            CHECK (analysis_status IN ('pending', 'completed', 'failed')),
    fail_reason             TEXT,                                -- 失败原因（超时/模型错误等）
    model_version           VARCHAR(50),                         -- 调用的大模型版本/名称
    created_at              TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    updated_at              TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    UNIQUE (question_id, round)                                  -- 每题每轮次唯一
);

CREATE INDEX idx_analyses_question ON question_analyses(question_id, round DESC);
CREATE INDEX idx_analyses_status   ON question_analyses(analysis_status);
```

**字段约束说明：**

| 字段 | 约束 |
|------|------|
| `round` | 与 `question_id` 联合唯一；`questions.analysis_round` 字段与此同步 |
| `ai_five_power_weights` | 大模型返回时校验：各维度整数值之和必须等于10 |
| `rejection_reason_used` | 首次分析（round=1）为 NULL；驳回重分析（round≥2）必填 |
| `analysis_status` | 大模型调用完成（成功/失败）后更新；`pending` 超时（30s）后标记为 `failed` |

### 6.1 cognitive_test_questions（五力认知测试题目表）

> **v1.2.0 变更：**

> - 去除"固定20道"硬约束，改为业务层保证：已发布题目恰好等于20道时测试功能生效

>
> **v1.3.0 变更：**
> - 移除 `target_power`（目标维度）字段，题目不再预先绑定某一五力维度

> - 移除 `option_scores`（简单得分）字段，所有题型统一改用五力权重向量

> - 题目类型枚举由 `STANDARD/OPEN` 改为 `OBJECTIVE`（客观题）/`PREFERENCE`（偏好题）
> - 新增 `answers` JSONB 字段，存储全部答案（包含 key、text、force_weights）
> - `correct_option` 改为非必填（仅客观题填写，偏好题为 NULL）
>
> **v1.4.0 变更：**
> - 移除 `question_type` 字段（五力测试题所有答案均无唯一正确选项，无需区分题型）
> - 移除 `correct_option` 字段（无唯一答案，无最优答案标记）

> - 删除 `idx_cogq_type_status` 索引（随 question_type 字段一并废弃）

```sql
-- 五力认知测试题目表（支持全生命周期管理：草稿→发布→下架）
-- 测试功能激活条件：status='published' 的记录恰好等于20条
-- 所有题目统一使用五力权重向量评分，无题型区分，无唯一正确答案
CREATE TABLE cognitive_test_questions (
    id                  SERIAL          PRIMARY KEY,
    question_no         SERIAL,                              -- 题目序号（自增，创建时分配，不可变）
    display_order       SMALLINT        NOT NULL,            -- 前台展示顺序（已发布题目按此排序组卷）
    description         TEXT,                                -- 题目描述（管理员元数据，不展示给学生，可空）
                                                             -- 用于记录该题的测量意图，便于内容管理
    stem                TEXT            NOT NULL,            -- 题干（展示给学生，支持 Markdown + LaTeX）
    image_url           VARCHAR(512),                        -- 题目图片 OSS 链接（可空）
    -- 答案配置：统一存储所有答案的内容与五力权重
    -- 格式：[{"key":"A","text":"...","force_weights":{"INSIGHT":0.7,"STRUCTURE":0.1,...}},...]
    -- key 由后端按答案顺序自动生成（A/B/C/D…），前端提交时不传 key
    -- 每条答案的 force_weights 五力权重之和需满足 0.99 ≤ sum ≤ 1.01
    -- 答案数量：最少 2 条，最多 8 条
    answers             JSONB           NOT NULL,
    reference_time_sec  SMALLINT        NOT NULL DEFAULT 90, -- 参考作答时间（秒），超时标记 is_timeout
    -- 题目生命周期状态
    status              VARCHAR(20)     NOT NULL DEFAULT 'draft'
                        CHECK (status IN ('draft', 'published', 'archived')),
                                                             -- draft:     草稿（不参与测试）
                                                             -- published: 已发布（参与组卷，需恰好20道）
                                                             -- archived:  已下架（保留历史引用，不参与新测试）
    created_by          INT             REFERENCES admin_users(id), -- 创建者（管理员）
    updated_by          INT             REFERENCES admin_users(id), -- 最后修改者
    created_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ     NOT NULL DEFAULT NOW()
);

-- 测试组卷查询索引：按状态 + 展示顺序取已发布题目
CREATE INDEX idx_cogq_status_order ON cognitive_test_questions(status, display_order)
    WHERE status = 'published';
```

**字段约束说明：**

| 字段 | 约束 |
|------|------|
| `description` | 选填，管理员内部使用，不影响评分逻辑 |
| `answers` | 数组长度必须在 2~8 之间；每条答案的 force_weights 五力权重之和需满足 `0.99 ≤ sum ≤ 1.01` |
| `status` | 状态转换规则：`draft → published`，`published → archived`，`archived → published`，禁止直接 `draft → archived` |
| `display_order` | 已发布题目按 `display_order ASC` 排序，取前20条组卷（有效保护历史数据） |

**业务层约束（由应用程序强制，非数据库约束）：**
- 发布接口（`PATCH /status` → `published`）：需确认当前已发布数 < 20，否则拒绝
- 测试会话创建接口：需确认当前已发布数 = 20，否则返回 `TEST-005` 错误
- 已引用题目（`test_answer_records.question_id`）不可物理删除，只能下架

```sql
-- 辅助视图：查看当前已发布题目数及测试可用状态（便于运维查询）
CREATE VIEW v_cognitive_test_status AS
SELECT
    COUNT(*) FILTER (WHERE status = 'published')  AS published_count,
    COUNT(*) FILTER (WHERE status = 'draft')      AS draft_count,
    COUNT(*) FILTER (WHERE status = 'archived')   AS archived_count,
    COUNT(*) FILTER (WHERE status = 'published') = 20 AS test_available
FROM cognitive_test_questions;
```

```sql
CREATE TYPE force_type AS ENUM (

CREATE TYPE force_level AS ENUM (

    'medium',   -- 🟡 需改进（50 ≤ ability < 65）
    'good',     -- 🟢 良好（65 ≤ ability < 80）
    'strong'    -- 💚 优势（ability ≥ 80）
);

-- 学习模式枚举
CREATE TYPE training_mode AS ENUM (
    'TRAIN_WEAKNESS',       -- 补足模式：有薄弱力需要强化
    'LEARN_BY_STRENGTH'     -- 一通百通模式：从优势力入口学新知识

CREATE TYPE wrong_review_status AS ENUM (
```

```sql
    CHECK (profile_confidence IS NULL OR profile_confidence BETWEEN 0 AND 1);
```

### 13.2 业务限制规则汇总

| 规则 | 实现层 | 描述 |
|------|--------|------|
| preference 5力总和=100 | 应用层 | 评分算法归一化后保证 |
| 每生最多2个家长 | 应用层 | 绑定时检查 parent_student_bindings 数量 |
| 每家长最多5个学生 | 应用层 | 绑定时检查 |
| 同一学生最多1个 active 对话会话 | 应用层 | 新建前关闭旧会话 |
| 同一学生最多1个 active 训练会话 | 应用层 | 新建前检查 |
| 同一学生 is_latest=TRUE 最多1条 | 应用层 | 更新时先将旧记录设为 FALSE |
| 训练配置同时只有1个生效版本 | 应用层 | 设置 is_active 时其他全设 FALSE |
| 邀请码生成时旧码自动作废 | 应用层 | 新建时 UPDATE 旧码 is_used=TRUE |
| 单会话最大对话轮数30轮 | 应用层 | 超出返回 ASST-001 错误 |
| AI主动介入单会话最多3次 | 应用层 | proactive_count ≥ 3 时不再主动 |
| 短信每60秒仅1次 | 应用层+Redis | Redis 计数器实现 |
| 短信每日最多10次 | 应用层+Redis | Redis 日计数器 |
| 密码连续错误5次锁定30分钟 | 应用层 | login_fail_count + locked_until |

### 13.3 软删除策略

| 表名 | 软删除字段 | 物理清除时机 |
|------|-----------|------------|
| `students` | `deleted_at` | 账号注销30天后，物理删除AI对话记录 |
| `questions` | `deleted_at` | 题目下架后保留，归档不删除 |
| `parent_student_bindings` | `deleted_at` | 解绑时软删除，保留历史 |

**软删除自动更新（PostgreSQL 触发器）：**

```sql
CREATE OR REPLACE FUNCTION update_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 为所有有 updated_at 字段的表添加触发器
CREATE TRIGGER trg_students_updated_at
    BEFORE UPDATE ON students
    FOR EACH ROW EXECUTE FUNCTION update_updated_at();
-- （其余表类似，此处省略）
```
