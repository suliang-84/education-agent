## 1. 一句话定义

**一款面向初中至高中生的数理化 AI 认知训练平台。**

通过「五力认知诊断」建立学生个人能力画像，驱动个性化选题与 AI 全程陪伴式启发教学。最终目标不是让学生做更多题，而是培养其数理化学科的底层认知能力与自主学习内驱力。

---

## 2. 产品的本质问题

从文档全貌来看，这不是一个传统意义上的「做题 App」，它要解决的是：

> **传统刷题工具的天花板**：学生刷了几千道题，同类型的题换个情境还是不会——因为训练的是题型记忆，而不是认知能力本身。

### 2.1 核心假设

> 中学生数理化学习困难的根本原因是**认知能力结构性薄弱**，而非知识点积累不足。

### 2.2 解法路径

| 阶段 | 做什么 | 技术支撑 |
|------|--------|----------|
| **先诊断** | 用五力测试找出每个学生的认知短板 | 五力评分算法 + 雷达图 |
| **再训练** | 针对认知短板进行结构化题型练习 | 双标签选题（知识点 × 五力）|
| **全程陪伴** | AI 像真实家教一样启发引导，不给答案 | RAG + 多轮对话 AI |

### 2.3 五力模型——产品核心差异化

五力是产品区别于通用刷题工具的核心能力维度，驱动产品内所有个性化逻辑：

| 五力维度 | 核心能力描述 | 训练侧重 |
|----------|-------------|----------|
| **洞察力** | 从题目中找关键条件、识别干扰信息、读图表有效信息 | 条件提取、隐含关系识别 |
| **建构力** | 建立变量关系、条件关系、图示关系、数理化模型 | 关系建立、模型建构 |
| **推演力** | 连续推理、步骤补全、下一步判断、证明、运算链 | 逻辑推导、步骤严密性 |
| **调适力** | 错误识别与归因、修改步骤、换方法、接受提示后重试 | 纠错、路径切换 |
| **迁移力** | 同构题、变式题、换条件/表达/情境、识别底层规律 | 跨情境应用、规律迁移 |

### 3.3 核心数据流

```
[学生完成五力测试]
        ↓
[五力画像]（5维度得分 + 薄弱项排序）
        ↓ 写入 five_power_profiles
        ↓
[个性化训练] ←── 双标签检索（知识点 × 五力权重）
        ↓
[学生答题]
        │
        ├── 答对 ──→ 沉默，继续下一题
        │
        └── 答错 ──→ ① RAG 解法层（异步，~1700 Token）
                          ↓ 展示结构化解题思路
                     ② 连续答错≥2次 → 智能助教介入
                          ↓ 苏格拉底式对话（~1850 Token）
        ↓
[训练结束] → 更新 five_power_training_profiles
        ↓
[再次五力测试] → 对比前后雷达图，验证成长
```

## 4. 四大核心模块

### 4.1 模块总览

| 模块 | 用户旅程位置 | 定位 | 主要技术 |
|------|------------|------|----------|
| **五力认知测试** | 入口，首次必经 | 诊断引擎，生成个人能力画像 | 选项权重评分、雷达图渲染、断点续测 |
| **个性化 AI 训练** | Tab 1，日常主场景 | 结构化做题 + RAG 解法指导 | 双标签检索、RAG 双路召回、向量数据库 |
| **智能助教** | Tab 2，全程可召唤 | 对话启发 + 认知突破 | 多轮对话、9种策略自动切换、策略有效性画像 |
| **管理后台** | 运营侧 | 内容与参数自助运营控制台 | AI 自动标注审核、Prompt 热更新、配置驱动 |

### 4.2 模块协作关系

```
┌────────────────────────────────────────────────────┐
│               并行双轨 · 互相调度                    │
│                                                    │
│  学生主动发起           AI感知后发起                 │
│                                                    │
│  ┌──────────────┐    ┌──────────────────────────┐  │
│  │ 个性化 AI 训练 │    │       智能助教             │  │
│  │              │    │                          │  │
│  │ "我要练这个点" │    │  "我有问题想问"            │  │
│  │  结构化做题    │    │  "AI 你来引导我"          │  │
│  │  RAG 解法层  │    │  多维启发对话              │  │
│  │  五力训练画像 │    │  策略自适应               │  │
│  └──────┬───────┘    └─────────────┬────────────┘  │
│         │  答错/困难时              │ 推荐实战时     │
│         └─────────────↔────────────┘               │
└────────────────────────────────────────────────────┘
```

**调度规则：**
- 03（训练）→ 04（助教）：同知识点连续答错 ≥2次，且距上次 RAG 完成 ≥90秒，触发助教悬浮介入
- 04（助教）→ 03（训练）：AI 判断需要实战检验，推荐「微训练」入口（2~3题）

### 4.3 题库架构

题库是产品内容底座，采用四级编码 + 双维度标签：

```
题目标识：[学科]-[年级]-[章节]-[知识点序号]
示例：MATH-G9-CH03-KP007

每道题携带两个维度标签：
├── 知识点标签：所属学科/年级/章节/知识点（位置）
└── 五力标签：主训练五力（INSIGHT/CONSTRUCT/DEDUCE/ADAPT/TRANSFER）
             + 可选辅助五力
```

题库入库流程：
```
人工上传 / 拍照 OCR / Word 批量导入
        ↓
AI 标注智能体（自动打五力标签 + 置信度评分）
        ↓
置信度 ≥0.85 → 批量确认
置信度 0.60~0.85 → 人工逐题审核
置信度 <0.60 → 强制人工填写
        ↓
向量化入库（Embedding → Milvus/Chroma）
        ↓
题目上线，开放训练入口
```

## 5. 两个关键架构决策

### 5.1 决策一：RAG 与对话 AI 的双层架构

这个产品里有两套 AI 调用机制，职责严格分离，禁止越界：

| | RAG 解法层（03模块） | 对话启发层（04模块） |
|--|---------------------|---------------------|
| **触发方式** | 学生答错后自动异步触发 | 学生主动提问 / AI 主动介入 |
| **输出风格** | 直接、结构化解题思路框架 | 苏格拉底式提问引导 |
| **输出长度** | ≤200字 | ≤400字 |
| **Token 预算** | ~1700 Token/次 | ~1850 Token/次 |
| **禁区** | 禁止使用"你觉得…""想想看…"等启发语 | 禁止直接给出解题步骤 |

**两者是递进关系：**
- 第一层（RAG）：解决「怎么做」——给方法框架
- 第二层（对话）：解决「为什么这样做」——引导认知过程

这个分层设计既控制了 Token 成本，又保证了「先给工具，再引导思考」的教学节奏。

### 5.2 决策二：五力画像驱动一切

五力画像是整个产品的核心数据资产，贯穿所有业务环节：

```
五力画像（5个维度得分）
  │
  ├── 选题权重（03模块）
  │    └── 得分 <50分：基础权重 +40%
  │    └── 得分 50~65分：基础权重 +20%
  │    └── 得分 ≥65分：无额外加权
  │
  ├── AI 对话倾向（04模块）
  │    └── 关注维度（score <65）→ 优先引导该维度相关能力
  │    └── 全部 ≥65分 → 通用启发策略
  │
  ├── RAG 检索策略（03模块）
  │    └── 路径1：检索相似题解析，过滤薄弱五力相关内容
  │    └── 路径2：检索五力策略文档（按薄弱维度匹配）
  │
  └── 训练效果度量（闭环）
       └── 再测五力 → 对比前后雷达图 → 验证成长
```

**数据优先级（各模块统一遵循）：**
- 训练画像（`five_power_training_profiles`）比测试画像更新，优先使用
- 两者都有时：综合得分 = 训练得分 × 0.6 + 测试得分 × 0.4
- 都没有时：03模块拦截，04模块降级为通用模式

## 6. 架构风险判断

### 6.1 最大风险：题库冷启动 🔴

**性质：** 内容工程风险，非技术风险

整个选题算法依赖「知识点 × 五力」双标签题库，每个知识点至少需要 **5 道**已标注题目才能开放训练入口。客户文档中明确标注：

> **「有待解决：题库！」**

**影响评估：** 题库不足 → 训练入口无法开放 → 核心功能形同虚设 → 产品无法上线

**缓解措施：**
- AI 自动标注智能体（降低人工标注成本）
- 优先建设初三、高一的数理化主干知识点（缩小范围，聚焦启动）
- 确定题库来源方案（人工录入 / 合规采购 / AI 辅助生成）

### 6.2 第二风险：五力算法未交付 🟠

**性质：** 外部依赖风险

文档多次提及「五力评分算法由产品方提供」，但当前未交付具体算法文档。

**影响评估：** 算法精度决定画像是否可信 → 画像失准则个性化选题和 AI 指导都偏离靶心

**缓解措施：** 开发可并行推进，预留算法参数的后台配置接口，上线前必须完成算法交付与验证。

### 6.3 第三风险：双 AI 的 Token 成本 🟡

**性质：** 商业模式风险

RAG + 对话双 AI 在单次训练会话内最高消耗约 **10,000 Token**。以当前主流大模型定价，高频用户的 AI 成本需要提前建模。

**已有缓解设计：**
- 「能用规则解决的不调 AI」原则（答对沉默、选择题答错走静态解析）
- 明确的 Token 降级策略（AI 不可用时展示静态内容）
- 多供应商切换支持（可选最优性价比供应商）

### 6.4 风险优先级矩阵

| 风险 | 严重程度 | 发生概率 | 优先级 | 行动建议 |
|------|----------|----------|--------|----------|
| 题库冷启动 | 致命 | 高 | 🔴 P0 | 开发启动前专项立项，明确种子题库里程碑 |
| 五力算法未交付 | 严重 | 中 | 🟠 P1 | 上线前 deadline，预留参数配置接口 |
| Token 成本 | 中等 | 中 | 🟡 P2 | 建立成本监控看板，设置会话 Token 上限熔断 |
| AI 服务稳定性 | 中等 | 低 | 🟡 P2 | 静态降级方案已设计，多供应商备切 |

## 7. 架构师结论

### 7.1 技术选型评价

| 技术选型 | 评价 |
|----------|------|
| 微信小程序 | ✅ 合理。目标用户（中学生）微信覆盖率极高，无需下载 App 降低门槛 |
| 向量数据库（Milvus/Chroma） | ✅ 合理。RAG 场景标准选型，双路召回设计有实际工程价值 |
| 大模型多供应商切换 | ✅ 合理。避免供应商锁定，可按成本/质量动态切换 |
| 参数配置化（不硬编码） | ✅ 正确。五力阈值、Token 预算、Prompt 模板均走配置，运营可自助调整 |
| AI 自动标注审核流程 | ✅ 合理。人机协同降低内容成本，置信度分级处理策略可行 |

### 7.2 一句话总结

**这是一个以「五力认知画像」为核心数据驱动，融合 RAG 结构化解题指导与对话式苏格拉底启发的双轨 AI 学习系统。**

技术上并不激进（微信小程序 + 向量数据库 + 大模型 API），但产品逻辑有真实的教育学洞察。核心壁垒不在技术，在于：

1. **五力评估模型的准确性** — 诊断是否真正准确
2. **题库的持续建设质量** — 内容是否足够支撑个性化选题

这两点才是决定产品能否真正区别于普通 AI 答题工具的关键，也是架构师需要在设计阶段就确认方案的优先事项。
