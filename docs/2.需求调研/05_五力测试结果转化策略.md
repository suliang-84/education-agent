## 1. 转化总览

### 1.1 转化链路一览

```
20道测试题
    │
    ├── 10道标准答案题（每力2题）
    │       ↓
    │   ability_score（五力能力分）
    │   → 回答："他实际上做得到什么"
    │
    └── 10道无唯一答案题（每力2题）
            ↓
        preference_score（五力认知入口分）
        → 回答："他更习惯从哪里进入陌生问题"
            │
            └── 两者合并
                    ↓
                final_score（综合五力分）
                → 用于前台雷达图可视化
```

### 1.2 最核心的设计原则

> **20道测试题最终不是只生成"五力高低"，而是分别识别学生"实际认知能力"和"习惯认知入口"。能力分决定哪些地方需要训练，入口分决定AI优先用什么方式讲。前者服务"补足你的力"，后者服务"一通百通"；后续再通过真实学习行为动态修正初始画像。**

### 1.3 五力字段统一定义

| 字段代码 | 中文名称 | 含义 |
|----------|----------|------|
| `INSIGHT` | 洞察力 | 从复杂信息中抓到改变问题性质的关键信息 |
| `STRUCTURE` | 建构力 | 把离散信息组织成可以思考的结构/模型 |
| `INFERENCE` | 推演力 | 接受前提后沿着规则连续推演到结论 |
| `ADAPTATION` | 调适力 | 遭遇新证据时主动修正原有模型 |
| `TRANSFER` | 迁移力 | 识别表面不同但底层结构相同的两个情境 |

每一力最终保存三个字段：

| 字段 | 含义 |
|------|------|
| `ability_score` | 能力分（0~100），来自标准答案题 |
| `preference_score` | 认知入口分（0~100），来自无唯一答案题 |
| `final_score` | 综合分（0~100），用于前台展示 |

## 2. 题目分类与计分基础

### 2.1 两类题目的分工

| 题型 | 数量 | 测量目标 | 计分方式 |
|------|------|----------|----------|
| **标准答案题** | 10题（每力2题） | 学生实际能不能完成该认知动作 | 对/错计分，影响 `ability_score` |
| **无唯一答案题** | 10题（每力2题） | 面对陌生问题时习惯从哪种方式进入 | 选项权重累加，影响 `preference_score` |

| 五力 | 标准答案题 | 无唯一答案题 |
|------|-----------|-------------|

| 推演力（INFERENCE） | 题09、题10 | 题11、题12 |
| 调适力（ADAPTATION） | 题13、题14 | 题15、题16 |
| 迁移力（TRANSFER） | 题17、题18 | 题19、题20 |

## 3. 五力能力分计算（ability_score）

### 3.1 计算规则

每一力有 **2 道标准答案题**，V1 采用最简单的 0/1 计分：

```
答对：1.0 分
答错：0.0 分

ability_score（某力）= (第1题得分 + 第2题得分) / 2 × 100
```

**示例：**

```
洞察力标准答案题：
  题01（答对）→ 1.0
  题02（答错）→ 0.0

ability_score(INSIGHT) = (1.0 + 0.0) / 2 × 100 = 50
```

### 3.2 V1.1 扩展方案（部分正确）

> 第一版不实现，预留扩展接口：

```
完全正确 = 1.0
部分正确 = 0.5
错误     = 0.0
```

### 3.3 五力能力分汇总示例

| 五力 | 题1 | 题2 | ability_score |
|------|-----|-----|---------------|
| 洞察力 | ✅ | ✅ | 100 |
| 建构力 | ✅ | ❌ | 50 |
| 推演力 | ❌ | ✅ | 50 |
| 调适力 | ❌ | ❌ | 0 |
| 迁移力 | ✅ | ✅ | 100 |

## 4. 五力认知入口分计算（preference_score）

### 4.1 计分原理

无唯一答案题的每个选项背后对应五力的不同权重向量。学生选择某选项后，该选项的权重向量累加到总分池中。

**单题权重示例（题03，洞察力题）：**

| 选项 | 选项描述 | 洞察 | 建构 | 推演 | 调适 | 迁移 |
|------|----------|------|------|------|------|------|
| A | 先比较各变化发生的时间 | 0.70 | 0.05 | 0.10 | 0.10 | 0.05 |
| B | 先画出各要素之间的关系图 | 0.10 | 0.65 | 0.10 | 0.10 | 0.05 |
| C | 假设一个原因成立，继续推演 | 0.10 | 0.10 | 0.65 | 0.10 | 0.05 |
| D | 找一个发生过类似情况的湖泊比较 | 0.10 | 0.05 | 0.05 | 0.10 | 0.70 |

> **学生选 B**，本题贡献：洞察 +0.10 / 建构 +0.65 / 推演 +0.10 / 调适 +0.10 / 迁移 +0.05

### 4.2 完整计算流程

```
Step 1：对 10 道无唯一答案题，每题按学生选项的权重向量累加

  例：10题完成后，各力累计值：
    洞察累计 = 3.80
    建构累计 = 2.60
    推演累计 = 1.70
    调适累计 = 0.90
    迁移累计 = 1.00
    ─────────────
    总和      = 10.00（每题权重之和约为1，10题总和≈10）

Step 2：归一化到 0~100（转为百分比）

    洞察 = 3.80 / 10 × 100 = 38
    建构 = 2.60 / 10 × 100 = 26
    推演 = 1.70 / 10 × 100 = 17
    调适 = 0.90 / 10 × 100 = 9
    迁移 = 1.00 / 10 × 100 = 10
    ─────────────────────────────
    总和 = 100（五力入口分之和永远为100）
```

### 4.3 重要注意事项

> ⚠️ **入口分是相对偏好分布，总和永远为 100。**
>
> 前台**不能**解释为"你的洞察力只有38分"。
> 正确的展示方式是：**"认知入口倾向：第一入口：洞察力 / 第二入口：建构力"**

### 4.4 认知入口倾向的确定

```
从 preference_score 中取前两名：

  洞察 38 → primary_entry = INSIGHT
  建构 26 → secondary_entry = STRUCTURE

后台字段：
  primary_entry   = "INSIGHT"
  secondary_entry = "STRUCTURE"
```

### 4.5 调适力题的特殊权重设计

**题15、题16 的所有选项调适力权重均为最高**（0.45~0.50），但同时暴露学生靠哪种方式进行调适：

| 选项 | 调适 | 同时揭示的其他力 |
|------|------|-----------------|
| A（检查是否漏掉关键条件） | 0.45 | 洞察 0.40 |
| B（看模型哪条关系需要调整） | 0.45 | 建构 0.40 |
| C（从冲突处往回找第一步不成立的地方） | 0.45 | 推演 0.40 |
| D（找一个能容纳新旧事实的解释） | 0.45 | 迁移 0.35 |

> 这意味着调适力不只告诉我们"学生能不能调适"，还告诉我们"学生习惯通过洞察/建构/推演/迁移哪种方式来调适"。

## 5. 综合五力分计算（final_score）

### 5.1 计算公式

```
final_score（某力）= ability_score × 0.70 + normalized_preference × 0.30
```

**示例（洞察力）：**

```
ability_score(INSIGHT)      = 82
preference_score(INSIGHT)   = 34   ← 已归一化到0~100

final_score(INSIGHT) = 82 × 0.70 + 34 × 0.30
                     = 57.4 + 10.2
                     = 67.6 ≈ 68
```

### 5.2 五力完整示例

| 五力 | ability_score | preference_score | final_score |
|------|:---:|:---:|:---:|
| 洞察力 | 82 | 34 | **68** |
| 建构力 | 47 | 26 | **41** |
| 推演力 | 74 | 17 | **57** |
| 调适力 | 58 | 9 | **43** |
| 迁移力 | 51 | 14 | **40** |

### 5.3 综合分的用途限制

> ⚠️ **综合分主要用于前台雷达图可视化，不建议直接用于驱动 AI 教学决策。**
>
> AI 教学应优先使用两个原始数据：
> - `ability_score`：决定哪些地方需要训练
> - `preference_score`：决定 AI 优先用什么方式讲

## 6. 薄弱项识别规则

### 6.1 阈值判断逻辑

不以"分数最低的力"直接定义薄弱，而是基于阈值区间：

```
ability_score < 60          → 明显需要加强（weak）
60 ≤ ability_score ≤ 75    → 中等（medium）
ability_score > 75          → 相对优势（strong）
```

### 6.2 薄弱项排序规则

```
Step 1：筛选出所有 ability_score < 60 的五力

Step 2：在这些力中按 ability_score 从低到高排序

Step 3：取排名前两位
  primary_weakness   = ability_score 最低的那一力
  secondary_weakness = ability_score 第二低的那一力

Step 4：若没有任何力 < 60，则不设薄弱项（学生各力均衡）
```

**示例：**

```
能力分：
  洞察 82 → strong
  建构 47 → weak  ← 最低，第一薄弱
  推演 74 → medium
  调适 58 → weak  ← 第二低，第二薄弱
  迁移 51 → weak

primary_weakness   = "STRUCTURE"  （建构力，47分）
secondary_weakness = "TRANSFER"   （迁移力，51分）
third_weakness     = "ADAPTATION" （调适力，58分，可选字段）

后台字段：
  primary_weakness   = "STRUCTURE"
  secondary_weakness = "TRANSFER"
```

### 6.3 前台展示规则

| 得分区间 | 等级标签 | 界面颜色 | 前台文案 |
|----------|----------|----------|----------|
| < 50 | 重点强化 | 🔴 红色 | "需要重点训练" |
| 50~64 | 次重点 | 🟡 黄色 | "值得加强" |
| 65~79 | 良好 | 🟢 绿色 | "正常水平" |
| ≥ 80 | 优势 | 💚 深绿 | "你的优势" |

## 7. 优势入口识别规则

### 7.1 判断来源

**优势入口主要看无唯一答案题的 `preference_score`**（入口倾向），而非能力分。

```
preference_score 分布示例：
  洞察 38 → primary_entry（第一入口）
  建构 26 → secondary_entry（第二入口）
  推演 17
  调适  9
  迁移 10

primary_entry   = "INSIGHT"
secondary_entry = "STRUCTURE"
```

### 7.2 用途说明

```
优势入口给 AI 使用，作为教学默认入口：

  学习新知识时，优先从 primary_entry 对应的思维方式切入。

  不是永远只能这样教，而是"默认优先入口"。
```

### 7.3 优势入口 vs 能力优势

> ⚠️ **优势入口（preference）和能力优势（ability）是两个独立维度，不等价。**

| 字段 | 来源 | 含义 |
|------|------|------|
| `primary_entry` | preference_score 最高 | 学生习惯从哪里开始思考 |
| `primary_strength` | ability_score 最高 | 学生哪方面能力实际最强 |

两者可能相同，也可能不同（见第8章错位分析）。

## 8. 能力分与入口分的错位分析

### 8.1 为什么要分析错位

> **这是整个系统里最重要的一条：能力分和入口分不能混为一谈。**

同一个学生可能：

```
建构能力 = 42
建构入口倾向 = 78
```

这不是矛盾，而是：他很自然喜欢通过搭关系、建模型去理解问题，但目前实际建构能力并不成熟。

另一种情况：

```
洞察能力 = 85
洞察入口倾向 = 35
```

表示：他其实很擅长抓关键信息，但平时解决陌生问题时并不优先使用这个能力。

### 8.2 四种典型错位类型

| 错位类型 | ability | preference | 教学含义 |
|----------|:-------:|:----------:|----------|
| **低能力 + 高入口偏好** | 42 | 78 | 很喜欢建模但能力尚不成熟；应给予大量建构训练，顺应其建模欲望 |
| **高能力 + 低入口偏好** | 85 | 35 | 洞察能力强但不习惯主动用；应引导发挥已有能力，增强工具意识 |
| **能力与入口匹配（高高）** | 80 | 72 | 稳定优势；可作为教学入口，也可以用于迁移类拓展 |
| **能力与入口匹配（低低）** | 40 | 18 | 真正的薄弱；需从基础训练入手，不能以此为入口 |

### 8.3 错位对 AI 教学的影响

```
情境A：建构能力 42，建构入口 78
  → AI 策略：顺应学生的建构倾向，多给建构类题
             但要注意题目难度从低开始，避免打击信心

情境B：洞察能力 85，洞察入口 35
  → AI 策略：主动引导学生用洞察方式切入
             可以在 Prompt 中提示"你其实很擅长找关键条件，先试试这个方向"
```

## 9. AI可读画像生成

### 9.1 完整画像 JSON 结构

测试完成后，系统生成两份输出：
- **用户可见：** 五力雷达图 + 文字解读
- **AI 可读：** 结构化 JSON 对象（核心）

```json
{
  "grade": "初二",
  "forces": {
    "insight": {
      "ability": 82,
      "entry_preference": 34,
      "final_score": 68,
      "level": "strong"
    },
    "structure": {
      "ability": 47,
      "entry_preference": 18,
      "final_score": 38,
      "level": "weak"
    },
    "inference": {
      "ability": 74,
      "entry_preference": 21,
      "final_score": 58,
      "level": "medium"
    },
    "adaptation": {
      "ability": 58,
      "entry_preference": 9,
      "final_score": 44,
      "level": "weak"
    },
    "transfer": {
      "ability": 51,
      "entry_preference": 18,
      "final_score": 41,
      "level": "weak"
    }
  },
  "primary_strength": "insight",
  "primary_weakness": "structure",
  "secondary_weakness": "transfer",
  "primary_learning_entry": "insight",
  "secondary_learning_entry": "inference",
  "recommended_mode": "TRAIN_WEAKNESS"
}
```

### 9.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `forces[x].ability` | Int 0~100 | 该力的能力分（来自标准答案题） |
| `forces[x].entry_preference` | Int 0~100 | 该力的认知入口分（来自无唯一答案题，归一化后） |
| `forces[x].final_score` | Int 0~100 | 该力的综合分（ability×70% + preference×30%） |
| `forces[x].level` | Enum | `strong` / `medium` / `weak` |
| `primary_strength` | Enum | ability_score 最高的力 |
| `primary_weakness` | Enum | ability_score 最低且 < 60 的力 |
| `secondary_weakness` | Enum | ability_score 第二低且 < 60 的力 |
| `primary_learning_entry` | Enum | entry_preference 最高的力（AI 首选教学入口） |
| `secondary_learning_entry` | Enum | entry_preference 第二高的力 |
| `recommended_mode` | Enum | `TRAIN_WEAKNESS` 或 `LEARN_BY_STRENGTH` |

### 9.3 画像的使用规则

> **后续 AI 每次学习时，不需要把完整 20 道题重新传进去。只调用这个 JSON 画像即可。**

```
AI Prompt 中调用方式示例：

当前学生画像：
- 建构力：ability=47（需要强化）
- 洞察力：ability=82（优势）
- 认知入口：洞察力优先

当前训练目标：建构力
优先教学入口：洞察力

具体指令：
  优先通过找关键条件、比较变化和不变量的方式，
  逐步引导学生建立变量关系。
  不要直接告诉学生变量、方程或模型。
```

## 10. 两种学习模式的衔接

### 10.1 模式一：补足你的力（TRAIN_WEAKNESS）

**触发条件：** `primary_weakness` 存在（即有任一力 ability_score < 60）

```
画像输入：
  primary_weakness       = STRUCTURE（建构力）
  primary_learning_entry = INSIGHT（洞察力）

系统向 AI 传递：
{
  "training_mode": "TRAIN_WEAKNESS",
  "target_force": "STRUCTURE",
  "preferred_force": "INSIGHT"
}

AI 教学指令（自动生成）：
  当前主要训练建构力。
  学生洞察力较强。
  优先通过找关键条件、比较变化和不变量的方式，
  逐步引导学生建立变量关系。
  不要直接告诉学生变量、方程或模型。

设计原理：
  用长板（洞察力）补短板（建构力）
  → 目标是补弱项
  → 但入口从强项切入
```

### 10.2 模式二：一通百通（LEARN_BY_STRENGTH）

**触发条件：** 该知识点首次学习，或所有力 ability_score ≥ 60

```
画像输入：
  primary_learning_entry = INSIGHT（洞察力）

系统向 AI 传递：
{
  "training_mode": "LEARN_BY_STRENGTH",
  "preferred_force": "INSIGHT"
}

AI 教学指令（自动生成）：
  学生更容易通过洞察方式进入陌生知识。
  讲解一次函数时，
  优先从"什么在变化、什么不变、变化规律是什么"切入，
  再逐渐引入变量和函数表达。
  这里五力不是训练目标，而是教学入口。

设计原理：
  → 目标是学新知识
  → 从最容易进入的思维方式开门
```

### 10.3 两种模式的核心区别

| 维度 | TRAIN_WEAKNESS | LEARN_BY_STRENGTH |
|------|:--------------:|:-----------------:|
| **使用时机** | 有明确薄弱项 | 首次学习新知识 / 均衡型学生 |
| **五力的作用** | 决定训练目标 | 决定教学入口 |
| **target_force** | = primary_weakness | 不适用 |
| **preferred_force** | = primary_learning_entry（入口） | = primary_learning_entry（入口） |
| **AI 的任务** | 训练弱力，用强力引导 | 用优势思维方式讲新知识 |

## 11. 动态画像更新机制

### 11.1 设计原则

> **不要把一次测试当成终身结论。**
> 五力测试只是学生进入 MESH 时的初始认知画像。后续做题和 AI 互动过程中，应持续修正。

### 11.2 更新触发条件

| 行为信号 | 对应更新 |
|----------|----------|
| 建构类题独立完成率提高 | `structure.ability` 上调 |
| AI 提示依赖次数下降 | 对应力的 `ability` 上调 |
| 迁移题成功率提高 | `transfer.ability` 上调 |
| 学生反复使用某种思维入口 | 对应力的 `entry_preference` 上调 |
| 某类题持续答错 | 对应力的 `ability` 保持或下调 |

### 11.3 架构设计

```
初始测试画像（20题）
        +
后续真实学习行为数据
        ↓
  动态五力画像（持续更新）

建议：
  测试画像：five_power_profiles（来自测试模块）
  训练画像：five_power_training_profiles（来自训练模块，滚动更新）
  综合查询：training_score × 0.6 + test_score × 0.4
```

### 11.4 重测机制

```
学生可主动申请重测（建议间隔 ≥ 30 天）
重测结果作为新的 ability_score 参考
与训练数据综合计算新的综合画像
历史测试记录保留，用于成长对比
```

## 12. 可配置参数清单

> **以下所有参数 V1 必须配置化，不得写死在代码中。**
> 后续根据真实学生数据可直接修改配置，无需改代码。

| 参数名 | V1 默认值 | 取值范围 | 说明 |
|--------|----------|----------|------|
| `objective_weight` | 0.70 | 0~1 | ability_score 在综合分中的权重 |
| `preference_weight` | 0.30 | 0~1 | preference_score 在综合分中的权重 |
| `weak_threshold` | 60 | 0~100 | ability < 此值 → 定义为薄弱项 |
| `strong_threshold` | 75 | 0~100 | ability > 此值 → 定义为相对优势 |
| `is_correct_threshold` | 0.70 | 0~1 | 文字题答案质量系数 ≥ 此值判为正确 |
| `question_option_force_weight` | 见各题权重表 | 各力权重向量之和 = 1 | 每道无唯一答案题的各选项五力权重，支持后台独立调整 |
| `profile_decay_coefficient` | 0.30 | 0~1 | 训练画像滚动更新衰减系数（新数据权重） |
| `retest_min_interval_days` | 30 | 正整数 | 重测最小间隔天数 |
| `training_test_mix_ratio` | 0.6 / 0.4 | 0~1 | 综合查询时训练画像/测试画像的融合比例 |
