## 1. 核心设计原则

### 1.1 五力不能简单映射为"刷对应类型题"

> **错误做法：**
> - 建构力低 → 多做建构力题
> - 推演力低 → 多做推演力题

这样很容易变成一个贴了"五力标签"的普通题库，而不是真正的个性化教学。

### 1.2 五力真正需要转换的三件事

| 转换维度 | 说明 |
|----------|------|
| **给学生什么题** | 不仅仅是该五力维度的题，而是能从最优路径训练该力的题 |
| **做到哪一步时 AI 介入** | 每种五力薄弱的学生，AI 的介入时机和位置完全不同 |
| **AI 用什么方式说** | 语言风格、引导逻辑、问题粒度因力而异 |

### 1.3 最重要的一句话

> **学生缺什么，决定我们练什么；学生擅长什么，决定我们怎么把他带进去。**

## 2. 两种学习模式

系统后台需要明确区分两种模式，并在每次学习会话中选择其一：

### 模式 A：补足模式（TRAIN_WEAKNESS）

**目标：** 哪一力弱，就专门训练哪一力。

**关键原则：** 训练弱项，不代表必须用学生最不擅长的方式讲解。

```
目标：补弱项
入口：借强项

示例：
  洞察力 82 / 建构力 43
  ↓
  训练目标 = 建构力
  但 AI 先用洞察力入口带入，再引导至建构力训练
```

### 模式 B：一通百通模式（LEARN_BY_STRENGTH）

**目标：** 不以补弱项为主，而是通过最优入口学习新知识。

**关键原则：** 同一知识点，不同五力的学生从不同思维入口进入。

```
示例：学习"二元一次方程"

  洞察型 → 从"找变化和不变量"进入
  建构型 → 从"把故事搭成关系"进入
  推演型 → 从"如果……那么……"逻辑链进入
  迁移型 → 从已有知识和相似情境进入
```

| 模式 | 五力的作用 |
|------|-----------|
| 补足模式 | 五力决定**训练目标** |
| 一通百通 | 五力决定**教学入口** |

## 3. 五力问题诊断与AI介入策略

> **参考题目（贯穿全章）**
>
> 几个人一起买黄金：
> - 每人出 400 钱，会多出 3400 钱；
> - 每人出 300 钱，会多出 100 钱。
>
> 请建立人数与总价之间的方程关系。（北师大版八年级数学 · 2024年深圳期末题）

---

### 3.1 洞察力薄弱策略

#### 问题诊断

洞察力弱的学生，真正的困难不是不会解方程，而是没有看懂题目里**数量关系的实际含义**。

```
典型错误：
  学生将"多出3400"理解为相加关系
  写出：400x + 3400 = y  ← 错误
  应为：400x - y = 3400  ← 正确
```

**根本原因：** 学生没有在脑中还原"多出"这个动作的实际含义，没有建立抽象符号与现实情境的连接。

#### AI 不应该做的事

❌ 直接指出错误：*"你列反了，应该是 400x - y = 3400"*

这样学生虽然改对了这道题，但下次遇到"还差""剩余""至少"等类似表述还是会错。

#### AI 应该做的事：重建现实场景，让学生自己发现关系

```
AI引导流程：

步骤1：还原情境
  AI："假设大家把钱全部放到桌上。桌上有 400x 元。
       买完东西以后，桌上还剩 3400 元。
       哪个数更大：大家交的钱，还是商品价格？"
  学生："大家交的钱。"

步骤2：量化差距
  AI："大多少？"
  学生："3400。"

步骤3：让学生自己写关系
  AI："那你现在自己写一句：
       '大家交的钱 = 商品价格 + ______'"
  学生："400x = y + 3400"

步骤4：引导变形
  AI（不说话，让学生自己变形）
  学生："400x - y = 3400"  ← 学生自己发现了正确关系
```

**训练本质：** 不是告诉学生正确式子，而是**让学生重新看清题目发生了什么**。

#### 后续选题方向

优先选择含以下表述的题型，而非增加运算难度：

| 题目特征 | 示例场景 |
|----------|----------|
| "还剩多少" | 找零、余量问题 |
| "还差多少" | 凑钱、不足问题 |
| "多了多少" | 盈余、超额问题 |
| "至少""至多" | 不等式的现实含义 |
| 隐含条件 | 表面没有直接给出的等量关系 |
| 多余条件 | 题目中有干扰信息，需筛选 |
| 图表有效信息 | 从图表中读取关键数据 |

---

### 3.2 建构力薄弱策略

#### 问题诊断

建构力弱的学生，能听懂题目的每一句话，但无法将语言描述转化为数学关系。

```
典型表现：
  "我都看懂了，但不知道怎么列式"
  能理解"每人400"和"多3400"各是什么意思
  但无法建立它们之间的数量关系
```

**根本原因：** 缺乏"从语言世界进入数学世界"的建模能力，即变量的抽象和关系的搭建。

#### AI 不应该做的事

❌ 直接给出设元方式：*"设人数为 x，总价为 y"*

因为"设什么、怎么产生关系"正是该学生需要训练的核心能力。

#### AI 应该做的事：用具体数字搭桥，逐步抽象

```
AI引导流程：

步骤1：找到未知量（用自然语言）
  AI："这道题里，有哪两个东西是我们真正不知道的？"
  学生："人数，还有金子的价格。"

步骤2：用具体数字建立感知
  AI："好，先别管 x 和 y。假设有10个人，每人400，一共多少？"
  学生："4000。"
  AI："如果有20个人？"
  学生："8000。"

步骤3：从具体到抽象
  AI："所以如果人数叫 x，总共凑的钱怎么写？"
  学生："400x。"

步骤4：建立第一个关系
  AI："桌上有 400x，买完还剩 3400，商品价格和 400x 是什么关系？"
  学生："商品价格 = 400x - 3400"

步骤5：学生自己完成第二个关系
  AI："好。第二种情况你自己来。"
  学生："商品价格 = 300x - 100"

步骤6：两个关系自然呈现
  y = 400x - 3400
  y = 300x - 100
  → 进入二元一次方程组求解
```

**训练本质：** 不是让学生记"盈→减，不足→加"，而是让学生**养成把故事中的东西变成量、再把量之间的关系写出来的习惯**。

#### 后续选题方向

优先选择需要"从语言世界进入数学世界"的题型：

| 题型 | 建模动作 |
|------|----------|
| 行程问题 | 速度 × 时间 = 路程 |
| 商品价格问题 | 成本 / 售价 / 利润关系 |
| 浓度问题 | 溶质 / 溶液 / 浓度三量关系 |
| 水量变化 | 流入 / 流出 / 存量关系 |
| 租车收费 | 基础费 + 单价 × 数量 |
| 几何面积关系 | 形状尺寸与面积的代数关系 |
| 函数实际应用 | 变量识别与函数表达 |

---

### 3.3 推演力薄弱策略

#### 问题诊断

推演力弱的学生，洞察和建构没有问题——他能正确列出方程，但在计算和推导过程中出现断裂。

```
典型表现：
  正确列出：y = 400x - 3400
            y = 300x - 100
  代入联立后：400x - 3400 = 300x - 100
  然后卡住，或写成：100x = 3400 - 100  ← 符号出错
```

**根本原因：** 推演链条在某一步断裂，学生失去了"当前目标是什么"的意识，无法连续执行变换步骤。

#### AI 不应该做的事

❌ 重新讲知识点，从头解释移项、合并同类项的规则

因为学生已经知道规则，问题是执行过程中的连续性断裂。

#### AI 应该做的事：把长推导拆成学生可连续完成的小动作

```
AI引导流程：

步骤1：明确当前目标
  AI："先不算结果。我们现在的目标是什么？"
  学生："求 x。"

步骤2：明确终态
  AI："那你希望最后左边只剩什么？"
  学生："x。"

步骤3：识别障碍
  AI："现在两边都有 x。你想先消掉哪一个？"
  学生："300x。"

步骤4：执行单步动作
  AI："那两边同时做什么？"
  学生："减 300x。"
  结果：100x - 3400 = -100

步骤5：继续下一个小目标
  AI："现在你想让 x 旁边还留下什么？"
  → 学生继续执行...
```

**渐进式退出策略（关键设计）：**

```
阶段1（初期）：AI 每一步问一次，全程脚手架
阶段2（中期）：两三步才问一次，逐步减少提示
阶段3（成熟）：学生整段自己完成，AI 仅在出错时介入
```

**训练本质：** 不重新讲知识，而是把长推导链拆成**学生自己能够连续完成的小动作**，并随熟练度逐步撤除支撑。

#### 后续选题方向

| 题目特征 | 训练价值 |
|----------|----------|
| 多步骤计算 | 训练推导链的连续性 |
| 需要多次变形 | 训练目标意识的保持 |
| 分数、负数运算 | 高错误率节点的专项训练 |
| 证明题 | 训练从已知到结论的完整逻辑链 |
| 递推数列 | 训练规律识别与连续推演 |

### 3.4 调适力薄弱策略

#### 问题诊断

调适力弱的学生，问题不是不会算，而是**不会检验自己**——一路算到底，得出荒谬结果也不自知。

```
典型表现：
  写出：400x + 3400 = y  ← 关系错误
  一路算下去，得到一个明显不合理的人数
  没有回头验证
```

**根本原因：** 缺乏"把结果放回情境验证"的习惯，以及"发现错误后主动调整策略"的能力。

#### AI 不应该做的事

❌ 马上指出错误位置：*"第一步就错了"*

因为调适力训练的重点恰恰是：**让学生自己发现错误**，而不是被告知错误。

#### AI 应该做的事：创造让学生自己发现错误的机会

```
AI引导流程：

步骤1：先不评判，让学生验证结果
  AI："先别看我的答案。你得到的人数，
       把它放回原来的故事里试一次。"
  学生代入后，发现：每人交400并没有多3400。

步骤2：引导自主诊断
  AI："所以现在有两种可能：
       计算错了，或者最开始关系搭错了。
       你觉得先查哪一个比较快？"
  学生："先查关系。"

步骤3：用极简情境帮他重建直觉
  AI："好。不用看公式。假设商品100元，
       你交了120元，最后剩20元。
       是 120 + 20 = 100，还是 120 = 100 + 20？"
  学生："后面那个。"
  → 学生自己发现：正负号方向错了。
```

**训练本质：** AI 制造一个**让学生自己发现错误的机会**，而不是替学生完成错误发现的动作。

#### 后续选题方向

| 题目特征 | 训练价值 |
|----------|----------|
| 含常见错误解法 | 让学生判断哪里有问题 |
| 一题两解 | 比较两种方法，分析异同 |
| 看起来正确但不成立的步骤 | 训练对推导逻辑的审查 |
| 结果可用现实意义检验的题 | 培养"代回验证"习惯 |
| 一种方法走不通必须换路的题 | 训练策略切换意识 |

### 3.5 迁移力薄弱策略

#### 问题诊断

迁移力弱的学生，能把当前题目做会，但换了一个表面不同（实际同构）的题目就无法识别和应用相同的解题结构。

```
典型表现：
  "盈不足"题做完全会了
  AI问："懂了吗？"
  学生："懂了。"← 这句话几乎没价值

  换成班级活动收费题：
    每人交50元多300元 / 每人交40元差200元
  学生又不会列式了
```

**根本原因：** 学生习惯了"题目→方法"的直接映射，缺乏"识别底层结构"的能力，无法在不同表面形式中看到相同的数学关系。

#### AI 不应该做的事

❌ 直接提示：*"这就是刚才那道买金问题"*

这一句话等于 AI 替学生完成了迁移，学生自己没有走过这个过程。

#### AI 应该做的事：让学生自己剥离表面，识别相同结构

```
AI引导流程：

步骤1：给出换皮题（表面完全不同）
  原题：几人买黄金，400钱多3400，300钱多100
  新题：班级活动，每人交50元多300元，每人交40元差200元

步骤2：不提示"两题一样"，让学生先观察
  AI："先不算。上一题和这一题都出现了哪三样东西？"
  学生："人数、每人出多少钱、总费用。"

步骤3：引导发现结构不变
  AI："故事不同，但这三者之间的关系变了吗？"
  学生慢慢发现："没变。"

步骤4：学生自己列式
  50x - y = 300
  y - 40x = 200
  → 迁移发生了

评估标准：
  ✅ 学生马上能列 → 迁移成功
  ❌ 学生无法列式 → 继续上述引导流程
```

**训练本质：** 让学生自己发现"外壳变了，内核没变"，用**洞察力剥离表面，最终看见同构结构**。

#### 后续选题方向（迁移链设计）

以"盈不足"结构为例，构建迁移梯度：

```
同构迁移链：
  黄金购买（原题）
    ↓
  班级活动收费
    ↓
  租车收费（起步价 + 单价）
    ↓
  门票收费（团体折扣 vs 单人价格）
    ↓
  工程费用（多队合作 vs 单队）
    ↓
  购物优惠（满减 vs 折扣）
```

迁移训练的核心是：**表面情境不断换，底层数学结构保持相同**。

## 4. 五力横向对比：AI介入行为差异

> 同一道题，五种学生，AI 做的是五件完全不同的事。

| 五力薄弱 | 核心问题 | AI 介入位置 | AI 主要行为 |
|----------|----------|------------|------------|
| **洞察力弱** | 没看懂题目里数量关系的实际含义 | 学生列式前 | 帮学生重新还原"多3400"背后发生了什么 |
| **建构力弱** | 看懂了题但不知道怎么列式 | 学生开始建模时 | 用具体数字引导，把故事一步步变成数量关系 |
| **推演力弱** | 列式对了但计算推导链断裂 | 每一个推导步骤节点 | 把长推导链拆成连续小动作，随熟练度退出 |
| **调适力弱** | 算完了不验证，或发现错误不知如何调整 | 学生得出结果后 | 不立即纠错，创造让学生自己发现错误的机会 |
| **迁移力弱** | 换一个表面不同的题就不会了 | 学生完成原题后 | 给换皮题，引导学生自己识别同构结构 |

**关键洞察：** 同一道题，不是生成五种不同语气的解释，而是 **AI 介入的位置本身就不一样**。

## 5. 借强补弱：跨力桥接策略

当系统确定"训练目标力"后，不应直接把学生扔进最陌生的思维方式，而是通过**优势力作为入口**，逐步引导至目标力的训练。

### 5.1 桥接策略总表

| 训练目标 | 优势入口 | 桥接路径 |
|----------|----------|----------|
| **建构弱 + 洞察强** | 洞察力 | 先找变化/不变量/关键条件 → 再把已发现的信息建立关系 |
| **推演弱 + 建构强** | 建构力 | 先让学生把整体结构搭出来（A→B→C→D） → 再一格一格走推演 |
| **调适弱 + 推演强** | 推演力 | 利用推演能力倒着检查全过程 → 让推演成为检查工具 |
| **迁移弱 + 洞察强** | 洞察力 | 先观察哪些表面信息变了/哪些关系没变 → 用洞察剥离外壳，看见同构 |

### 5.2 桥接示例详解：建构弱 + 洞察强

```
场景：洞察力 82，建构力 41，训练目标：建构力

❌ 错误做法：
  AI："请建立数学模型。"
  AI："请确定变量关系。"
  → 这种语言最容易让他懵，因为他不擅长

✅ 正确做法（借洞察入口）：

  AI（洞察入口）：
    "你先找一下，两种付款方式里哪些东西变了，哪些没变？"
    学生："每人交的钱变了；人数没变；商品价格也没变。"

  AI（过渡）：
    "很好。既然人数和价格没变，
     我们把两种情况分别写出来，
     看它们能不能同时指向同一个价格。"

  → 进入建构训练
```

**桥接的本质：** 从学生擅长的思维方式进入，用已有能力作为跳板，引导到需要训练的能力区域。

## 6. 一通百通：以优势力为入口学习新知识

当学生处于"一通百通"模式时，五力不是训练对象，而是 **AI 选择"从哪扇门进去"的依据**。

### 6.1 示例：学习"一次函数"

> 传统 AI 可能直接说："一般地，形如 y = kx + b……"

MESH 根据五力选择不同入口：

#### 洞察型学生的入口

```
AI：给出现实变化情境
  "一辆出租车，起步价10元，之后每公里增加2元。"
  "什么一直不变？"
  学生："起步价10元。"
  "什么随着里程一直变化？"
  学生："车费。"
  "每多1公里，车费总是增加多少？"
  学生："2元。"

AI：
  "你刚才自己找出来的两个东西，
   其实就是一次函数里最重要的两个部分。"

→ 学生用洞察力自己发现了斜率（k）和截距（b）的概念
```

#### 建构型学生的入口

```
给几个里程和车费数据
  → 让学生建立 x、y 变量
  → 让学生自己搭出数量关系式
  → 再抽象出 y = kx + b
```

#### 推演型学生的入口

```
1公里多少钱？
  → 2公里？
  → 3公里？
  → n公里？
从具体数字不断向前推，最终归纳出函数结构
```

### 6.2 五种入口对比

| 优势力 | 新知识学习入口 | 学生的认知动作 |
|--------|--------------|--------------|
| 洞察力 | 从"找变化和不变量"进入 | 先感知规律，再抽象定义 |
| 建构力 | 从"把故事搭成关系"进入 | 先建模，再归纳公式 |
| 推演力 | 从"如果……那么……"逻辑链进入 | 先递推，再总结规律 |
| 调适力 | 从多个案例的共同错误分析进入 | 先排除错误，再确认正确结构 |
| 迁移力 | 从已有知识和相似情境进入 | 先类比已知，再扩展新知 |

## 7. 程序实现：三个核心参数

AI 每次进入学习会话时，系统至少传入三个核心参数：

### 7.1 参数定义

```json
{
  "mode": "TRAIN_WEAKNESS | LEARN_BY_STRENGTH",
  "target_force": "洞察力 | 建构力 | 推演力 | 调适力 | 迁移力",
  "preferred_force": "洞察力 | 建构力 | 推演力 | 调适力 | 迁移力"
}
```

| 参数 | 说明 | 示例 |
|------|------|------|
| `mode` | 当前学习模式 | `TRAIN_WEAKNESS`（补弱）/ `LEARN_BY_STRENGTH`（借强） |
| `target_force` | 今天真正要训练的力 | `target_force = 建构力` |
| `preferred_force` | 学生的优势入口 | `preferred_force = 洞察力` |

### 7.2 AI 收到的 Prompt 示例

```
当前题目主要训练建构力。
不要直接提供未知数、方程或变量关系。
学生洞察力较强，如学生卡住，优先让其比较条件、
寻找变化量和不变量，再将其已经发现的信息转化成数量关系。
```

**这才是真正有用的 Prompt。** 而不是模糊的"这个学生建构力很弱，请多鼓励他"。

## 8. 题库标签体系

每道题至少标注以下标签，使其成为**可以被 AI 从不同角度调用的教学素材**，而不只是"题 + 答案"。

### 8.1 完整标签字段

| 标签字段 | 说明 |
|----------|------|
| 学科 | 数学 / 物理 / 化学 |
| 年级 | 七年级 ~ 十二年级 |
| 知识点 | 如：二元一次方程组应用 |
| 主训练力 | 最核心训练的五力维度 |
| 次训练力 | 辅助训练的五力维度 |
| 常见错误 | 该题的典型错误模式 |
| 洞察训练点 | 如何用此题训练洞察力 |
| 建构训练点 | 如何用此题训练建构力 |
| 推演训练点 | 如何用此题训练推演力 |
| 调适训练点 | 是否可做调适训练 + 方式 |
| 迁移方向 | 可迁移到哪些情境/题型 |

### 8.2 示例标注（"盈不足"题）

```yaml
题目: "几人买黄金，每人400多3400，每人300多100"
知识点: 二元一次方程组应用
主训练力: 建构力
次训练力: 洞察力
常见错误: 把"盈余"关系写反（400x + 3400 = y）

洞察训练点: 理解"多出"的真实数量关系（大家的钱 > 商品价格）
建构训练点: 人数×单价与总价之间的关系建立
推演训练点: 消元过程（移项、合并同类项）
调适训练点: 把结果代回现实情境检查（人数合理吗？）
迁移方向:
  - 班级活动收费
  - 租车收费
  - 门票收费
  - 工程费用分摊
  - 购物满减计算
```

## 9. AI Prompt 设计规范

### 9.1 五力对应的 AI 行为指令模板

#### 洞察力薄弱时

```
当前题目训练重点：洞察力。
学生容易忽略题目中的隐含数量关系。
不要直接指出学生的列式错误。
先用情境还原法：让学生描述题目中"发生了什么"。
引导学生自己写出大小关系，再写出等式。
不要给出正确答案，直到学生自己推导出来。
```

#### 建构力薄弱时

```
当前题目训练重点：建构力。
不要直接提供未知数设定或方程。
先用具体数字（如10人、20人）帮学生建立感知。
引导学生从具体到抽象，自己写出变量和关系式。
如学生卡住，优先使用洞察入口（找变化/不变量），再过渡到建构。
```

#### 推演力薄弱时

```
当前题目训练重点：推演力。
学生已正确列式，但推导链容易断裂。
不要重新讲知识点。
把每个推导步骤拆成单一小问题。
每次只问一个"下一步做什么"，让学生自己执行。
随着学生熟练度提升，逐步减少提问频次。
```

#### 调适力薄弱时

```
当前题目训练重点：调适力。
不要在学生计算完成前指出错误。
学生得到结果后，引导他将结果代回题目情境验证。
让学生自己判断：是计算错了还是建模错了。
用极简情境帮助他重建正确的直觉，不要直接给答案。
```

#### 迁移力薄弱时

```
当前题目训练重点：迁移力。
学生已完成原题，现在给出换皮题（结构相同，情境不同）。
不要提示"两道题是一样的"。
引导学生观察：两道题出现了哪些相同的"角色"？
让学生自己发现关系结构没有变化，再开始列式。
```

### 9.2 渐进式提示原则

```
脚手架退出策略：

初期：高频提示，每步引导
  │
  ▼
中期：降低频率，两三步提示一次
  │
  ▼
后期：仅在卡点出现时介入
  │
  ▼
成熟：学生整段独立完成，AI沉默
```

## 10. 产品核心定义

### 一句话定义

> **MESH 五力系统不是根据学生弱项生成不同的"讲解话术"，而是改变 AI 介入解题过程的位置、选题方式和教学入口。**

### 完整定义

> **学生缺什么，决定我们练什么；学生擅长什么，决定我们怎么把他带进去。**

### 与普通 AI 答题工具的本质区别

| 维度 | 普通 AI 答题工具 | MESH 五力系统 |
|------|----------------|--------------|
| 核心逻辑 | 学生有问题 → AI 给答案 | 学生有问题 → AI 改变介入位置 |
| 个性化方式 | 不同语气风格的讲解 | 不同的 AI 介入时机和问题粒度 |
| 题目选择 | 按知识点匹配 | 按知识点 × 五力 × 优势入口匹配 |
| 教学目标 | 做对这道题 | 训练对应认知能力 |
| 成长追踪 | 正确率变化 | 五力得分变化 |
