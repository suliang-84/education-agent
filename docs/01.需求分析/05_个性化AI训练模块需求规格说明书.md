## 1. 概述

### 1.1 模块目标

个性化AI训练模块是中学数理化AI助教微信小程序的核心功能模块（V1.0最高优先级），承接五力认知测试模块输出的学生五力画像，驱动全链路个性化训练闭环：

1. **选题个性化**：根据学生当前五力薄弱情况，从结构化题库中自动生成专属训练题卷
2. **指导智能化**：学生答题后，通过RAG技术从向量数据库检索相似题解析和五力方法论，生成针对学生薄弱五力的定向解题思路
3. **画像动态化**：实时记录答题过程中各五力类型题目的正确率、单题耗时、训练总耗时等结构化数据，持续更新学生个人画像
4. **管理高效化**：后台支持题目AI自动标注与五力关联，管理员只需审核确认，大幅降低内容管理成本

### 1.2 设计原则

| 编号 | 原则 | 说明 |
|------|------|------|
| P-01 | 五力驱动选题 | 选题逻辑以学生五力薄弱项为核心权重，非随机出题 |
| P-02 | AI辅助不替代 | RAG生成解题引导思路，不直接给出答案，保留学生思考空间 |
| P-03 | 异步不阻塞 | AI标注、向量化入库、RAG生成均异步执行，不阻塞主流程 |
| P-04 | 降级有保底 | AI不可用时，自动降级展示静态解析文本，训练流程不中断 |
| P-05 | 配置可调 | 选题权重、难度分布、RAG参数均通过后台配置驱动，无需代码发布 |
| P-06 | 数据分层存储 | 训练画像与测试画像独立存储，互不覆盖，选题算法同时参考两者 |

### 1.3 用户角色

| 角色标识 | 角色名称 | 使用端 | 核心职责 |
|----------|----------|--------|----------|
| STUDENT | 学生 | 微信小程序 | 选择知识点训练，查看解题思路，查看训练小结 |
| SUPER_ADMIN | 超级管理员 | 后台管理系统 | 全权限，含训练配置、数据导出、策略文档管理 |
| CONTENT_ADMIN | 内容管理员 | 后台管理系统 | 管理知识点树、题库、审核AI标注、管理策略文档 |
| ORG_ADMIN | 机构管理员 | 后台管理系统 | 查看本机构学生训练数据并导出 |
| DATA_VIEWER | 数据查看员 | 后台管理系统 | 只读查看全局训练数据与统计报表 |

### 1.4 术语定义

| 术语 | 定义 |
|------|------|
| 五力 | 洞察力、建构力、推演力、调适力、迁移力五项认知能力维度的统称 |
| 训练会话（Training Session） | 一次完整训练的生命周期单元，含选题快照、答题过程、结束小结 |
| 选题快照 | 组卷时记录的题目ID有序列表与五力权重参数，保障历史可复现 |
| 薄弱五力 | 学生五力得分低于薄弱阈值（默认65分）的维度 |
| 标注智能体 | 负责分析题目认知要求并输出五力标签及置信度的AI模块 |
| 向量化入库 | 将题目文本Embedding后存入向量数据库的过程 |
| RAG | 检索增强生成（Retrieval-Augmented Generation），通过检索向量库内容增强AI生成质量 |
| 双路召回 | RAG检索时同时检索题目解析库（路径1）和五力策略文档库（路径2） |
| 策略文档 | 预置于向量库中的五力解题方法论文档，用于RAG路径2检索 |
| 训练画像 | 基于训练答题数据更新的五力能力档案，与测试画像独立存储 |
| 降级策略 | AI服务不可用时，自动展示题目静态解析文本的兜底机制 |

### 1.5 前置依赖

- 学生必须已完成至少一次五力认知测试，存在有效的 `five_power_profiles` 记录，方可进入个性化训练模块
- 题库中各知识点可用已发布题目数量不低于5道，方可开放该知识点训练入口
- 向量数据库（Milvus 或 Chroma）已完成部署，五力策略文档已完成预置向量化

## 2. 应用场景

### 2.1 场景 S-01：学生首次进入个性化AI训练

**前置条件：**
- 学生已完成微信授权登录
- 学生已完成至少一次五力测试，存在有效的五力画像

**主流程：**
1. 学生进入小程序，点击「个性化AI训练」入口
2. 系统读取最新五力画像，在页面顶部展示当前得分最低的2个薄弱五力
3. 学生按「学科→年级→章节→知识点」四级目录选择训练知识点
4. 系统执行选题算法，生成5道（默认）专属训练题，创建训练会话（session_status=active）
5. 展示训练说明：题数、重点训练五力、知识点名称
6. 学生点击「开始训练」，进入第一道题答题界面
7. 学生逐题作答，每题提交后系统同步判题，答错触发RAG生成解题思路
8. 全部题目完成后，系统生成训练小结，展示本次训练数据
9. 训练结束后异步更新学生五力训练画像

**后置结果：**
- `training_sessions` 记录完整训练过程，`session_status=completed`
- `training_answer_records` 写入每题答题数据
- `five_power_training_profiles` 异步更新各五力训练得分

---

### 2.2 场景 S-02：学生答错后接收 RAG 解题思路

**前置条件：**
- 学生已提交某题答案且判题结果为错误
- 该题已完成向量化入库（`embedding_status=completed`）
- RAG 服务可用

**主流程：**
1. 系统同步返回判题结果"答错了"
2. 前端展示骨架屏占位，提示「AI正在从你的薄弱五力角度生成思路...」
3. 后台触发 Queue-C，执行双路RAG检索
4. 路径1：以题目文本检索向量库中相似题解析（TopK=3，过滤薄弱五力）
5. 路径2：以「薄弱五力+题型」检索策略文档库（TopK=2）
6. 两路结果合并注入大模型Prompt，生成200字以内的定向引导思路
7. 前端每3秒轮询，获取生成结果后替换骨架屏展示解题思路
8. 学生查看解题思路后，点击「有帮助」或「看不懂」反馈，系统记录至 `rag_feedback` 表

**分支流程：**
- RAG 生成超时（>8秒）：降级展示题目 `solution` 字段静态解析文本，并提示「AI助手暂时繁忙，展示参考解析」
- 向量库中无相关内容（相关性分数全部低于0.75）：直接以题目信息调用大模型生成，不注入检索结果

**后置结果：**
- `training_answer_records.rag_generated` 标记为 true
- `rag_feedback` 写入学生反馈（如有）

---

### 2.3 场景 S-03：内容管理员审核 AI 标注结果

**前置条件：**
- 题目已上传入库（status=draft 或 published）
- AI 标注任务已完成（`annotation_status=pending`）
- 操作者已以 CONTENT_ADMIN 或 SUPER_ADMIN 身份登录后台

**主流程：**
1. 操作者进入「AI标注审核工作台」
2. 系统展示待审核题目列表，默认筛选置信度 0.60~0.85 的题目
3. 操作者逐题查看题干和AI标注理由
4. 对标注合理的题目点击「确认」，`annotation_status=confirmed`
5. 对标注不合理的题目点击「修改」，从五力下拉选择正确标签后确认
6. 批量确认：勾选多道置信度 ≥ 0.85 的题目，点击「批量确认」
7. 确认后系统自动触发 Queue-B（向量化入库）

**分支流程：**
- 置信度 < 0.60 的题目：在「标注失败」列表单独展示，必须手动填写五力标签后强制确认

**后置结果：**
- `question_annotations.annotation_status = confirmed`
- `question_annotations.confirmed_primary_power` 写入最终确认的五力标签
- Queue-B 触发，题目进入向量化流程

---

### 2.4 场景 S-04：内容管理员新增五力策略文档

**前置条件：**
- 操作者已以 CONTENT_ADMIN 或 SUPER_ADMIN 身份登录后台

**主流程：**
1. 操作者进入「五力策略文档管理」
2. 点击「新增文档」，填写：文档标题 / 对应五力 / 适用场景标签 / 正文内容
3. 点击「预览效果」：输入测试题干，系统执行路径2检索，展示命中文档及相关性分数
4. 确认效果后点击「保存」，系统生成新版本号，触发向量化
5. 新文档向量化完成后，`is_active=true`，立即对后续RAG检索生效

**后置结果：**
- 新文档写入 `collection_strategies`，旧版本 `is_active=false` 保留

---

### 2.5 场景 S-05：学生通过「薄弱五力推荐」快速进入训练

**前置条件：**
- 学生已完成五力测试，存在薄弱五力（得分 < 65分）

**主流程：**
1. 学生点击首屏「按薄弱五力推荐」快速入口
2. 系统自动选择：题目最多 AND 覆盖薄弱五力最多的知识点
3. 跳过知识点选择步骤，直接展示已选知识点名称和训练说明
4. 学生确认后点击「开始训练」，流程同场景 S-01 步骤 6~9

**后置结果：**
- `training_sessions.source_type = recommended`

---

### 2.6 场景 S-06：机构管理员查看本机构训练数据

**前置条件：**
- 操作者已以 ORG_ADMIN 身份登录后台
- 本机构已有至少一名学生完成训练

**主流程：**
1. 操作者进入「训练数据看板」→「机构数据」
2. 系统仅返回本机构 org_id 下的训练数据（服务层强制过滤）
3. 查看概览：训练总次数 / 活跃学生数 / 各五力正确率分布
4. 查看各知识点热度排行（训练人次最多前10）
5. 查看本机构学生五力薄弱分布热力图
6. 按年级/班级筛选
7. 点击某学生查看该学生训练历史、各五力正确率趋势、常错知识点
8. 支持导出 Excel（学生ID / 训练次数 / 各五力正确率 / 最近训练时间）

**后置结果：**
- 导出操作写入审计日志

### 3.2 核心数据流

**主线一：题目入库 → 标注 → 向量化**

```
管理员上传题目
      ↓
题目写入 MySQL（status=draft）
      ↓
触发 Queue-A（题目标注）
      ↓
规则引擎 → 识别难度（基础/进阶/挑战）
大模型 API → 识别主五力 + 辅五力 + 置信度
      ↓
标注结果回写 question_annotations，等待人工确认
      ↓
管理员确认后 annotation_status=confirmed，触发 Queue-B
      ↓
题目文本 + 解析 → Embedding → 写入向量数据库
```

**主线二：学生答卷 → RAG 生成解题思路**

```
学生提交答案
      ↓
同步判题（≤1秒）→ 返回对错结果 → 记录本题五力类型
      ↓
答错（或按配置）→ 触发 Queue-C
      ↓
RAG 双路并行检索：
  路径1：以题目文本检索相似题解析（TopK=3，按薄弱五力过滤）
  路径2：以「薄弱五力+题型」检索策略文档（TopK=2）
      ↓
相关性分数过滤（阈值0.75）→ 两路结果合并注入 Prompt
      ↓
大模型生成定向解题引导思路（≤200字）
      ↓
写入 training_answer_records → 前端轮询获取 → 展示给学生
```

### 3.3 异步队列规格

| 队列编号 | 队列名称 | 触发条件 | 预期耗时 | 前端轮询策略 | 超时处理 |
|----------|----------|----------|----------|-------------|---------|
| Queue-A | 题目标注 | 题目上传写入MySQL后 | 3~10秒/题 | 管理员列表页标注状态自动刷新 | 标记annotation_status=failed，管理员手动重试 |
| Queue-B | 向量化入库 | 标注confirmed后 | 1~3秒/题 | 无需前端感知，后台静默执行 | 标记embedding_status=failed，系统告警 |
| Queue-C | RAG生成 | 学生提交答案后 | 3~8秒 | 每3秒轮询，最长8秒 | 降级展示静态解析，记录generation_status=failed |

## 4. 数据来源与题库建设

### 4.1 冷启动阶段（0~3个月）

采用**方案A+C混合启动**：购买结构化题库 + 收录公开考试真题。

| 来源 | 描述 | 优点 | 缺点 | 优先级 |
|------|------|------|------|--------|
| **A. 购买/授权结构化题库** | 从学科网、题库宝典等平台购买含题干/答案/解析/知识点分类的数据包 | 数据质量高，量大，开箱即用 | 版权成本高；五力标签需自行标注；格式需转换 | 主要来源 |
| **C. 公开考试真题** | 收录历年中考/高考/模拟卷真题（已进入公共领域） | 零版权风险，题目质量有保证，难度分布合理 | 需人工解析结构化处理；数量有限 | 补充来源 |

**冷启动目标题量：** 每学科每年级不低于 500 道，优先覆盖初三数学、高一物理、高一化学。

### 4.2 长期建设阶段（3个月后）

| 方式 | 机制 |
|------|------|
| 内容团队自建 | 专职内容编辑按知识点地图持续创作，每月新增配额制管理 |
| 教师贡献 | 合作教师上传题目，审核通过后计入贡献积分（换取平台功能权益） |
| 学生拍照上传 | 学生训练时拍照上传题目，经 OCR + AI 标注 + 人工审核后入库（TR-08，P1功能） |
| 变式题自动生成 | V1.1规划：大模型基于已有题目自动生成变式题，人工审核后发布 |

### 4.3 难度识别规则引擎

难度识别由规则引擎承担，不调用大模型，多维度加权打分后映射至三级难度。

| 规则维度 | 权重 | 基础 | 进阶 | 挑战 |
|----------|------|------|------|------|
| 知识点数量（单题涉及） | 30% | 1个 | 2个 | 3个及以上 |
| 解题步骤数（解析中） | 30% | ≤3步 | 4~6步 | ≥7步 |
| 题型 | 20% | 单选/填空 | 计算/证明 | 综合/开放题 |
| 历史答题正确率（冷启动后迭代） | 20% | ≥70% | 40~70% | <40% |

各维度权重可在后台配置；冷启动阶段历史正确率维度数据为空，该维度权重自动分配至其余三维。

## 5. 题目标注智能体

### 5.1 智能体职责边界

| 职责 | 是否由智能体承担 | 说明 |
|------|----------------|------|
| 识别题目主五力 | ✅ | 大模型分析认知要求 |
| 识别题目辅五力 | ✅ | 最多1个辅助五力 |
| 输出五力置信度 | ✅ | 用于分层人工审核 |

### 6.4 RAG 双路检索流程

```
触发条件：学生提交某题答案（答错必触发，答对可按配置触发）

输入上下文：
  - 当前题目（stem, solution, primary_power）
  - 学生薄弱五力列表（得分 < 65分，按得分升序取前2个）
  - 学生年级 + 学科

┌─────────────────────────────────────────┐
│              双路并行检索                 │
│                                         │
│  路径1：题目解析检索                     │
│  Query = 题目 stem 文本                  │
│  Filter：primary_power IN 薄弱五力列表   │
│           AND subject = 当前学科         │
│           AND is_active = true           │
│  TopK = 3（可配置）                      │
│  返回：相似题目解题过程文本               │
│                                         │
│  路径2：五力策略检索                     │
│  Query = "如何用{薄弱五力}解{题型}题"    │
│  Filter：power_type = 当前薄弱五力       │
│  TopK = 2（可配置）                      │

└─────────────────────────────────────────┘
      ↓
相关性分数过滤（低于阈值0.75的结果丢弃）
      ↓
合并两路结果，按相关性分数排序
      ↓
注入生成 Prompt
      ↓
大模型生成解题思路 → 写入 training_answer_records
前端每3秒轮询 → 展示给学生
```

### 7.2 个性化选题算法

**输入参数：**

| 参数 | 来源 | 说明 |
|------|------|------|
| student_id | 当前登录学生 | - |
| knowledge_point_id | 学生选择 | 目标知识点 |
| five_power_profile | five_power_profiles + five_power_training_profiles | 测试画像与训练画像综合 |
| recent_answered_question_ids | training_answer_records | 近N道已答题目ID（去重窗口默认30） |
| training_config | 后台配置当前生效版本 | 总题数、权重参数等 |

**选题算法步骤：**

```
Step 1：计算各五力选题权重
  基础权重：各五力均分20%
  薄弱加权：得分 < weak_power_threshold（默认65）的五力
            权重 += weak_power_weight_boost（默认0.30）
  归一化处理，确保总权重=100%

  示例（调适力58分，迁移力72分均低于65）：
  调适力 20%+30%=50% → 归一后≈38%
  迁移力 20%+15%=35% → 归一后≈27%
  其余三力各≈12%

Step 2：按权重 × 总题数（默认5题）计算各五力出题数
  取整后若总数不足，从权重最高的五力补充

Step 3：每个五力从题库筛选候选池
  条件：knowledge_point_id匹配 AND primary_power匹配
        AND status=published AND deleted_at IS NULL
        AND id NOT IN recent_answered_question_ids
  难度分层：基础50% / 进阶35% / 挑战15%（可配置）

Step 4：候选池不足时降级
  同五力同知识点不足 → 扩展至同章节其他知识点同五力题目
  仍不足 → 降级选取其他五力题目补充
  记录降级原因至训练会话快照

Step 5：生成训练会话快照
  question_ids有序列表 + 五力权重参数快照 + config_version_id
  写入 training_sessions（session_status=active）
```

```
读取本次各五力题目正确率

加权更新五力训练得分：
  训练得分 = 历史训练得分 × profile_decay_coefficient（默认0.70）
           + 本次正确率 × 100 × (1 - profile_decay_coefficient)
      ↓
更新 five_power_training_profiles 表
```

### 8.5 训练配置管理

**配置参数表：**

| 参数名 | 标识 | 默认值 | 范围 | 说明 |
|--------|------|--------|------|------|
| 单次训练题数 | `training_total_questions` | 5 | 3~20 | 每次训练生成的题目数量 |
| 薄弱五力权重加成 | `weak_power_weight_boost` | 0.30 | 0~0.5 | 得分低于阈值的五力额外权重 |
| 薄弱五力判定阈值 | `weak_power_threshold` | 65 | 0~100 | 低于此分视为薄弱五力 |
| 难度分层比例 | `difficulty_ratio` | 基础50%/进阶35%/挑战15% | 三项合计100% | 训练题目难度分布 |
| 近期去重窗口 | `dedup_window_size` | 30 | 10~100 | 选题时排除近N道已答题目 |
| RAG触发条件 | `rag_trigger_mode` | wrong_only | wrong_only / all / disabled | 控制RAG生成范围 |
| RAG检索TopK-题目 | `rag_topk_questions` | 3 | 1~5 | 路径1召回题目数量 |
| RAG检索TopK-策略 | `rag_topk_strategies` | 2 | 1~3 | 路径2召回策略文档数量 |
| RAG相关性阈值 | `rag_similarity_threshold` | 0.75 | 0.5~0.95 | 低于此分的结果丢弃 |
| AI降级超时时长 | `rag_timeout_seconds` | 8 | 3~30 | 超时后降级展示静态解析（秒） |
| 训练画像衰减系数 | `profile_decay_coefficient` | 0.70 | 0.5~0.9 | 历史训练分权重 |

**配置版本管理规则：**
- 每次保存生成递增版本号（v1, v2...），历史版本只读保留
- 同一时刻只允许一个生效版本（is_active=true）
- 新建训练会话始终读取最新生效版本
- 训练会话快照记录对应 config_version_id，历史可追溯

**验收标准：**

- AC-8.5-01：Given 管理员修改难度分层比例三项之和不等于100%，When 点击「保存并生效」，Then 系统阻止保存并提示「难度比例合计必须等于100%，当前为X%」
- AC-8.5-02：Given 管理员保存新配置版本，When 系统写入成功，Then 旧版本is_active变为false，新版本is_active为true，后续新建训练会话使用新版本参数

## 10. 错误码与异常处理

### 10.1 客户端错误码（4xx）

| 错误码 | HTTP状态 | 标识 | 描述 | 用户提示 |
|--------|----------|------|------|----------|
| ERR-TR-001 | 403 | NO_FIVE_POWER_PROFILE | 学生未完成五力测试，无法进入训练 | 「请先完成五力测试，系统才能为你生成专属训练」 |
| ERR-TR-002 | 400 | KNOWLEDGE_POINT_DISABLED | 目标知识点已禁用 | 「该知识点暂不可用，请选择其他知识点」 |
| ERR-TR-003 | 400 | QUESTION_POOL_TOO_SMALL | 知识点可用题目不足5道 | 「该知识点题目建设中，暂不支持训练」 |
| ERR-TR-004 | 400 | SESSION_ALREADY_COMPLETED | 尝试重复提交已完成的训练会话 | 「本次训练已完成，请开始新训练」 |
| ERR-TR-005 | 400 | ANSWER_ALREADY_SUBMITTED | 该题答案已提交 | 「该题已作答，请进行下一题」 |
| ERR-TR-006 | 400 | ANNOTATION_BATCH_INVALID | 批量确认包含置信度<0.85的题目 | 「批量确认仅支持置信度≥0.85的题目，请单独确认低置信度题目」 |
| ERR-TR-007 | 403 | PERMISSION_DENIED | 无权访问目标数据 | 「无权访问该数据」 |

### 10.2 服务端错误码（5xx）

| 错误码 | HTTP状态 | 标识 | 描述 | 用户提示 |
|--------|----------|------|------|----------|
| ERR-TR-101 | 503 | ANNOTATION_SERVICE_UNAVAILABLE | 大模型API不可用，标注任务失败 | 管理员端：「AI标注服务暂时不可用，题目已保存，可稍后重新触发标注」 |
| ERR-TR-102 | 504 | RAG_GENERATION_TIMEOUT | RAG生成超时（>8秒） | 「AI助手暂时繁忙，为你展示参考解析」（降级处理） |
| ERR-TR-103 | 503 | VECTOR_DB_UNAVAILABLE | 向量数据库不可用 | 降级：直接展示静态解析，记录generation_status=degraded |
| ERR-TR-104 | 503 | EMBEDDING_SERVICE_FAILED | 向量化入库失败 | 系统内部告警，管理员无感知，支持手动重触发 |
| ERR-TR-105 | 500 | SCORING_FAILED | 判题过程异常 | 「答案提交遇到问题，请重试」 |
| ERR-TR-106 | 500 | PROFILE_UPDATE_FAILED | 训练画像更新失败 | 异步静默失败，系统告警，不影响用户感知 |

### 10.3 异步任务失败重试策略

| 队列 | 最大重试次数 | 重试间隔 | 最终失败处理 |
|------|------------|----------|------------|
| Queue-A（题目标注） | 3次 | 10秒间隔 | annotation_status=failed，管理员工作台显示，支持手动重触发 |
| Queue-B（向量化入库） | 3次 | 15秒间隔 | embedding_status=failed，系统告警，支持手动重触发 |
| Queue-C（RAG生成） | 2次 | 5秒间隔 | generation_status=failed，降级展示静态解析 |
