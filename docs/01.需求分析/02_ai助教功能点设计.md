### 0.3 术语表

| 术语 | 定义 | 说明 |
|------|------|------|
| **五力** | 洞察力、建构力、推演力、调适力、迁移力 | 本产品核心认知能力评估维度 |
| **洞察力** | 从题目条件中提取关键信息、识别隐含关系的能力 | 如：识别题目中的已知量与未知量 |
| **建构力** | 将离散知识点组合为解题模型或知识结构的能力 | 如：构建方程组 |

| **调适力** | 在遇到障碍时调整策略、容错纠偏的能力 | 如：发现解题路径不通后切换方法 |
| **迁移力** | 将已学知识应用到新情境、跨题型的能力 | 如：将公式迁移应用到新题型 |
| **知识点** | 课程体系中最小的可独立训练的学科概念单元 | 按学科-年级-章节-知识点四级编码管理 |

| **五边形雷达图** | 以五力为维度的可视化图表 | 满分100分/维度，历次结果可叠加对比 |
| **Token** | AI大模型API的计量单位 | 约4个英文字符或1.5个中文字符 |
| **P0** | 优先级最高，MVP必须完成的功能 | 若缺失，产品无法上线 |
| **P1** | 优先级次高，V1.0应完成的功能 | 影响体验但不阻断核心流程 |
| **P2** | 优先级较低，V1.1或V2.0完成的功能 | 锦上添花型功能 |
| **五力画像** | 学生完成测试后系统生成的个人认知能力报告 | 含各维度得分、训练方向建议 |

## 第1章 全局视图

### 1.1 产品概述

#### 1.1.1 产品定位与核心价值主张

**产品定位**：面向初一至高三学生的数理化智能自适应练习平台，通过认知能力诊断驱动个性化训练，提供"专属AI老师"体验。

**核心价值差异化**：

| 价值维度 | 传统刷题工具 | 本产品 |
|----------|-------------|--------|
| 诊断深度 | 知识点掌握情况 | 认知能力（五力）薄弱项 |
| 训练逻辑 | 题量堆砌 | 认知能力针对性训练 |
| AI介入时机 | 全程或解题后 | 按五力目标定向介入 |
| 学习反馈 | 正确率/错题集 | 五力成长对比/能力画像变化 |

#### 1.1.2 适用范围

**年级**：初一（七年级）至高三（十二年级），共6个年级。初期内容建设优先覆盖初三和高一。

| 学科 | V1.0覆盖范围 | 不覆盖内容 |
|------|-------------|-----------|
| 数学 | 初中数学全册、高中数学必修1-5 | 高中选修模块 |
| 物理 | 初中物理全册、高中物理必修1-3 | 高中选考物理 |
| 化学 | 初中化学全册、高中化学必修1-2 | 高中选考化学 |

#### 1.1.3 产品愿景与V1.0目标

**愿景**：让每一位中学生都能获得一位了解自己认知特点的数理化专属AI教练。

**V1.0目标**：
1. 验证核心假设：五力认知模型能有效区分不同学生的学习薄弱点
2. 完成核心验收链路：注册 → 五力测试 → 生成画像与训练方案 → 进入知识点训练 → AI定向指导 → 保存结果 → 对比成长
3. 积累种子用户数据：目标首批500名真实学生用户完成完整学习闭环

### 1.3 系统架构全景

#### 1.3.1 五大模块关系说明

**模块一：五力认知系统** — 整个产品的"诊断入口"，学生首次使用时完成五力测试，生成五力画像驱动后续所有模块。

**模块二：数理化题库** — 整个产品的"内容底座"，为每道题标注三个维度标签：学科-年级-知识点（位置标签）、五力维度（能力标签）、难度系数（深度标签）。

**模块三：个性化AI训练系统** — V1.0核心功能模块，连接"五力数据"与"题库内容"，驱动个性化选题与AI定向指导。

**模块四：学习记录与反馈** — 整个系统的"数据沉淀层"，接收训练数据，聚合生成学习报告。

**模块五：管理后台** — 产品的"运营控制台"，覆盖其他四个模块的内容维护和参数配置。

#### 1.3.2 核心数据流转路径

```
[学生完成五力测试]
        ↓
[模块一] 生成五力画像（五个维度得分 + 强弱排序 + 薄弱项标识）
        ↓
[模块三] 接收五力画像 + 学生选定知识点
        ↓
[模块二] 按「知识点编码 × 五力薄弱维度」双标签检索题目
        ↓
[模块三] 展示题目 → 学生作答 → AI按五力目标给出定向指导
        ↓
[模块四] 记录答题结果 + AI交互内容 + 时长数据
        ↓
[模块四] 聚合生成学习报告 → 学生/家长/教师查看
        ↓
[学生再次完成五力测试] → 对比五力成长变化（闭环）
```

#### 1.3.3 第三方依赖清单

| 依赖项 | 用途 | 风险评估 | 备选方案 |
|--------|------|----------|----------|
| AI大模型API | 训练过程中的AI定向指导 | 高：服务稳定性和成本是核心风险 | 支持多家供应商切换；建立降级策略 |
| OCR多模态API | 识别学生拍照上传的题目 | 中：识别准确率影响体验 | V1.0限制印刷体；提供手动输入兜底 |
| 短信/邮件服务 | 注册验证码、提醒推送 | 低 | 国内备选运营商 |
| 对象存储服务 | 存储图片、PDF报告 | 低 | 多云备份策略 |

### 1.4 用户旅程全景地图

#### 1.4.1 学生端端到端旅程

| 旅程阶段 | 用户行为 | 用户情绪 | 系统关键动作 |
|----------|----------|----------|-------------|
| 注册登录 | 输入手机号、验证码、设置年级 | 中性/轻微期待 | 验证手机号，初始化用户档案 |
| 完成五力测试 | 完成约20题诊断测试，约15~20分钟 | 专注/轻微焦虑 | 计时、记录答题行为 |
| 查看五力画像 | 查看雷达图、各维度得分 | **高兴奋/顿悟感**（关键时刻#1） | 生成雷达图、薄弱项解读、推荐训练方向 |
| 选择知识点训练 | 选择当前想练的知识点，开始训练 | 期待/挑战感 | 按知识点×五力短板检索题目 |
| AI辅助指导 | 遇到困难时触发AI提示，与AI交互 | **被理解感/获得感**（关键时刻#2） | 按五力训练目标生成定向提示 |
| 完成训练 | 查看本次训练结果 | 满足感/成就感 | 生成训练小结 |
| 再次五力测试 | 完成新一轮五力测试 | 紧张/期待 | 对比新旧画像 |
| 查看成长对比 | 查看两次五力雷达图叠加对比 | **成就感/自信感**（关键时刻#3） | 生成对比雷达图、成长分析 |

#### 1.4.2 关键时刻识别

**关键时刻#1：首次查看五力画像** — 产品核心价值认知的关键时刻，雷达图需视觉震撼，薄弱项描述需具体有共鸣。

**关键时刻#2：首次AI指导体验** — 决定学生是否认可AI作为学习伙伴，AI指导必须与五力训练目标一致，有温度。

**关键时刻#3：首次五力成长对比** — 产品价值的最终验证时刻，需视觉差异明显，量化表达变化。

**五力维度代码**：INSIGHT / CONSTRUCT / DEDUCE / ADAPT / TRANSFER

#### 1.6.2 Token使用全局策略

**何时调用AI**：学生主动请求提示 / 学生连续答错2次 / 训练结束总结 / 五力画像文字解读

**何时不调用AI**：学生浏览题目未作答 / 学生首次作答正确 / 选择题错误（使用预置解析）/ AI响应超5秒时降级

**单次上下文范围**：
```
系统Prompt（角色设定+五力目标）    ≈ 500 Token
题目内容+学生答案                  ≈ 200~400 Token
历史对话（最多保留3轮）            ≈ 0~600 Token
五力画像摘要                       ≈ 100 Token
────────────────────────────────────────────────
单次输入上限                       ≈ 1500 Token
输出上限                           ≈ 800 Token
```

#### 1.6.3 【建议新增】数据安全与隐私保护基线

| 法规 | 核心要求 | 产品落地措施 |
|------|----------|-------------|
| 《个人信息保护法》 | 处理未成年人个人信息须取得监护人同意 | 18岁以下用户须填写家长手机号并完成家长确认 |
| 《未成年人保护法》 | 不得向未成年人推送影响身心健康的信息 | 产品内无广告，无游戏化激励（仅正向学习反馈） |
| 《数据安全法》 | 重要数据分级保护 | 学生学习数据、五力画像加密存储 |

**最小数据采集原则**：不采集地理位置、不持续采集摄像头权限、不采集社交关系数据。用户注销后30天内完全清除AI交互记录。

## 第2章 模块一：五力认知系统

> 旅程片段定位：用户旅程起点——建立认知基准，驱动后续所有个性化逻辑

### 2.1 功能清单

| 功能ID | 功能名称 | 功能描述 | 优先级 | 备注 |
|--------|----------|----------|--------|------|
| F-01 | 学生注册与账号创建 | 通过手机号/邮箱完成注册，填写年级、科目偏好，系统生成唯一学生ID | P0 | 支持家长账号关联（预留字段） |

### 2.4 交互流程

#### 2.4.1 五力测试主流程

**正常流程**：
```
[首次登录] → [认知档案初始化] → [引导弹窗]（开始测试/稍后测试）
→ [加载题目列表] → [逐题作答]（进度条+计时器+上一题/下一题）
→ [提交确认弹窗] → [提交中] → [计算中（≤3秒动画）] → [结果展示页]
```

**中断恢复流程**：
```
[用户退出App] → 系统保存progress → session_status="已中断"
[用户重新打开] → 检测到中断session → 弹出恢复提示
→ [继续测试]：从断点题目继续，答案保留，计时续计
→ [重新开始]：当前session作废，创建新session
```

**网络异常处理**：
```
[网络断开] → 页面顶部显示离线提示条，答题继续
→ 答案写入本地缓存 → [网络恢复] → 静默同步 → 提示条消失
```

#### 2.4.2 雷达图展示交互规则

**刻度定义**（五档，可配置）：

| 刻度档 | 分值区间 | 说明 |
|--------|----------|------|
| 第1档 | 0-20 | 基础薄弱 |
| 第2档 | 21-40 | 初步形成 |
| 第3档 | 41-60 | 基本掌握 |
| 第4档 | 61-80 | 较为扎实 |
| 第5档 | 81-100 | 熟练运用 |

**点击顶点交互**：触发底部抽屉（Bottom Sheet），展示该力名称、得分、等级、能力描述和改善建议（50~100字）。

**历史对比模式**：点击"与历史对比"，选择一条历史记录，雷达图切换为双色叠加模式（蓝色=历史，橙色=本次）。

#### 2.4.3 训练方案生成规则（参数可配置）

```json
// algo_config.json 示例
{
  "primary_focus_threshold": 50,      // 低于此值 → 重点强化项

  "algo_version": "v1.0.0"

```

#### 2.5.2 性能验收标准

| 指标 | 目标值 | 测量场景 |
|------|--------|----------|
| 测试题目加载时间 | ≤3秒（4G网络） | 点击"开始测试"到第一题显示 |

#### 2.5.3 数据准确性验收标准

- 五力得分计算准确性：误差为零（整数分值），小数精度误差≤0.01

### 2.6 用户旅程片段

#### 2.6.1 情绪曲线

| 阶段 | 情绪值 | 关键描述 | 设计应对 |
|------|--------|----------|----------|
| 注册/看到测试引导 | 45/100 | "又要做测试？" 轻微抵触 | 强调"帮助系统了解你"而非"测试评估你" |
| 答题前期（1-5题） | 65/100 | 逐渐投入，进入心流 | 进度条让终点感知明确 |
| 答题中期（8-14题） | 40/100 | 疲倦与动摇，最大低谷 | 50%进度显示鼓励文案+预计剩余时长 |
| 答题后期（15题+） | 65/100 | 看到终点，坚持冲刺 | "最后5题"提示加速完成欲望 |
| 等待计算结果（3秒） | 60/100 | 最紧绷时刻 | 动画+文案告知进度 |
| **拿到雷达图** | **90/100** | **情绪峰值：惊喜与满足** | **动画+个性化评价+训练方向** |

#### 2.6.2 痛点与设计应对

**痛点一：测试题目过多，学生中途放弃**
- 设计策略：进度条始终可见；完成25%/50%/75%时显示鼓励文案；明确告知"退出后可从此处继续"降低沉没成本

**痛点二：不理解测试目的，敷衍作答**
- 设计策略：引导页用利益说明"真实作答才能帮系统了解你"；后台监控单题耗时过短的答案打低可信度标签

**痛点三：拿到结果后不知道如何行动**
- 设计策略：结果页直接展示训练方案摘要，配"开始今日训练"主操作按钮；训练方案语言具体化

#### 2.6.3 成功时刻设计（峰值体验）

**视觉层**：雷达图以从中心向外扩展的动画进入（1.5秒），各顶点数字以"滚动计数"显示（0→最终值），高分顶点旁显示小星形徽章。

**文案层**：综合评价文字以"首先肯定优势"开头，再提改善方向，避免一上来打击信心。

**互动层**：点击任意顶点查看详情，延长在结果页停留时间；提供"分享图谱"功能（含隐私模式）；底部自动上浮训练方案卡片引导下一步。

#### 3.5.2 数据完整性验收标准

- 多维筛选（最多5个维度组合）响应时间：P95 ≤1.5秒

### 4.2 用户故事

**US-301 学生进入知识点开始个性化训练**
- 作为初中生，我希望选择"一元二次方程"后系统能直接为我推送适合我的题目，以便不需要自己手动筛选。
- 验收标准：
  - Given 学生五力测试已完成且调适力得分为三项最低 When 学生选择知识点并点击"开始训练" Then 系统在3秒内完成选题并展示第一道题目，选题参数快照中"调适力权重"应高于其他四力
  - Given 学生从未训练过该知识点 When 进入知识点 Then 系统以难度系数0.4（中低难度）作为起始基准
  - Given 学生已对该知识点完成过3次训练 When 再次进入 Then 系统优先排除已答对率≥2次的题目

**US-302 系统推送调适力薄弱相关题目（选题逻辑示例）**
- 选题逻辑示例：学生调适力45分（最低）→ 调适力题目权重55%，推演力25%，其余各7% → 候选池30道题中调适力12道 → 按难度0.5~0.65区间筛选 → 排除近7日已答题目 → 选出最终题目
- 验收标准：
  - Given 调适力为得分最低五力 When 系统执行选题算法 Then 选出题目的主训练维度应与当前训练重点吻合，可通过选题参数快照验证
  - Given 学生在某知识点近5题正确率低于40% When 系统选题 Then 自动将难度系数下调0.1~0.15
  - Given 候选题池中调适力题目不足3道 When 系统选题 Then 降级选取推演力题目，并在快照中记录降级原因

**US-303 学生答错后触发AI指导（按五力目标定向引导）**
- 作为学生，我希望答错后AI能有针对性地引导我找到错误，而不是直接告诉我答案。
- 验收标准：
  - Given 本题主训练维度为"推演力" When 学生提交错误答案 Then AI首条回复包含"你在第几步的推导出现了问题？"类型的追问，不得直接展示正确推导过程
  - Given 本题主训练维度为"调适力" When 学生提交错误答案 Then AI引导语聚焦于"你发现自己哪里走错了？如果换一条路，你会怎么重新开始？"
  - Given 学生与AI已进行3轮以上对话仍未解出 When 对话轮次≥3 Then AI提示"我们来看一个关键步骤"，给出最小必要脚手架提示，而非完整答案

**US-304 学生主动请求提示**
- 验收标准：
  - Given 学生点击"提示"按钮（一级） When 系统响应 Then 展示方向性提示，一级提示不消耗AI Token
  - Given 学生已解锁一级提示且再次点击"提示" When 等待时间不足30秒 Then 提示"再想想，你刚刚看到了什么信息？"

**US-305 学生通过文字输入自主提问题库外问题**
- 验收标准：
  - Given 学生输入"为什么氯化钠溶液能导电而蔗糖溶液不能" When 点击提交 Then 1秒内完成学科识别（化学）并进入AI辅助流程
  - Given 学生输入内容学科识别置信度低于60% When 系统判断不确定 Then 展示学科选择弹窗由学生确认

**US-306 【建议新增】拍照上传题目并识别**
- 验收标准：
  - Given 学生上传包含数学公式和文字的题目图片 When OCR识别完成 Then 识别结果在可编辑文本框中展示，LaTeX公式还原率≥85%，完成时间≤5秒
  - Given OCR识别结果置信度低 When 系统检测到 Then 提示"识别结果可能有误，请检查后再提交"，高亮低置信度区域

**US-307 学生完成一次训练查看小结**
- 验收标准：
  - Given 学生完成5道题的训练 When 点击"结束训练" Then 小结页在3秒内生成，包含：答题数量、整体正确率、本次重点训练五力、AI指导触发次数、与上次训练的对比
  - Given 本次训练调适力题目正确率较上次提升≥15% When 小结展示 Then 高亮标注该项提升并展示激励文案

**US-308 AI服务不可用时的降级体验**
- 验收标准：
  - Given AI服务连接超时（超过8秒） When 学生等待AI指导 Then 系统自动降级为规则提示，展示"AI助手暂时繁忙，为你展示参考提示"
  - Given 学生处于自主提问界面且AI不可用 When 学生提交问题 Then 系统询问"是否保存问题，等AI恢复后回答？"

### 4.4 交互流程

#### 4.4.1 知识点进入与选题主流程

```
[学生点击"开始训练"]
→ [读取学生最新五力得分快照]
→ [计算五力训练权重：最低得分五力55% / 第二低25% / 其余各7%]
→ [构建选题参数：知识点+五力权重+难度区间+已排除题目]
→ [查询候选题池（候选池<3道时放宽排除条件）]
→ [按权重随机选题，记录选题参数快照]
→ [渲染题目（LaTeX公式渲染+图片加载+提示按钮重置）]
→ [展示题目，等待学生作答]
```

**难度动态调整规则**：
- 近3题正确率≥80%：难度系数上调0.1（不超过上限1.0）
- 近3题正确率≤40%：难度系数下调0.1（不低于下限0.1）
- 其余情况：保持当前难度区间

#### 4.4.2 AI指导触发与对话流程

**触发条件**（满足任一即触发）：
- 学生提交答案且答案判断为错误
- 学生在题目页面停留超过120秒且未作答
- 学生主动点击"请AI指导"按钮
- 学生在对话区发起追问

**发送给AI的上下文结构**：
```json
{
  "student_five_force": {"insight":80,"construct":75,"deduce":70,"adapt":45,"transfer":65},
  "subject": "chemistry",
  "knowledge_point": "氧化还原反应",
  "question_content": "题目完整文本",
  "question_force_label": "adapt",
  "training_goal": "帮助学生识别推导错误节点并自主修正",
  "student_answer": "学生提交的答案原文",
  "hint_level_used": 0,
  "conversation_history": ["...上一轮对话摘要..."]
}
```

**AI输出规范（System Prompt约束）**：
- 禁止直接输出完整正确答案
- 每次回复必须以追问或任务结束
- 回复字数控制在150字以内
- 按五力目标的指导话语模板：
  - 洞察力：「题目中哪些条件你还没有用到？」
  - 建构力：「这道题的物理/化学模型应该是什么样子的？」
  - 推演力：「你的第X步是怎么推导出来的？」
  - 调适力：「你发现哪里走错了？如果重新出发，你会从哪一步开始？」
  - 迁移力：「如果把这个题的条件换成…，你的思路会变吗？」

**对话流程**：
```
[AI触发] → [构建上下文JSON] → [调用AI API（流式输出）]
→ [AI对话区展示流式文字，逐字渲染]
→ [学生可打断输入追问，追问追加到conversation_history]
→ [对话轮次计数+1，记录至ai_conversation_logs]
→ [轮次≥3且仍未解出] → [AI给出最小脚手架提示]
→ [学生提交正确答案或选择"看答案"] → [结束对话，保存记录]
```

#### 4.4.3 学生自主提问流程

**路径一：文字输入**

**路径二：【建议新增】拍照上传识别**

| AC-F10 | AI服务响应超时超过8秒 | 学生等待AI回复 | 系统自动展示预置规则提示，展示"AI助手暂时繁忙" |

#### 4.5.2 AI响应质量验收标准

- **不直接给出完整答案**：抽取100条AI回复，两名评审员判定，不包含完整答案的回复比例≥95%
- **响应时间**：首字符出现时间（流式）≤3秒；完整回复完成时间≤8秒（超过视为超时触发降级）
- **引导性话语评估**：每次AI回复结尾必须包含开放性问题或任务；追问内容应与当前错误点直接相关；与题目主训练五力标签匹配

#### 4.5.3 选题算法验收标准

- **五力匹配度**：构造5个不同五力分布的测试账号，各进行30道题训练，验证主训练五力为当前最低五力的选题比例≥50%（允许±5%偏差）
- **题目不重复**：同一题目在同一知识点下，7日内不得重复推送；排除后候选池不足时，放宽至仅排除当日已答题目
- **难度适配**：连续答对测试用例验证难度系数在答题记录中的变化趋势符合规则

#### 4.5.4 Token消耗准确性验收标准

- 记录的tokens_total与AI API返回的usage字段数据一致，误差为0
- 每次AI调用完成后，Token消耗数据在500ms内写入token_usage_logs
- 阈值触发测试：人工模拟消耗至70%/90%/100%阈值，验证系统在阈值触发后1次请求内切换降级层级

### 4.6 用户旅程片段

#### 4.6.1 情绪曲线

| 阶段 | 情绪值 | 关键描述 | 设计应对 |
|------|--------|----------|----------|
| 进入知识点 | 50/100 | 期待+轻微紧张 | 展示"本次主练：调适力"降低不确定性焦虑 |
| 第一题顺利 | 65/100 | 逐渐投入 | |
| 连续答错（低谷） | 30/100 | 挫败感，怀疑自己 | AI语气调整为鼓励性；系统自动下调难度制造"小赢"机会 |
| **AI引导下独立解出（峰值）** | **90/100** | **满足感、被理解感** | **AI确认归功于学生；标记"AI引导下独立解出"；过渡语连接下一题** |
| 训练结束小结 | 70/100 | 获得量化成就感 | 用视觉化呈现提升幅度；激励文案引用当次数据 |

#### 4.6.2 关键时刻：AI首次成功引导

当学生第一次通过AI引导而不是看答案独立解出题目时，这是整个产品的峰值体验时刻。

**设计要点**：
1. **结果确认的仪式感**：1秒轻微粒子动效配合AI的"对了！"确认语
2. **归因于学生自身努力**：AI确认语必须将功劳归于学生——"你刚才找到了问题的关键——"
3. **标记可见的成长**：该题记录为"AI引导下独立解出"，与"看答案"明确区分
4. **即时连续性**：下一题推送带有温和过渡语，而非冷冰冰直接切换

#### 4.6.3 痛点与设计应对

| 痛点 | 具体场景 | 设计应对方案 |
|------|----------|--------------|
| AI响应慢 | 等待AI超过3秒，焦虑感上升，可能重复点击 | 提交后立即锁定按钮，展示"AI正在思考中…"打字动画；8秒超时自动降级 |
| AI直接给出答案 | AI回复包含完整解题步骤，学生直接抄答案 | System Prompt硬约束+回复质量抽样监控+每月人工抽检100条日志 |
| 题目难度不适配 | 连续过难或过易，学生感到无聊或挫败 | 动态难度调整算法（近3题正确率实时计算）+学生主动标记双轨校正 |
| Token耗尽 | 中度降级时追问功能关闭，体验断裂 | 降级前提前预警（达80%时提示）；降级后用更清晰的规则提示补位；每日00:00自动恢复 |

#### 4.6.4 训练结束时的即时反馈设计

1. **数据要有对比**：展示"调适力正确率40%，比上次提升15%"而非孤立数字
2. **激励文案个性化**：根据本次数据动态生成，调适力进步则说"你的纠错能力在成长"
3. **下一步方向明确**：底部给出一个具体行动建议（不超过一句话），让学生知道下一步怎么走
4. **退出路径清晰不催促**：提供"再练一组"和"返回首页"，不弹出留存弹窗，不设倒计时
5. **成就标记可累积**：小结中的标记可在个人成长记录中查看历史，让每次训练都成为可追溯的里程碑

### 5.2 用户故事

### 5.4 交互流程

#### 5.4.1 训练数据自动记录流程

**触发时机**：学生点击"结束训练" / 完成预设题数 / 关闭页面或切换后台超过10分钟（is_completed=false）

**写入顺序**：
```
[训练结束事件触发]
→ [前端汇总本次会话数据，计算duration_seconds（过滤单题超5分钟空置段）]
→ [写入 learning_summaries 表]
→ [更新 knowledge_mastery 表（掌握度状态和连续答对计数）]
→ [检查本次答错题目] → [写入/更新 error_notebook 表]
→ [更新 power_training_stats 表（按五力维度累加当日数据）]
→ [写入完成] → [前端跳转训练结果页]
```

**失败重试机制**：前端在写入前将本次训练数据存入localStorage；网络请求失败时最多自动重试3次（每次间隔2秒）；3次重试均失败后数据保留在localStorage，下次打开应用时触发补传。

#### 5.4.2 学习报告页交互规则

| 区块名称 | 数据来源 | 查询逻辑 |
|----------|----------|----------|
| 学习时长 | learning_summaries | SUM(duration_seconds) WHERE 时间范围 |
| 训练天数 | learning_summaries | COUNT(DISTINCT training_date) WHERE 时间范围 |
| 做题情况 | learning_summaries | SUM/GROUP BY subject或knowledge_point_id |
| 五力分布 | power_training_stats | SUM(question_count) GROUP BY power_type |
| 知识点进度 | knowledge_mastery | 按mastery_status统计各状态数量 |

**时间维度切换**：提供"今日/本周/本月"三个Tab，默认选中"本周"；切换时各区块显示骨架屏，数据返回后渐入展示。

**空态展示规则**：所选时间维度内无训练记录时，展示空态插图和引导文案，不显示0值数据。

#### 5.4.3 错题本使用流程

```
[训练答错] → [训练结束时写入error_notebook，状态=pending_review]
→ [学生进入错题本] → [默认展示"待复习"状态错题，按答错时间倒序]
→ [点击某错题] → [进入错题详情页（原题/错误答案高亮/正确答案/AI解析）]
→ [点击"重新作答"] → [进入单题作答模式]
→ 答错 → 显示"还需继续练习"，retry_count+1
→ 答对 → 弹出确认弹窗"掌握了吗？"
  → 确认 → error_status=mastered，从"待复习"移出
  → 暂不标记 → 关闭弹窗，保持pending_review
```

#### 5.4.4 五力成长对比交互

```
[进入"五力成长"页面]

→ [点击"换一次测试对比"] → [弹出历史测试列表] → [学生选择] → [雷达图重新渲染]
→ [页面底部展示"下一阶段训练建议"（得分提升最少的1-2个维度+针对性训练入口）]
```

### 5.5 验收标准

#### 5.5.1 功能验收标准

| # | Given | When | Then |
|---|-------|------|------|
| AC-501 | 学生正常完成一次含5题的训练 | 点击"结束训练" | learning_summaries表中新增记录，所有必填字段均有值，is_completed=true |

| AC-505 | 学生在训练中答错2道题 | 训练结束后进入错题本 | 2道错题均出现在"待复习"列表，学科、知识点标签正确 |

| AC-508 | 学生已完成3次五力测试 | 进入"五力成长对比"页选择第1次和第3次 | 雷达图正确展示两次得分，蓝色对应第1次，橙色对应第3次，数据与原始记录一致 |
| AC-509 | 对比两次测试后，调适力维度得分提升最小 | 页面渲染完成 | 底部"下一阶段训练建议"明确指出调适力，并提供"针对性训练"入口 |
| AC-510 | 新用户注册后未完成任何训练 | 进入学习报告页 | 展示空态插图和引导文案，不显示任何0值数据 |
| AC-511 | 学生点击"分享成果" | 系统生成分享图和分享链接 | 链接有效期30天，分享快照为生成时的静态数据 |
| AC-512 | 学生点击双色雷达图某顶点 | 触发点击 | 底部抽屉正确显示两次得分、提升幅度、本阶段题数，展开动画≤300ms |

#### 5.5.2 数据记录完整性验收标准

- 建立题目作答明细表与learning_summaries汇总表的自动对账任务（每小时运行），差异超过1题时触发告警
- 前端在训练开始时生成session_id存入localStorage，收到服务端确认后才清除；未获确认则在24小时内主动补传
- 监控"已写入汇总表的session数/已创建session数"比率，低于99%时触发P2级别告警

#### 5.5.3 报告数据准确性验收标准

- 时长准确性：手动计时与系统记录对比，误差不超过60秒（单次训练）
- 正确率准确性：accuracy_rate = correct_count/total_questions × 100，精确到小数点后两位，误差为0
- 五力统计准确性：各维度题数之和等于同一时间范围内total_questions之和，误差为0
- 知识点状态准确性：mastery_status变更在触发条件满足后5秒内完成更新

### 5.6 用户旅程片段

#### 5.6.1 情绪曲线

| 阶段 | 情绪 | 设计重点 |
|------|------|----------|
| 新用户注册后第一次进入学习报告（空态） | 期待：我知道怎么开始了 | 空态引导清晰，有明确行动入口 |
| 训练3-7天后首次看到有数据的报告 | 正向惊喜：我做到了这么多 | 本周数据具体化（天数/题数/正确率） |
| **第一次重测五力并看到对比图** | **情绪峰值：我真的在进步** | **双色雷达图视觉冲击；量化表达变化幅度** |
| 分享成果时刻 | 二次高峰：外部认可 | 社交分享带来额外情绪正向 |

#### 5.6.2 关键时刻：首次看到成长数据的峰值体验设计

1. **视觉先行，数字强化**：雷达图进入时先展示蓝色基准图（停顿0.3秒），再渐入橙色当前图（让学生有意识感受"这是我的成长"）
2. **用自然语言描述数字变化**：不只放数字，展示"与上次相比，你的推演力提升了18分，进步最明显。"
3. **成就感要即时兑现**：某维度提升超过10分时，在顶点附近显示小徽章图标
4. **给下一步明确方向**："下一阶段训练建议"必须在同一屏幕可见，内容要具体指明哪个维度

#### 5.6.3 家长查看报告的转化设计点

家长查看报告本质上是回答两个问题：「孩子有在用吗？」和「用了有没有效？」

1. **"有在用"的信号放在首屏顶部**：展示"本月训练天数：18天/31天，连续训练中"配日历打卡图
2. **"有没有效"用五力对比说话**：雷达图对比必须在首屏或第一次滚动后可见
3. **一句AI评语降低理解门槛**：用日常语言转译——"本月孩子在解题逻辑分析能力上进步显著"
4. **续费/推荐行动引导**：展示"下一阶段重点训练计划已生成"旁附"分享给朋友"按钮（裂变入口）

#### 5.6.4 空态设计与激励引导

| 场景 | 设计策略 |
|------|----------|
| 新用户空态（未完成任何训练） | 展示种子插图+"你的学习数据花园正在等待种下第一颗种子"；主按钮"开始我的第一次训练" |
| 已完成五力测试但尚未训练 | 展示灰色填充雷达图（标注"你的起点"）+"这是你今天的五力基准，开始训练，见证成长" |
| 长期未训练（超过14天） | 橙色提示条（非全屏弹窗）："你已有X天未训练，上次学到了[知识点名称]，要继续吗？"提供继续训练和稍后提醒两个选项 |
| 某学科尚未训练 | 在对应学科区块显示局部空态："你还没有物理训练记录。" + 去练物理快捷入口 |

**空态设计原则**：目标不是展示"没有数据"，而是为下一步行动提供清晰入口；所有空态页面必须包含至少一个可点击的行动入口，文案要具体指向下一步操作。

- 验收标准：
  - Given 管理员修改Prompt文本内容后点击"测试调用" When 系统响应 Then 使用修改后的Prompt向当前配置的AI模型发起测试请求，页面右侧实时显示AI返回结果（P95 < 10秒）
  - Given 管理员对测试结果满意 When 点击"发布此版本" Then 将该Prompt标记为当前生效版本，旧版本自动归入历史列表（不删除），记录操作人和发布时间
  - Given 新Prompt发布后产生异常 When 管理员点击历史版本的"回滚" Then 系统在5秒内将生效版本切换回历史版本，无需重启服务

**US-ADM-04 管理员查询某学生的学习记录**
- 验收标准：
  - Given 管理员输入手机号后点击"搜索" When 系统找到匹配学生 Then 展示学生基础信息及快捷入口（查看五力/查看训练记录）
  - Given 管理员点击"查看训练记录"并选择时间范围 When 数据加载 Then 以时间倒序展示每次训练的题目、学科、难度、用时、答题结果及AI交互摘要
  - Given 管理员需要导出数据 When 点击"导出"并选择时间范围 Then 系统生成CSV文件并提供下载，生成时间P95 < 30秒

**US-ADM-05 【建议新增】管理员通过数据看板发现异常**
- 验收标准：
  - Given 管理员打开数据看板 When 页面加载 Then 展示今日活跃学生数（对比昨日）、AI调用成功率（对比前7日均值）、当日Token消耗量（对比日预算上限）
  - Given 任一指标触发预警阈值 When 管理员打开看板 Then 对应指标卡片以红色边框高亮显示，顶部通知栏同步显示异常说明
  - Given 管理员需要临时关闭AI功能 When 点击"紧急降级"开关 Then 确认后AI对话功能切换为降级模式，并在操作日志中记录

### 6.4 交互流程

#### 6.4.1 Prompt模板管理流程

```
[管理员进入Prompt模板管理页]
→ [选择模板（学科×五力维度，如"数学-推演力"）]
→ [进入模板编辑页（左侧编辑区+右侧测试调用面板+底部版本历史）]
→ [编辑Prompt内容，使用占位变量如{{subject}}]
→ [点击"校验变量"] → [非法变量标红] → [变量合法]
→ [点击"测试调用"]
  ├── AI调用中（Loading动画）
  ├── 超时（>15秒）→ 提示"调用超时，请检查网络或API配置"
  └── 结果展示在右侧面板
→ 不满意 → 继续修改 → 重新测试
→ 满意 → [点击"发布此版本"]
→ [确认弹窗] → 确认 → [旧版本标记为历史，新版本标记为生效]
→ [页面提示"Prompt模板 v{N} 已发布，操作已记录"]
→ 版本历史列表更新（最新版本置顶，旧版本显示"回滚至此版本"）

---回滚分支---
[点击历史版本"回滚至此版本"] → [确认弹窗]
→ 确认 → [5秒内完成版本切换，生成操作日志]
→ 页面提示"已回滚至v{N}，当前生效版本更新"
```


### 6.6 用户旅程片段

#### 6.6.1 管理员首次配置AI参数的体验设计要点

- **引导设计**：首次进入AI配置页时，显示"配置向导"浮层（Step1填写API Key并测试连通性 → Step2确认模型名称 → Step3完成测试调用验证）
- **即时反馈**：填写API Key后点击"测试连接"，5秒内返回连接结果（成功显示绿色勾+模型名称，失败显示错误码和排查建议）
- **安全可视化**：API Key采用密码掩码显示，提供"为什么要加密存储？"说明链接
- **渐进披露**：高级参数（调用超时时长、重试次数）默认收起，展示"高级配置（可选）"折叠项，避免信息过载

#### 6.6.2 批量操作出错时的容错与回滚体验

- **操作前确认**：所有批量操作在执行前弹出确认弹窗，明确显示"将对[X]道题目执行[操作类型]，操作不可自动撤销"，要求管理员输入"确认"二字或勾选确认框
- **部分失败处理**：批量操作完成后显示执行摘要（成功N条/失败N条），失败条目以列表形式展示含题目ID和失败原因，支持导出失败列表
- **重要操作回滚**：Prompt模板、训练规则、计分规则的修改保留版本历史，提供"回滚至上一版本"快捷入口，回滚3秒内完成

#### 6.6.3 管理员通过数据看板发现异常的监控设计

- **预警阈值可配置**：超级管理员可在看板设置页配置各指标的预警阈值
- **异常分级展示**：橙色警告（指标接近阈值）和红色告警（指标已超阈值），红色告警同步发送邮件通知
- **异常下钻路径**：点击异常指标卡片，可查看24小时分时趋势、异常开始时间、受影响学生数量、系统自动生成的"可能原因"建议列表
- **快速响应工具**：看板页提供"紧急降级"入口（默认收起），一键将AI对话切换为降级模式；降级操作需二次确认并记录日志

### 7.1 【建议新增】通知与消息中心（优先级：P1）

**立项理由**：解决学生训练粘性不足的问题；Token消耗超限、系统维护等运营事件需要统一触达渠道。建议V1.1纳入，提升次日留存率和训练完成率。

**通知类型清单**：

| 通知类型 | 触发条件 | 默认开关 |
|----------|----------|----------|
| 训练提醒 | 学生当日尚未完成训练，且距设定学习时间已超过2小时 | 开启 |
| 五力测试提醒 | 注册满7天未完成测试；或五力结果已满30天未更新 | 开启 |
| 成就达成推送 | 学生解锁新成就徽章 | 开启 |
| Token余量预警 | 学生当月剩余Token不足20% | 开启 |
| 系统公告 | 管理员在后台发布公告 | 强制发送 |
| 家长通报 | 学生本周训练时长/正确率周报 | 家长开启后生效 |

**通知渠道矩阵**：站内信（全部类型）/ App推送（除家长通报外均支持）/ 家长短信（仅家长通报）/ 微信服务号（训练提醒/测试提醒/Token预警/系统公告）

**合规约束**：
- 每日推送总数上限：同一学生每日≤3条（系统公告除外）
- 免打扰时段：晚22:00至次日7:00禁止向学生推送App推送
- 不得以通知方式向未成年人推送商业促销内容

### 7.2 【建议新增】权限与角色管理（优先级：P1）

**立项理由**：V1.0后台仅支持单一管理员角色，无法满足多校部署场景下的精细化权限管理需求。建议V1.1引入多角色权限体系。

| 角色名称 | 角色代码 | 定义 |

| 超级管理员 | SUPER_ADMIN | 拥有所有操作权限，可管理其他管理员账号及角色分配 |
| 机构管理员 | ORG_ADMIN | 针对某一学校/机构，仅可访问本机构学生数据 |
| 内容管理员 | CONTENT_ADMIN | 管理认知测试、题库、Prompt模板，无学生个人数据权限 |
| 数据查看员 | DATA_VIEWER | 只读访问学生数据和数据看板，不可进行配置修改操作 |

**权限矩阵表**：

| 功能模块 | 超级管理员 | 机构管理员 | 内容管理员 | 数据查看员 |
|----------|-----------|-----------|-----------|-----------|
| 认知测试管理（读写） | 是 | 否 | 是 | 否 |
| 题库管理（读写） | 是 | 否 | 是 | 否 |
| 训练规则配置（读写） | 是 | 否 | 是 | 否 |
| AI参数配置（读写） | 是 | 否 | 否 | 否 |
| 学生数据查询（本机构） | 是 | 是 | 否 | 是 |
| 学生数据查询（全局） | 是 | 否 | 否 | 否 |
| 数据看板（全局） | 是 | 否 | 否 | 是 |
| 数据看板（机构维度） | 是 | 是 | 否 | 是 |

### 7.6 【建议新增】内容安全与反作弊（优先级：P0）

**立项理由**：本产品面向12-18岁未成年人，AI对话内容安全和答题反作弊是不可妥协的合规底线，属于产品合法上线的技术前提。

**AI对话内容过滤规则**：

| 过滤类型 | 具体规则 | 处理方式 |
|----------|----------|----------|
| 违规词过滤 | 维护违规词库（暴力/色情/政治敏感） | 命中时替换为"[内容已过滤]"并记录告警 |
| 诱导答题识别 | 检测AI回答中是否包含直接给出答案的模式 | 触发时重新生成回答，最多重试2次，仍触发则返回固定引导文案 |
| 学科无关内容过滤 | 检测学生输入是否与数理化无关 | AI返回"我是你的数理化助教，只能帮你解决数理化问题"并记录 |

**学生作弊行为识别策略**：

| 作弊行为类型 | 识别特征 | 处理策略 |
|-------------|----------|----------|
| 答题时长异常 | 完成时间低于该题型历史均值的10% | 标记为疑似作弊，该题不计入五力得分 |
| 高难度快速全对 | 连续5道挑战难度题目，平均答题时长低于30秒且全对 | 触发人工复核标记，暂停难度进阶，通知管理员 |
| 固定答题模式 | 连续10道题选择同一选项 | 系统中断训练并提示"检测到异常答题行为，训练已暂停，请认真作答" |

**优先级为P0的理由**：
1. 法律合规要求：《网络安全法》《未成年人网络保护条例》对面向未成年人的AI交互产品有明确的内容安全要求
2. 产品信任底线：一次被传播的AI不当输出事件足以击穿家长群体的信任
3. 上线前置条件：监管部门对AI教育产品的备案审查明确要求具备内容过滤机制

### 附录B：五力评分算法说明（概要）

#### B.1 设计原则

- **可干预性**：算法参数（权重、衰减系数等）由产品方通过配置文件控制，不硬编码在业务逻辑中
- **可解释性**：每次五力得分更新均生成可读的更新原因记录
- **动态性**：学生得分随每次训练结果实时更新，设置合理的历史衰减机制（近期表现权重高于历史表现）
- **鲁棒性**：题目数量不足时保持上一次有效得分，不因数据不足产生大幅波动

#### B.2 计分输入变量

| 变量名称 | 说明 |
|----------|------|
| 答题正确率 | 该五力维度下近N次作答的正确率（N为可配置参数） |
| 题目难度权重 | 不同难度题目对得分贡献的权重系数 |
| 答题时长系数 | 在合理时长范围内完成作答的加权系数 |
| AI提示使用次数 | 本次训练使用AI引导提示的次数（使用提示越少得分略高） |
| 历史得分衰减系数 | 控制历史得分对当前计算结果影响程度的衰减参数 |
| 变式题表现 | 在同一知识点变式题上的表现（评估迁移力的核心输入） |

#### B.3 不硬编码的实现原则

所有以下参数均不允许直接写入业务代码，须通过配置表读取：
- 各难度题目的得分权重系数
- 历史得分衰减系数
- AI提示次数对得分的折减比例
- 五力训练权重比例
- 难度进阶所需正确率阈值

以上参数的修改须通过管理后台操作完成，并记录操作日志，工程师不得在代码中覆盖配置值。
