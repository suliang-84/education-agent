## 1. 调研背景与产品定位

### 1.1 产品背景

本产品面向初一至高三在校中学生，覆盖数学、物理、化学三个学科。产品核心假设：

> **中学生学习困难的根本原因不只是"知识点不会"，而是认知能力薄弱。** 通过"五力认知测试"诊断学生的认知特点与薄弱项，再在具体知识点中进行针对性训练，让每位学生获得真正个性化的"专属AI老师"体验。

### 1.2 V1.0目标边界

| 维度 | 范围 |
|------|------|
| 年级 | 初一至高三（优先初三、高一内容建设） |
| 学科 | 数学（必修）、物理（必修）、化学（必修） |
| 用户角色 | 学生（主）、家长（关联）、管理员（后台） |
| 核心验收 | 完整跑通：注册 → 五力测试 → 画像生成 → 知识点训练 → AI指导 → 保存结果 → 五力对比 |
| 不覆盖 | 高中选修模块、教师班级端、复杂数据分析报告 |

## 2. 产品核心理念

以下为从客户原始文档和反馈建议中提炼的产品核心设计哲学，是所有模块设计决策的基础原则。

### 2.1 从"做题工具"到"专属AI老师"

**客户原文（20260820需求文档.docx）：**
> "V1的核心不是做一个通用AI答题工具，而是通过'五力认知测试'找到学生的认知特点与薄弱项，再在具体知识点中进行针对性训练，让用户获得具有个人训练路径的'专属AI老师'。"

**产品设计含义：**
- "专属"不是为每个学生训练独立大模型，而是同一套AI教学系统根据不同学生的五力画像动态调整"练什么"和"怎么练"
- AI的核心价值在于个性化的**指导方式**，而非题目推送本身

### 2.2 从"答错触发AI"到"AI伴随全程"

**客户反馈（20260824需求文档.docx）：**
> "用户在学习过程中要更多的交互感（初步以文字交流的方式），而不是在做错题以后出现AI助教。"
>
> "AI不仅在答错后出现，在整个学习过程中持续结合五力画像、当前题目、对话状态和不同启发策略进行互动，并允许学生自由文字提问。"

**产品设计含义：**
- AI互动是主线，题目训练是工具
- 体验流程调整为：五力测试 → 画像生成 → **进入AI学习互动** → AI根据画像决定讲解/提问/提示方式 → 在需要时调用题目
- 这是V1.0产品体验的核心差异化

### 2.3 内驱力培养是终极目标

**客户反馈（20260824需求文档.docx）：**
> "核心是：培养用户的内驱力，让他们在学习解答的过程中获得成就感。"

**产品设计含义：**
- AI不直接给答案，而是通过启发引导让学生自主推导
- 学生"想通了"的顿悟感比"被告知答案"更有学习价值
- 题目是教学工具，不是学习目标本身

### 2.4 五力是一切个性化的起点

五力是产品区别于通用刷题工具的核心差异化能力维度，统一定义如下：

| 五力维度 | 核心能力描述 | 训练侧重 |
|----------|-------------|----------|
| **洞察力** | 从题目中找关键条件、识别干扰信息、读图表有效信息 | 条件提取、隐含关系识别 |
| **建构力** | 建立变量关系、条件关系、图示关系、数学/物理/化学模型 | 关系建立、模型建构 |
| **推演力** | 连续推理、步骤补全、下一步判断、证明、运算链 | 逻辑推导、步骤严密性 |
| **调适力** | 错误识别与归因、修改步骤、换方法、接受提示后重新尝试 | 纠错、路径切换 |
| **迁移力** | 同构题、变式题、换条件/表达/情境、识别相同底层规律 | 跨情境应用、规律迁移 |

## 3. 客户原始需求（按模块）

> 本章为客户原始需求的忠实整理，保留原始表述，不做主观增减。

### 3.1 登录与账号管理

**原始需求（隐含在01文档中）：**
- 支持学生注册与登录
- 建立学生账号及个人认知档案
- V1核心验收链路从"注册/登录"开始

**客户反馈补充：**
- 疑问："学生与家长双验证是否有点繁琐？可否简化？"（见 20260824需求文档.docx）
- 客户倾向于降低注册门槛，避免繁琐验证流程阻碍用户进入

**关键约束：**
- 无特别指定登录方式，以用户体验简洁为优先

---

### 3.2 五力认知系统

**原始需求（20260820需求文档.docx，第一节）：**

**账号与档案：**
- 建立学生账号及个人认知档案
- 首次使用时完成五力认知测试

**测试题规格：**
- 支持题型：单选、多选、图片选择、排序、简单拖拽、数字/文字输入
- 每道题后台可设置：题目、答案、主测五力、分值、参考时间、计分规则
- 程序记录：答案、正确/错误、单题耗时、修改次数、总测试时间

**测试结果：**
- 生成五项得分、五边形雷达图、单项解释、综合评价
- 判断当前重点强化项、次重点项、正常训练项
- 五力评分及训练权重的具体算法由产品方提供，程序须做到参数可调，不写死在代码中

**历史与对比：**
- 允许学生重新测试
- 保存历次五力结果，用于前后比较

---

### 3.3 数理化题库

**原始需求（20260820需求文档.docx，第二节）：**

**覆盖范围：**
- 学科：数学、物理、化学
- 管理层级：学科 → 年级 → 章节 → 知识点

**基础字段：**
- 题干、图片、题型、难度、答案、解题过程、所属知识点

**五力标签：**
- 每道训练题增加"主训练五力"标签（洞察/建构/推演/调适/迁移）
- 必要时允许增加一个辅助标签

**扩展字段（渐进补充，非一次性要求）：**
- 常见错误、分级提示、关键步骤、同类题、变式题

**五力题型设计原则（非换标签）：**
| 五力 | 题目设计重点 |
|------|-------------|
| 洞察 | 关键条件与干扰信息识别 |
| 建构 | 关系和模型建立 |
| 推演 | 连续推理与步骤完整性 |
| 调适 | 纠错与路径切换 |
| 迁移 | 同构、变式、换情境 |

**管理要求：**
- 后台必须支持自行新增、修改、删除题目及调整五力标签
- 扩展字段可逐步补充，不要求一次填写完整

**客户关切：**
- "有待解决：**题库！**"（20260824需求文档.docx，重点标注）
- 题库建设是V1.0最大的内容工程风险，需专项规划

---

### 3.4 个性化AI训练系统

**原始需求（20260820需求文档.docx，第三节）：**

**1. 个人训练方案生成**
- 五力测试后，根据五项结果生成训练优先级和训练权重
- 示例：建构重点强化、迁移次重点、其他维持；对应训练比例由后台规则生成并允许调整
- 前端可包装为"正在生成你的专属AI老师"

**2. 个性化选题**
- 选题综合考虑：当前知识点 + 五力训练重点 + 题目难度 + 已完成题目 + 近期训练结果
- 示例：建构力薄弱的学生优先获得"关系建立、模型建立类"题目；迁移力薄弱的学生增加同构题、变式题

**3. 强化训练逻辑**
- 在一个阶段内优先强化最明显的薄弱项，同时保留其他能力基础训练
- 训练比例、题量、切换条件做成可配置参数，便于真实学生测试后调整

**4. AI个性化指导**
- AI读取：学生当前五力特点、学科/知识点、本题主训练五力、当前训练目标、学生本次回答
- 不同五力目标对应不同指导方式：
  - 建构训练：强调关系建立
  - 调适训练：强调错误发现和换路
  - 迁移训练：强调变式与同构

**5. AI按需调用与Token控制**
- 优先由结构化题库、规则、预设提示完成，AI处理：自然语言回答、非标准解法解释、学生追问、题库外问题、动态提示
- 每次调用只发送当前必要上下文，不反复发送全部历史记录

**6. 自主提问**
- 学生可文字输入或拍照上传数理化题目
- 调用视觉/OCR/多模态能力识别后，判断学科、知识点、题型，进入AI辅助流程

### 3.5 学习记录与反馈

**原始需求（20260820需求文档.docx，第四节）：**

**记录内容：**
- 每次训练：学科、知识点、题目、主训练五力、难度、正确/错误、耗时、提示使用情况、AI调用情况

**学生端反馈展示：**
- 学习时长
- 知识点进度
- 做题情况（正确率、题量）
- 当前重点训练能力
- 五力训练数量（各维度题量分布）

**五力对比：**
- 重新进行五力测试后，可对比前后五边形变化

**V1定位：**
- "V1以记录和基础反馈为主，不需要制作复杂的数据分析报告"

## 4. 客户反馈与补充需求

> 本章整理 20260824需求文档.docx 中的全部内容，包括产品体验流程调整、新增功能需求和客户疑问。

### 4.1 产品体验流程调整

**客户原始表述：**
> "MESH的核心体验是：五力测试 → 生成个人训练画像/专属AI老师 → 学生先进入AI学习互动 → AI根据学生画像决定讲解、提问、提示和训练方式 → 在需要时调用结构化题目进行训练。"

**与原始需求的差异对比：**

| 维度 | 原始需求流程 | 反馈调整后流程 |
|------|-------------|---------------|
| 核心交互形态 | 题目列表 → 作答 → 错误后触发AI | **对话主线 → AI伴随 → 按需调用题目** |
| AI出现时机 | 答错后触发 | **全程伴随，AI主动决定何时介入** |
| 题目的角色 | 训练主体 | **AI教学过程中可调用的工具** |
| 用户体验感知 | "做题平台有AI辅助" | **"和AI老师一起学，顺便做题"** |

**影响评估：**
- 这是产品体验的根本性调整，不是功能点的增删
- 原有个性化AI训练模块（模块三）的交互逻辑需要重新审视
- 新增"AI伴随学习层"作为独立模块（模块六：智能助教）

### 4.2 新增模块：AI伴随学习层（智能助教）

**客户原始表述（20260824需求文档.docx）：**
> "文档05已有的五力画像进入Prompt和五力策略调用，在保留的同时；再增加一个AI伴随学习层，AI不仅在答错后出现，在整个学习过程中持续结合五力画像、当前题目、对话状态和不同启发策略进行互动，并允许学生自由文字提问。"

**功能要点逐条整理：**

| 编号 | 客户原文 | 功能含义 |
|------|----------|----------|
| F-1 | 学生可以直接和AI文字交流 | 自由文字输入对话界面，随时提问 |
| F-2 | AI持续知道当前学生的学习状态 | 状态感知引擎：五力画像 + 错题 + 对话历史实时注入上下文 |
| F-3 | AI决定什么时候说、什么时候不说 | AI介入时机决策机制：主动介入 vs 沉默策略 |
| F-4 | 同一种提示无效以后换一个启发角度 | 启发策略切换：同一策略N次无效自动切换维度 |
| F-5 | 可以从生活、空间、故事、音乐、反例等不同维度启发 | 多维启发策略库（生活类比/空间想象/故事叙述/节奏模式/反例证伪等） |
| F-6 | 记录"这个学生哪种启发方式有效" | 学生策略有效性画像：per-student策略响应档案 |
| F-7 | AI根据历史互动逐渐调整启发策略 | 策略自适应：AI优先选用历史有效策略 |
| F-8 | 题目只是AI教学过程中可以调用的工具 | 题目作为工具插入对话，不是训练主线 |
| F-9 | 培养用户的内驱力，让他们在学习解答的过程中获得成就感 | 成就感设计：理解突破识别 + 个性化正反馈 |

### 4.3 客户疑问与关切

#### 疑问一：家长双验证繁琐问题

**客户原文：** "是否学生与家长双验证是否有点繁琐？可否简化？"

**背景：** 规格说明书（01_登录模块）中设计了"18岁以下学生注册须填写家长手机号并完成家长确认"的双验证机制。

**已决策（登录模块 V1.0）：**
- 18岁以下学生注册只需本人微信认证或手机号认证即可，无需家长确认
- 注册流程与成年人一致，家长绑定改为可选功能（学生完成注册后，可主动邀请家长关联）
- 家长查看子女报告需完成绑定，但绑定不阻断学生注册主流程

#### 疑问二：题库建设问题

**客户原文：** "有待解决：**题库！**"（重点标注）

**背景：** 题库是整个产品的内容底座，质量和数量直接决定训练效果，但题库建设是一项持续的内容工程，V1.0能否上线与种子题库规模强相关。

**当前状态：** 待专项规划（见第7章待解决问题）
