## 1. 概述

### 1.1 模块目标

五力认知测试模块是中学数理化 AI 助教微信小程序的核心入口功能。模块目标为：

1. **诊断**：通过结构化题目测量学生在五个认知维度上的当前水平
2. **画像**：生成可视化的个人五力雷达图，形成可量化的认知能力档案
3. **驱动**：以测试结果作为输入，驱动后续个性化训练内容的精准推送
4. **追踪**：支持多次测试的历史对比，追踪认知能力的成长轨迹

### 1.2 设计原则

| 编号 | 原则 | 说明 |
|------|------|------|
| P-01 | 学生侧零门槛 | 测试流程不超过4步进入答题，交互设计适配初一（12岁）至高三（18岁） |
| P-02 | 管理侧高效录入 | 支持拍照识别与批量 Word 导入，降低超级管理员的题目录入成本 |
| P-03 | 异步不阻塞 | OCR、Word 解析、AI 分析均异步执行，不阻塞主流程的用户操作 |
| P-04 | 配置可调 | 测试参数（题数、时长、评分权重等）通过后台配置驱动，无需代码发布 |
| P-05 | 历史可追溯 | 所有题目变更、配置变更、测试记录均保留历史快照，不可覆盖删除 |
| P-06 | 数据安全 | 学生测试数据仅超级管理员可访问全局数据，学生只能访问自己的测试结果 |

### 1.3 用户角色

| 角色标识 | 角色名称 | 使用端 | 核心职责 |
|----------|----------|--------|----------|
| STUDENT | 学生 | 微信小程序 | 参加五力测试，查看个人态势报告，获取训练入口 |
| SUPER_ADMIN | 超级管理员 | 后台管理系统 | 全权限，含题库管理、测试配置、用户管理、数据导出 |

### 1.4 术语定义

| 术语 | 定义 |
|------|------|
| 五力 | 洞察力、建构力、推演力、调适力、迁移力五项认知能力维度的统称 |
| 测试会话（Session） | 一次完整测试的生命周期单元，含试卷快照、答题过程、提交状态 |
| 试卷快照 | 组卷时记录的题目 ID 列表与配置版本号，保障历史可复现 |
| 五力权重 | 题目层面的权重系数（0.1~1.0），反映该题对目标五力维度总分的贡献比重 |
| 选项分值 | 各答案选项对题目所测五力维度的得分贡献值（如 A:10, B:7, C:4, D:1），无标准答案 |
| 配置版本 | 测试参数配置的一个不可变历史版本，新试卷始终取最新生效版本 |
| AI 个性化分析 | 由 AI 模型根据本次测试数据生成的 150~250 字个性化解读段落 |
| 重点强化项 | 某五力得分低于重点强化项阈值（默认50分）的维度 |
| 次重点项 | 某五力得分在重点强化项阈值至次重点项阈值（默认65分）之间的维度 |
| 骨架屏 | 内容加载期间的占位UI，用于替代空白等待，提升用户感知 |

### 1.5 五力认知能力定义

以下为系统内部标准文本，用于 AI 分析上下文、报告解读及题目标注。

**1. 洞察力（Insight）**

在复杂、模糊的信息中，穿透表象，直击事物底层本质和核心矛盾的能力。实现路径为"差异比较"——识别现状与应有状态之间的落差。真正的洞察必须有可验证的逻辑链，结论可被推论过程支撑。

**2. 建构力（Structuring）**

将模糊愿景、零散需求转化为清晰、可执行的系统框架、模型或流程的能力。精髓在于"取舍"——刻意忽略次要细节，确保核心结构稳固、主干清晰、可被他人理解与执行。

**3. 推演力（Projection）**

基于现有信息和逻辑，模拟事物发展多条路径的走向、节点和终局，预判各种可能性的能力。核心机制为"冗余设计"——预设关键信号（路标），一旦触发信号则启动预案。

**4. 调适力（Adaptation）**

当现实反馈与预期不符时，快速打破原有认知，调整策略、心态甚至目标，重新适配新环境的能力。最大敌人是"路径依赖"。调适分两层：微调（优化参数，保留框架）和范式转换（更换赛道，重建框架）。

**5. 迁移力（Transfer）**

将 A 领域习得的底层逻辑、成功经验抽象提炼后，应用到 B 领域解决新问题的能力。核心在于"去情境化"——剥离具体行业术语，只保留结构关系（如正反馈、负反馈、杠杆点），再将其映射到新场景。

## 2. 应用场景

### 2.1 场景 S-01：超级管理员拍照上传单题

**前置条件：**
- 操作者已以 SUPER_ADMIN 身份登录后台管理系统
- 操作者持有题目图片文件（JPG/PNG/HEIC，≤10MB）

**主流程：**
1. 操作者进入「题库管理」→「新增题目」→ 选择「拍照/图片识别」
2. 上传图片文件，系统校验格式与大小通过后返回上传成功提示
3. 系统将图片推入 OCR 异步队列，前端每 2 秒轮询一次识别状态，最长等待 30 秒
4. OCR 识别完成，系统自动填充题干、选项 A~E、参考答案字段
5. 置信度低于 80% 的字段以黄色高亮标注，提示操作者核对
6. 操作者核对并补充：五力类型（必填）、难度（必填）、分值、解析说明等字段
7. 操作者点击「保存草稿」或「保存并发布」，题目写入数据库

**分支流程：**
- 识别超时（>30秒）或识别置信度整体过低：系统提示「识别失败，请重新拍照或手动输入」
- 图片格式/大小不符：上传即报错，提示允许格式与大小限制

**后置结果：**
- 题目以「草稿」或「已发布」状态写入题库
- 操作日志记录上传者、上传时间、OCR 置信度、字段来源（自动填充/手动修改）

---

### 2.2 场景 S-02：超级管理员批量导入 Word 题库

**前置条件：**
- 操作者已以 SUPER_ADMIN 身份登录后台管理系统
- 操作者持有按系统模板格式制作的 .docx 文件（≤20MB）

**主流程：**
1. 操作者进入「题库管理」→「上传 Word 批量导入」
2. 下载 Word 模板参考格式（可选）
3. 上传 .docx 文件，系统校验格式与大小后推入 Word 解析异步队列
4. 前端轮询解析状态，最长等待 60 秒，期间显示进度提示「解析中...」
5. 解析完成，系统展示「批量导入预览页」：每道题一行，含题干前30字、自动识别题型、五力类型（空或识别结果）、操作按钮（编辑/删除）
6. 操作者逐题确认，对五力类型为空的题目逐一填写，或通过批量修改功能统一设置
7. 操作者点击「全部导入」，系统执行批量写入
8. 显示导入报告：成功 N 题 / 失败 N 题 + 失败原因

**分支流程：**
- Word 解析超时（>60秒）：提示「文档解析超时，请检查文档格式或稍后重试」
- 全部导入后部分失败：成功题目已写入，失败题目在报告中列出，支持单独修正后重新导入

**后置结果：**
- 通过审核的题目以「草稿」状态批量写入题库
- 生成本次导入的汇总报告，可下载为 CSV

### 2.3 场景 S-03：超级管理员配置新测试参数

**前置条件：**
- 操作者已以 SUPER_ADMIN 身份登录后台
- 各五力/各难度均有足量已发布题目覆盖新配置要求

**主流程：**
1. 操作者进入「测试配置」，查看当前生效版本参数
2. 点击「新建配置版本」，系统以当前版本为基础创建可编辑副本
3. 操作者修改：总题数、各五力占比、各难度占比、时长限制、评分加权系数等
4. 点击「校验」，系统检查：五力占比合计=100%、难度占比合计=100%、题库各组合（五力×难度）可用题目数≥配置所需数量
5. 校验通过后点击「保存并生效」，系统生成新版本号，标记为当前生效版本
6. 新版本立即对后续所有新建测试会话生效；历史测试会话保持原版本号不变

**后置结果：**
- 新配置版本写入 test_config_versions 表，is_active=true
- 旧版本 is_active 保持为 false，历史只读，不可回滚
- 操作日志记录变更人、变更时间、版本号对比

---

### 2.4 场景 S-04：学生首次参加五力测试

**前置条件：**
- 学生已完成微信授权登录
- 当前有生效的测试配置版本
- 题库中各五力/各难度题目数量满足配置要求

**主流程：**
1. 学生进入小程序首页，点击「开始五力测试」
2. 系统读取当前生效配置版本，按五力占比和难度占比分层抽题，随机排列
3. 生成试卷快照（题目 ID 列表 + 配置版本号），创建新 test_session（status=in_progress）
4. 展示「测试说明页」：题数、预计时长、注意事项、五力简介
5. 学生点击「开始答题」，进入答题界面
6. 顶部显示进度条（第X题/共N题）和总计时器
7. 学生逐题作答，每次点击「下一题」写入答案、单题耗时、修改次数
8. 最后一题点击「提交」→ 确认弹窗 → 确认提交
9. 系统同步执行评分（≤3秒）→ 跳转个人态势报告页
10. 后台异步触发 AI 个性化分析（5~20秒），完成后填入报告第三屏

**后置结果：**
- test_session status 更新为 completed
- test_results、five_power_profiles 写入评分数据与雷达图数据
- 学生可在报告页查看五力得分、等级标签、AI 分析段落（加载完成后）

---

### 2.5 场景 S-05：学生测试中途退出后恢复

**前置条件：**
- 学生已开始一次测试（test_session status=in_progress）
- 学生在未提交前退出小程序
- 距退出时间未超过 72 小时

**主流程：**
1. 学生重新进入小程序，系统检测到存在未完成会话
2. 显示弹窗：「检测到上次未完成的测试（已完成X题/共N题），是否继续？」
3. 选择「继续上次」→ 恢复到退出时的题目位置，已填答案保留，计时器续计
4. 选择「重新开始」→ 当前 session 标记为 abandoned，创建新 session，重新抽题
5. 学生继续作答至提交，流程同场景 S-04 步骤 8~10

**分支流程：**
- 72小时已过：旧 session 自动标记为 expired，学生进入直接触发新 session 创建，不显示恢复弹窗

**后置结果：**
- 恢复会话：原 session 记录续写完整答题数据
- 放弃会话：旧 session status=abandoned，不参与评分，计入历史行为记录

---

### 2.6 场景 S-06：学生查看历史对比报告

**前置条件：**
- 学生已完成至少 2 次五力测试

**主流程：**
1. 学生滑动至报告第四屏「历史对比」
2. 系统展示本次与上次测试的双色叠加雷达图
3. 各维度列出得分变化（↑/↓ + 数值 + 颜色标注：上升绿色，下降红色，不变灰色）
4. 趋势折线图展示最多5次历史各五力得分走势
5. 学生点击折线图上某个历史节点，查看该次报告摘要（时间、各五力得分）
6. 学生滑动至第五屏，查看基于本次结果的行动建议与训练入口

**后置结果：**
- 历史对比数据仅读取，不修改任何记录

## 4. 功能模块详细规格

### 4.1 题目上传与识别

#### 4.1.1 拍照/图片识别上传

**功能描述：** 管理员通过上传图片方式录入单道题目，系统自动执行 OCR 识别并回填字段。

**触发入口：** 后台「题库管理」→「新增题目」→「拍照/图片识别」

**输入规格：**

| 字段名 | 类型 | 必填 | 校验规则 |
|--------|------|------|----------|
| 图片文件 | File | 是 | 格式：JPG/PNG/HEIC；大小：≤10MB；单次上传1张 |

**处理流程：**

```
[1] 上传图片
       ↓
[2] 格式/大小校验
  通过 ──────────────────────────────────→ [3] 推入 OCR 队列
  失败 → [ERR-001] 返回文件格式错误

[3] 推入 OCR 队列
       ↓
[4] 前端每2秒轮询（最长30秒）
  识别完成 ──────────────────────────────→ [5]
  超时/失败 → [ERR-102] 提示重拍或手动输入

[5] 自动回填：题干 / 选项 / 参考答案
       ↓
[6] 置信度检查：< 80% 的字段标黄提示核对
       ↓
[7] 管理员核对补充必填字段（五力类型、难度）
       ↓
[8] 保存草稿 / 保存并发布 → 题目写入数据库
```

**OCR 自动回填字段：**

| 字段 | 是否可自动识别 | 置信度 < 80% 时行为 |
|------|--------------|---------------------|
| 题干 | 是 | 黄色高亮，显示「建议核对」 |
| 选项 A~E | 是 | 黄色高亮，显示「建议核对」 |
| 参考答案 | 部分题型 | 黄色高亮，显示「建议核对」 |
| 五力类型 | 否 | 管理员必填 |
| 难度 | 否 | 管理员必填 |

**验收标准：**

- AC-3.1-03：Given 某五力×难度组合（如洞察力-挑战）可用已发布题目不足配置所需，When 管理员点击「保存并生效」，Then 系统提示具体不足的组合与缺口数量，阻止本次生效

### 4.5 评分与个人态势报告

#### 4.5.1 评分计算规则（同步，≤3秒）

> **评分说明**：五力认知测试题目无"标准答案"，仅有各选项对目标五力维度的得分贡献权重。评分反映的是学生在特定认知维度上的表现倾向程度，而非对错判断。

**评分公式（逐步骤）：**

```
Step 1：逐题基础得分

  【选择类题目】（单选/情景判断/排序/拖拽匹配）：
    题目基础得分 = option_scores[学生选择] / max(option_scores) × 题目分值 × 五力权重
    · option_scores 为各选项预设的五力得分贡献（如 A:10, B:7, C:4, D:1）
    · 无标准答案，不使用对/错判断

  【多选题】：
    题目基础得分 = Σ(每个已选选项的 option_scores) / max_possible × 题目分值 × 五力权重
    · max_possible 为题目允许选择数量下所有最高分选项之和

  【文字类题目】（填空/简答/计算）：
    · 通过关键词匹配 + AI 语义评分，输出 0~1 的答案质量系数 q
    · 题目基础得分 = 题目分值 × 五力权重 × q
    · AI 语义评分为异步任务，最长等待 30 秒；超时后自动降级为关键词匹配结果

Step 2：五力原始得分汇总
  某五力原始分 = Σ（该五力下所有题目基础得分）

Step 3：答题时长加权
  时长加分 = 原始分 × time_bonus_coefficient × max(0, (参考时间-实际耗时)/参考时间)
  某五力时长加权分 = 原始分 + 时长加分

Step 4：历史衰减加权（第2次及以上测试）
  历史综合分 = 本次时长加权分 × (1 - history_decay_coefficient)
             + 上次最终得分 × history_decay_coefficient
  · history_decay_coefficient 默认 0.30，衰减基准为上次最终得分（已决策，见Q-002）

Step 5：等级判定
  最终分 < focus_threshold          → 重点强化（薄弱）
  最终分 < secondary_threshold      → 次重点（一般）
  最终分 < 80                       → 正常训练（良好）
  最终分 ≥ 80                       → 优秀
```

### Q-005 ✅ 已关闭（待最终选型确认）

**问题**：题目富文本中 LaTeX 公式的小程序端渲染方案是否已选定？

**决策结论**：以下为主流微信小程序 LaTeX 渲染方案对比，供技术选型参考：

| 方案 | 实现方式 | 渲染效果 | 包大小影响 | 启动性能影响 | 推荐场景 |
|------|---------|---------|-----------|------------|---------|
| **WxMath** | 微信小程序专属库，将 LaTeX 转为 WXML 节点 | 良好，支持常用数学公式 | 约 150KB | 低，按需加载可控 | 公式量少、性能敏感场景 |
| **KaTeX（WebView渲染）** | 在小程序 WebView 组件中加载 KaTeX | 优秀，覆盖完整 LaTeX 语法 | KaTeX 约 300KB，但可 CDN 加载 | 中，WebView 初始化耗时约 200~500ms | 公式复杂、效果要求高 |
| **MathJax（WebView渲染）** | 在 WebView 中加载 MathJax 3.x | 最完整，兼容性最强 | MathJax 约 1MB+ | 高，首次加载明显卡顿 | 不推荐用于小程序 |
| **服务端预渲染（SVG/PNG）** | 后端将 LaTeX 转为 SVG 或 PNG，前端展示图片 | 最一致，所有机型无差异 | 零额外包大小 | 极低（无渲染计算） | 公式不频繁更新的题库 |

**推荐方案**：**服务端预渲染（SVG）**（适合本项目）
- 后端在题目入库时将 LaTeX 统一转为 SVG 字符串，存入 `stem` 富文本字段
- 小程序展示时直接渲染 SVG，无需引入第三方渲染库，对启动包大小零影响
- 题目修改时后端重新生成 SVG 并覆盖缓存

**备选方案**：若题目存在大量动态公式场景，可使用 WxMath + 分包加载（将渲染库放入分包，主包不增大）

**已纳入**：第 5.1 节 stem 字段说明
