## 1. 概述

### 1.1 模块目标

本文档定义中学数理化 AI 助教系统登录模块的完整需求规格，涵盖：
- 微信小程序端学生/家长的注册、登录、身份绑定流程
- 后台管理系统各级管理员的登录、权限控制流程
- 统一身份服务的 Token 签发与刷新机制
- 角色与权限管理的增删改查规则

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 统一身份服务 | 小程序端与管理后台共用同一套 JWT 签发机制，角色通过 `role` 字段区分 |
| 最小权限 | 每个角色只能访问其职责范围内的数据与功能 |
| 未成年人保护 | 18岁以下学生注册只需本人微信认证或手机号认证即可，无需家长确认，注册流程与成年人一致 |
| 参数可配置 | 锁定时长、验证码有效期、Token 有效期等均通过配置表管理，不硬编码 |
| 操作留痕 | 所有登录、角色变更、账号管理操作均写入审计日志 |

### 1.3 角色一览

| 角色代码 | 中文名称 | 使用端 | 优先级 |
|----------|----------|--------|--------|
| STUDENT | 学生 | 微信小程序 | P0 |
| PARENT | 家长 | 微信小程序 | P1 |
| SUPER_ADMIN | 超级管理员 | 管理后台 | P0 |

## 2. 应用场景

### 2.1 场景 S-01：学生首次使用小程序

**描述**：初一至高三学生首次打开微信小程序，通过微信授权完成注册并绑定手机号，进入五力测试流程。

**前置条件**：用户已安装微信，年龄 13~18 岁

**主流程**：
1. 打开小程序，点击"微信一键登录"
2. 微信弹出授权确认框，用户同意
3. 系统检测该微信 openid 未绑定任何账号
4. 引导用户输入手机号并接收短信验证码
5. 验证码通过后，账号创建成功（未成年人无需家长确认，本人微信认证或手机号认证即可）
6. 首次进入显示新手引导，强引导完成五力测试

**后置结果**：学生账号创建，openid 与手机号绑定，JWT 签发

**首页导航规则（参见 05_系统交互协议规范.md §2.3）：**

```
登录/注册成功后：
│
├── 首次用户（无五力画像记录）
│    └── 全屏引导页，强引导完成五力测试
│         ├── 点击"开始测试" → 进入 02_五力认知测试模块
│         └── 点击"稍后再说" → 进入首页（Tab 1 默认），顶部展示测试入口横幅
│
└── 已有五力画像的用户
     └── 直接进入首页，默认选中 Tab 1（个性化训练）
          └── 顶部五力状态卡展示最近2个薄弱维度
```

**首页 Tab 结构（三 Tab）：**

| Tab | 功能标题 | 对应模块 | 默认状态 |
|-----|----------|----------|----------|
| Tab 1 | 个性化训练 | 03_个性化AI训练 | **默认选中** |
| Tab 2 | AI 助教 | 04_智能助教 | 可切换 |
| Tab 3 | 我的五力 | 02_五力认知测试（报告） | 可切换 |

### 2.2 场景 S-02：学生日常登录

**描述**：已注册学生再次打开小程序，静默登录无需手动操作。

**前置条件**：学生已完成注册，本设备曾登录

**主流程**：
1. 打开小程序，系统自动调用 `wx.login()` 获取 code
2. 后端用 code 换取 openid，查询到已绑定账号
3. 检查本地 access_token 是否有效
   - 有效：直接进入首页
   - 过期但 refresh_token 有效：静默续期，用户无感知
   - 两者均过期：弹出"重新登录"提示

**后置结果**：用户无需任何操作即进入首页，体验流畅

---

### 2.3 场景 S-03：家长绑定并查看子女报告

**描述**：家长通过学生分享的邀请码完成绑定，查看子女学习数据。

**前置条件**：学生账号已创建，学生生成了有效邀请码

**主流程**：
1. 家长点击小程序链接或扫描邀请二维码
2. 微信授权登录，系统判断 openid 未绑定账号，进入注册
3. 家长选择身份"我是家长"，输入手机号+验证码
4. 输入学生提供的6位邀请码
5. 系统校验邀请码有效性，绑定关系建立
6. 家长进入只读的"孩子学习"视图

**后置结果**：家长账号创建，绑定关系写入，家长看到子女学习报告

---

### 2.4 场景 S-04：超级管理员登录并管理角色

**描述**：超级管理员通过双因素验证登录后台，为新运营人员创建账号并分配角色。

**前置条件**：超级管理员账号已创建，绑定了手机号

**主流程**：
1. 输入用户名 + 密码（第一步）
2. 密码验证通过，系统向绑定手机号发送短信验证码
3. 输入短信验证码（第二步），验证通过
4. 进入超管视图，点击"用户管理" → "新建管理员"
5. 填写新账号信息（用户名、邮箱、备注说明）
6. 系统生成临时密码，发送欢迎邮件至新账号邮箱

**后置结果**：新管理员账号创建完毕，JWT 签发，操作日志记录

## 3. 整体认证架构

### 3.1 架构图

```
微信小程序端                              管理后台（Web）
─────────────────────────────────────────────────────────
学生 / 家长                               各级管理员
wx.login + 手机号绑定                     账号+密码（超管+短信2FA）
        │                                        │
        └──────────────┬─────────────────────────┘
                       ▼
              统一身份服务（Auth Service）
              ┌─────────────────────────────┐
              │ - JWT 签发（RS256 非对称加密）│
              │ - Refresh Token 管理         │
              │ - Token 黑名单（Redis）      │
              │ - 角色权限校验中间件          │
              └─────────────────────────────┘
                       │
          ┌────────────┴────────────┐
          ▼                         ▼
     业务 API 层                管理后台 API 层
     (学生/家长数据)             (管理后台 API 层)
```

### 3.2 Token 策略

| 参数 | 小程序端 | 管理后台 |
|------|---------|---------|
| access_token 有效期 | 7 天 | 8 小时 |
| refresh_token 有效期 | 30 天 | 不颁发 |
| 续期方式 | 静默自动续期（用户无感知） | 不支持续期，过期须重新登录 |
| 无操作超时 | 无限制 | 30 分钟弹出确认倒计时（60秒后强制退出） |
| Token 存储位置 | 微信小程序本地缓存（wx.setStorageSync） | 浏览器 httpOnly Cookie |
| Token 签名算法 | RS256 | RS256 |

### 3.3 鉴权中间件流程

```
收到 API 请求
→ 读取 Authorization Header（Bearer Token）
→ 验证 Token 签名与有效期
→ 查询 Redis Token 黑名单（是否已注销）
→ 解析 role 字段，匹配当前接口的权限要求
→ 通过 → 转发至业务层
→ 拒绝 → 返回对应错误码（见第10章）
```

## 4. 小程序端登录模块

### 4.1 微信授权登录

#### 4.1.1 功能描述

用户无需手动输入账号密码，通过微信授权完成身份识别。首次授权需绑定手机号，后续打开小程序自动静默登录。

#### 4.1.2 交互流程

**新用户首次微信授权：**

```
步骤 1：用户点击"微信一键登录"
步骤 2：小程序调用 wx.login() → 获取临时 code
步骤 3：code 发送至后端 → 调用微信服务器换取 openid + session_key
步骤 4：后端查询 openid → 未绑定任何账号
步骤 5：前端进入手机号绑定页
步骤 6：用户选择身份（学生 / 家长）
步骤 7：输入手机号 → 点击"获取验证码"
步骤 8：后端发送短信验证码（60秒冷却，验证码5分钟有效）
步骤 9：用户输入验证码
步骤 10：验证通过 → 直接创建账号 → 签发 JWT（无论是否未成年，流程一致）
步骤 11：首次进入显示新手引导页
```

**老用户静默登录：**

```
步骤 1：打开小程序 → 自动调用 wx.login() 获取 code
步骤 2：后端用 code 换取 openid → 查询已绑定账号
步骤 3：读取本地缓存 access_token
  情况A：access_token 有效 → 直接进入首页
  情况B：access_token 过期，refresh_token 有效
         → 后端静默签发新 access_token → 更新本地缓存 → 进入首页
  情况C：两者均过期
         → 清除本地缓存 → 弹出"登录已过期，请重新登录"弹窗
```

#### 4.1.3 输入与输出

| 步骤 | 输入 | 输出 | 说明 |
|------|------|------|------|
| wx.login | 无（微信自动提供） | 临时 code（5分钟有效） | 前端调用 |
| code 换 openid | code、AppID、AppSecret | openid、session_key | 后端调用微信接口 |
| 查询 openid | openid | 用户信息或"未绑定" | 后端数据库查询 |
| 发送验证码 | 手机号 | 短信发送结果 | 后端调用短信服务 |
| 验证验证码 | 手机号、验证码 | 通过/失败原因 | 后端校验 |
| 签发 JWT | user_id、role | access_token、refresh_token | 统一身份服务 |

#### 4.1.4 约束条件

- C-401：同一微信账号（openid）只能绑定一个手机号，绑定后不可自行更改（须联系管理员）
- C-402：同一手机号只能注册一个学生账号或一个家长账号
- C-403：未成年人注册只需本人完成微信认证或手机号认证，无需家长确认，注册流程与成年人一致
- C-404：微信 session_key 不存储至数据库，仅在当次注册流程中使用
- C-405：验证码发送频率：同一手机号每分钟最多 1 次，每日最多 10 次（参数可配置）

### 4.2 手机号+验证码登录

#### 4.2.1 功能描述

用户通过手机号+短信验证码完成身份验证，适用于更换微信账号或首选手机号登录的场景。

#### 4.2.2 交互流程

```
步骤 1：用户点击"手机号登录"
步骤 2：输入手机号 → 点击"获取验证码"
步骤 3：后端校验手机号格式 → 发送短信验证码（60秒冷却）
步骤 4：用户输入6位验证码
步骤 5：后端校验验证码
  通过 + 手机号已注册 → 查询账号 → 签发 JWT → 进入首页
  通过 + 手机号未注册 → 进入注册流程（见 4.3）
  失败（≤5次）→ 提示"验证码错误，还可尝试X次"
  失败（>5次）→ 锁定该手机号 10 分钟，提示重试时间
```

#### 4.2.3 输入与输出

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|----------|------|
| phone | string | 是 | 11位数字，1开头，符合中国大陆手机号格式 | 手机号 |
| sms_code | string | 是 | 6位数字，5分钟内有效 | 短信验证码 |

**输出（成功）：**

```json
{
  "access_token": "eyJhbGciOiJSUzI1NiJ9...",
  "refresh_token": "dGhpcyBpcyBhIHJlZnJlc2gg...",
  "expires_in": 604800,
  "user": {
    "user_id": "uuid",
    "role": "STUDENT",
    "nickname": "同学1234",
    "grade": "GRADE_9"
  }
}
```

**输出（失败）：** 见第 10 章错误码

#### 4.2.4 约束条件

- C-421：验证码错误超过 5 次，锁定手机号 10 分钟（参数可配置）
- C-422：同一手机号 60 秒内只能发送一次验证码
- C-423：验证码在服务端生成，6位随机数字，有效期 5 分钟，使用一次即失效

### 4.3 新用户注册流程

#### 4.3.1 功能描述

手机号+验证码验证通过但账号不存在时，触发注册流程，收集用户基础信息并创建账号。

#### 4.3.2 交互流程

```
步骤 1：身份选择页：学生 / 家长（二选一）

--- 学生注册 ---
步骤 2S：填写基础信息
  - 年级（下拉：初一至高三）[必填]
  - 科目偏好（多选：数学/物理/化学）[选填]
步骤 3S：填写出生年份（用于系统记录，不影响注册流程）
步骤 4S：直接提交 → 创建账号（未成年人无需家长确认，微信授权后绑定手机号）

--- 家长注册 ---
步骤 2P：提示"请输入孩子提供的邀请码，或由老师/管理员帮您绑定"
步骤 3P-A：输入邀请码 → 校验 → 绑定关系创建 → 账号创建
步骤 3P-B：暂不绑定 → 仅创建家长账号，等待后续绑定
```

#### 4.3.3 输入与输出

**学生注册信息：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| phone | string | 是 | 已通过验证码校验的手机号 |
| role | enum | 是 | STUDENT |
| grade | enum | 是 | GRADE_7 至 GRADE_12 |
| subject_prefs | array | 否 | ["MATH", "PHYSICS", "CHEMISTRY"] 的子集 |
| birth_year | integer | 否 | 用于系统记录出生年份，不影响注册流程，不再用于判断是否需要家长确认 |
| wx_openid | string | 否 | 通过微信授权注册时传入，与手机号绑定 |

**家长注册信息：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| phone | string | 是 | 已通过验证码校验的手机号 |
| role | enum | 是 | PARENT |
| invite_code | string | 否 | 6位邀请码，选填 |
| wx_openid | string | 否 | 通过微信授权注册时传入 |

#### 4.3.4 约束条件

- C-431：同一手机号不能同时注册学生账号和家长账号
- C-434：邀请码绑定成功后，该邀请码立即失效（一次性使用）

### 4.4 退出登录（小程序端）

#### 4.4.1 功能描述

用户主动退出小程序登录状态，清除本地 Token，下次进入需重新验证。

#### 4.4.2 交互流程

```
步骤 1：用户在"我的"页面点击"退出登录"
步骤 2：弹出确认弹窗："退出后将清除登录状态，是否确认？"
步骤 3：确认 → 前端清除本地缓存（access_token、refresh_token）
步骤 4：后端将 refresh_token 加入黑名单（Redis，TTL 与原 token 过期时间一致）
步骤 5：跳转至登录页
```

#### 4.4.3 输入与输出

| 输入 | 输出 |
|------|------|
| refresh_token（请求 Header 携带） | 成功：HTTP 200，清除状态 |

### 4.5 换绑手机号

#### 4.5.1 功能描述

学生或家长更换手机号时，可通过微信授权验证身份后在个人中心自助完成换绑；也可联系超级管理员在后台手动修改。

#### 4.5.2 交互流程

**自助换绑流程（学生/家长）：**

```
步骤 1：用户进入"个人中心" → "账号设置" → "换绑手机号"
步骤 2：系统发起微信授权请求，验证当前登录用户身份
步骤 3：微信授权成功 → 跳转至手机号换绑页
步骤 4：输入新手机号 → 点击"获取验证码"
步骤 5：后端发送短信验证码至新手机号（60秒冷却，5分钟有效）
步骤 6：用户输入验证码
  通过 → 更新手机号 → 提示"手机号已更换成功"
  失败 → 提示"验证码错误，请重新输入"
步骤 7：当前所有已签发 JWT 立即失效，引导用户以新手机号重新登录
```

**管理员手动修改流程（SUPER_ADMIN）：**

```
步骤 1：超管在后台学生/家长管理页搜索目标用户
步骤 2：进入用户详情 → 点击"修改手机号"
步骤 3：输入新手机号 → 提交
步骤 4：系统向新手机号发送验证短信，用户完成验证后正式生效
步骤 5：操作日志记录（操作人、目标账号、旧手机号脱敏、新手机号脱敏、时间）
```

#### 4.5.3 约束条件

- C-451：自助换绑须先通过微信授权验证当前用户身份，验证通过后方可操作
- C-452：新手机号不能与系统内已注册的其他账号手机号重复
- C-453：换绑成功后，用户当前所有已签发 JWT 立即加入黑名单，须以新手机号重新登录
- C-454：管理员手动修改手机号须向新手机号发送验证短信，用户完成验证后方可生效

## 5. 管理后台登录模块

### 5.1 超级管理员双因素登录（2FA）

**适用角色**：SUPER_ADMIN

#### 5.1.1 交互流程

```
--- 第一步：账号密码验证 ---
步骤 1：输入用户名 + 密码
步骤 2：后端校验密码（bcrypt，cost=14）
  失败（累计 ≤5 次）→ 提示"密码错误，还可尝试 X 次"
  失败（>5 次）→ 账号锁定 30 分钟，同时发送告警至绑定邮箱+手机号
  通过 → 步骤 3

--- 第二步：短信验证码验证 ---
步骤 3：系统向超管绑定手机号发送6位验证码（5分钟有效）
        页面提示"验证码已发送至 138****8888"
步骤 4：用户输入验证码
  通过 → 签发 JWT（8小时）→ 进入超管视图
  失败（累计 ≤5 次）→ 提示"验证码错误，还可尝试 X 次"
  失败（>5 次）→ 账号锁定 30 分钟，发送告警邮件+短信

超管不支持"记住此设备"，每次登录必须完成两步验证
```

#### 5.1.2 输入与输出

**第一步输入：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| username | string | 是 | 超级管理员用户名 |
| password | string | 是 | 密码（前端MD5预处理） |

**第二步输入：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| sms_code | string | 是 | 6位短信验证码 |
| session_token | string | 是 | 第一步通过后返回的临时 session_token（5分钟有效），用于关联两步验证状态 |

**输出（两步均通过）：**

```json
{
  "access_token": "eyJhbGciOiJSUzI1NiJ9...",
  "expires_in": 28800,
  "admin": {
    "admin_id": 1,
    "role": "SUPER_ADMIN",
    "display_name": "超级管理员"
  }
}
```

#### 5.1.3 约束条件

- C-521：超管不颁发 refresh_token，不支持会话续期，8小时后必须重新登录
- C-522：两步验证的 session_token 有效期 5 分钟，超期须重新输入密码
- C-523：超管账号锁定时，同步发送告警短信和邮件（双渠道）
- C-524：超管不允许"记住此设备"功能，每次登录均须完成2FA

步骤 3：页面展示邀请码 + 剩余有效时间 + 复制/分享按钮
步骤 4：学生可通过微信"转发小程序"将邀请码发给家长

步骤 4：后端校验邀请码
  有效 + 未超上限（该学生已绑定<2个家长）→ 步骤 5
  无效/已过期 → 提示"邀请码无效或已过期，请让孩子重新生成"

步骤 5：绑定关系写入数据库
步骤 6：学生收到通知："家长账号[手机号后4位]已与您的账号绑定"
步骤 7：邀请码立即失效（一次性使用）
步骤 8：家长进入子女学习报告视图
```

#### 7.1.3 输入与输出

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| invite_code | string | 是 | 6位数字 |
| parent_user_id | string | 是 | 当前登录家长的 user_id（从 JWT 中获取） |

**输出（成功）：**

}
```

#### 7.1.4 约束条件

- C-711：邀请码有效期 48 小时，过期后学生须重新生成（参数可配置）
- C-712：每个学生最多绑定 2 个家长账号（参数可配置）

## 8. 安全与合规

### 8.1 密码安全

| 规则 | 说明 |
|------|------|
| 存储方式 | bcrypt 哈希（学生/家长端 cost=12，管理员 cost=14），不存储明文 |
| 传输方式 | HTTPS 全程加密，前端对密码进行 MD5 预处理后传输（防止明文暴露于网络层） |
| 密码强度 | 管理员密码：不少于8位，须同时包含大写字母、小写字母、数字 |
| 密码过期 | 管理员密码默认90天强制更换（参数可配置） |
| 临时密码 | 系统生成的临时密码12位随机字符，首次登录强制修改 |

### 8.2 接口安全

| 规则 | 说明 |
|------|------|
| 协议 | 全部接口强制 HTTPS，HTTP 请求重定向至 HTTPS |
| Token 签名 | RS256 非对称加密，私钥存储于服务器，公钥用于验签 |
| Token 黑名单 | Redis 存储，TTL 与 Token 剩余有效时间一致，自动过期清除 |
| 接口限流 | 登录接口：同一 IP 每分钟最多 20 次请求；发送验证码：同一手机号每分钟最多 1 次 |
| CSRF 防护 | 管理后台使用 httpOnly Cookie 存储 Token，配合 SameSite=Strict 策略 |
| SQL 注入防护 | 所有数据库查询使用参数化查询（Prepared Statement），禁止字符串拼接 SQL |

### 8.3 未成年人合规

| 规则 | 说明 |
|------|------|
| 年龄判断 | 注册时填写出生年份，系统判断是否未成年（<18岁） |
| 认证方式 | 未成年学生注册只需本人完成微信认证或手机号认证，无需家长确认，注册后账号立即激活可正常使用 |
| 数据保护 | 未成年人个人信息加密存储，AI 对话记录在注销后30天内完全清除 |
| 推送限制 | 晚22:00至次日7:00禁止向学生账号发送任何 App 推送 |

### 8.4 审计日志

所有以下操作均写入 `admin_audit_logs` 表：

| 操作类型 | 记录字段 |
|----------|---------|
| 管理员登录（成功/失败） | 操作人、时间、IP、结果 |
| 管理员登录锁定 | 账号、锁定时间、触发IP |
| 创建/修改/禁用管理员账号 | 操作人、目标账号、变更前后值、时间 |
| 角色变更 | 操作人、目标账号、旧角色、新角色、时间 |
| 密码重置 | 操作人、目标账号、时间（不记录密码值） |
| 家长-学生绑定/解绑（管理员操作） | 操作人、学生ID、家长手机号（脱敏）、时间 |

### 10.2 异常降级处理

| 异常场景 | 降级策略 | 用户提示 |
|----------|----------|---------|
| 短信服务不可用 | 提示用户稍后重试，系统告警通知运维 | "短信发送失败，请稍后重试" |
| Redis 不可用（黑名单查询失败） | 降级为仅校验 JWT 签名有效期，记录告警日志 | 用户无感知（安全性略降，运维尽快修复） |
| 微信服务器超时（code 换 openid） | 重试一次，失败后提示用户切换手机号登录 | "微信登录暂时不可用，请使用手机号登录" |
