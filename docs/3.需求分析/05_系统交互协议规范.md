## 1. 文档说明

### 1.1 为何需要本文档

各模块规格说明书独立定义了各自的交互逻辑，在以下场景产生了设计冲突：

| 冲突类别 | 具体问题 | 严重程度 |
|----------|----------|----------|
| 首页导航缺失 | 登录成功后跳转至哪个模块、Tab顺序和优先级未定义 | 🔴 阻断 |
| 模块主辅矛盾 | 03模块（题目驱动）与04模块（对话驱动）均主张自己是主线 | 🔴 阻断 |
| AI触发冲突 | 答错后 RAG（03模块）与智能助教对话（04模块）同时触发，优先级未定义 | 🔴 阻断 |
| 五力阈值不一致 | "薄弱五力"在03模块为 <65分，在04模块为 <50分 | 🟠 体验影响 |
| 前置依赖矛盾 | 03模块强制要求完成五力测试，04模块允许降级，规则不对齐 | 🟠 体验影响 |

**本文档作为最高优先级的跨模块契约，各模块规格说明书遇到与本文档冲突的条款，以本文档为准。**

### 1.2 修订影响说明

本文档的发布导致以下规格文档需同步更新（已在各文档备注）：

| 规格文档 | 影响章节 | 变更说明 |
|----------|----------|----------|
| 01_登录模块 | §2.1 应用场景S-01 | 补充登录后首页导航规则 |
| 02_五力认知测试 | §1.5 前置依赖 | 补充与03/04模块的衔接说明 |
| 03_个性化AI训练 | §1.1 模块目标、§1.2 设计原则 | 修订模块定位为"结构化训练"而非"主线" |
| 04_智能助教 | §1.1 模块目标、§4.3 AI介入决策 | 补充与03模块的AI调用协调规则 |

## 2. 首页导航架构

### 2.1 首页 Tab 结构定义

**（解决问题 A-001：登录后首页导航设计缺失）**

```
┌────────────────────────────────────────────┐
│              小程序首页                     │
│                                            │
│  ┌──────────────────────────────────────┐  │
│  │         五力状态卡（常驻顶部）          │  │
│  │  洞察力 52↓  建构力 48↓  [去测试 >]   │  │
│  └──────────────────────────────────────┘  │
│                                            │
│  ┌──────────┬──────────┬──────────────┐   │
│  │Tab 1     │Tab 2     │Tab 3         │   │
│  │个性化训练  │AI助教    │我的五力       │   │
│  │(03模块)  │(04模块)  │(02模块报告)  │   │
│  └──────────┴──────────┴──────────────┘   │
└────────────────────────────────────────────┘
```

### 2.2 Tab 定义与优先级

| Tab | 功能标题 | 对应模块 | 主要功能 | 导航优先级 |
|-----|----------|----------|----------|-----------|
| Tab 1 | 个性化训练 | 03_个性化AI训练 | 选知识点 → 做题 → RAG指导 | P0（默认选中） |
| Tab 2 | AI助教 | 04_智能助教 | 自由提问 / 错题复盘 / AI伴随 | P1 |
| Tab 3 | 我的五力 | 02_五力测试（报告） | 五力画像 / 历史对比 / 成长报告 | P2 |

**Tab 1（个性化训练）为默认选中 Tab，理由：** 学生最常见的使用场景是主动选知识点训练；AI助教更多是辅助手段，而非强制入口。

### 2.3 首页导航路由规则

**（覆盖 01_登录模块 §2.1 应用场景 S-01 的后置条件）**

```
登录成功
   ↓
是否存在有效 five_power_profiles 记录？
   │
   ├── 否（首次使用）
   │    └── 全屏引导页：强引导完成五力测试
   │         └── 点击"开始测试" → 02_五力测试模块
   │         └── 点击"稍后再说" → 进入首页（Tab 1），顶部横幅提示
   │
   └── 是（已有画像）
        └── 进入首页，默认选中 Tab 1
             └── 顶部五力状态卡展示最近2个薄弱维度
```

### 2.4 顶部五力状态卡规格

| 属性 | 规格 |
|------|------|
| 展示内容 | 最近一次五力测试的最弱 2 个维度 + 得分 |
| 数据来源 | `five_power_profiles`（取 `is_latest=true` 的记录） |
| 交互 | 点击卡片 → 跳转至 Tab 3（我的五力） |
| 更新时机 | 完成五力测试后实时刷新 |
| 无数据状态 | 显示"完成五力测试，解锁你的专属训练" + 按钮跳转 |

## 3. 用户旅程全链路

### 3.1 首次用户完整旅程

```
[注册登录]
    ↓ 01_登录模块
[五力测试引导]
    ↓
[完成五力测试] → 生成五力画像 + 个人训练方案
    ↓ 02_五力认知测试模块
[进入首页 Tab 1]
    │
    ├─ 路径A：主动训练路径（高频）
    │    ↓ 03_个性化AI训练模块
    │   [选择学科→年级→章节→知识点]
    │   [开始训练：5题专属题卷]
    │   [逐题作答]
    │       ├─ 答对 → 继续下一题
    │       └─ 答错 → RAG 解题思路（03模块内部）
    │            └─ 连续答错≥2次 → 触发 AI 助教介入（跳转 Tab 2 或悬浮提示）
    │   [训练小结] → 更新五力训练画像
    │
    └─ 路径B：AI陪伴路径（辅助/随时可切换）
         ↓ 04_智能助教模块
        [自由提问 / 错题复盘]
        [AI多维启发引导]
            └─ AI 判断需要实战检验 → 推荐"微训练入口"（2~3题）
                └─ 跳转 Tab 1 或弹出微训练浮层
        [理解突破] → 成就感反馈
```

### 3.2 模块间跳转矩阵

| 来源 | 目标 | 触发条件 | 携带参数 |
|------|------|----------|----------|
| 03训练 → 04助教 | 连续答错≥2次 | `training_session_id`、`question_id`、`error_count` |
| 04助教 → 03训练 | AI推荐微训练 | `knowledge_point_id`、`target_power`、`source_chat_session_id` |
| 03训练 → 03训练 | 完成当前训练，继续 | `next_knowledge_point_id`（可选） |
| 02五力 → 03训练 | 完成测试，开始训练 | `weak_powers[]`（最弱2维度） |
| 02五力 → 04助教 | 点击"问AI怎么提升" | `five_power_profile_id` |
| 任意 → 02五力 | 顶部五力卡 / Tab 3 | 无 |

## 4. 模块主辅关系与职责边界

**（解决问题 D-001：03 和 04 模块对"学习主体"的定位矛盾）**

### 4.1 模块定位声明

两个模块采用"**并行双轨 + 互相调度**"的协作模式，而非主从关系：

```
┌─────────────────────────────────────────────────┐
│                  学习主线                         │
│                                                 │
│  学生主动发起     ←→     AI感知后发起             │
│                                                 │
│  ┌────────────────┐    ┌────────────────────┐   │
│  │  03 个性化训练  │    │   04 智能助教        │   │
│  │                │    │                    │   │
│  │ "我要练这个点"  │    │ "我有个问题想问"    │   │
│  │ 结构化做题      │    │ "AI你来说说"       │   │
│  │ RAG解题思路    │    │ 多维启发对话        │   │
│  │ 五力训练画像   │    │ 策略自适应          │   │
│  └───────┬────────┘    └─────────┬──────────┘   │
│          │ 答错/困难时             │ 推荐实战时   │
│          └──────────↔────────────┘             │
└─────────────────────────────────────────────────┘
```

### 4.2 各模块职责边界（清晰划分，不允许越界）

**03_个性化AI训练模块 — 负责：**

| 职责 | 说明 |
|------|------|
| 结构化知识诊断与巩固 | 学生主动选知识点，系统精准出题 |
| 五力驱动选题 | 基于五力画像权重分配题型 |
| 答错即时 RAG 指导 | 检索相似题解析 + 五力策略文档，生成定向思路 |
| 训练画像更新 | 记录答题数据，异步更新 `five_power_training_profiles` |
| 错题记录生产 | 写入 `wrong_answer_records`，供 04 模块消费 |

**03_个性化AI训练模块 — 不负责：**
- 个性化启发策略切换
- 多轮自然语言对话
- 情感支持与内驱力培养
- 策略有效性档案管理

---

**04_智能助教模块 — 负责：**

| 职责 | 说明 |
|------|------|
| 学习陪伴与认知突破 | AI感知学生困难，主动或被动介入 |
| 多维启发引导 | 9种启发策略，自动切换，不重复无效策略 |
| 学生策略档案维护 | 记录每位学生对各种启发方式的响应效果 |
| 错题复盘对话 | 消费 03 模块产生的 `wrong_answer_records`，展开苏格拉底式复盘 |
| 微训练调度 | 在对话中判断需要实战检验时，调用 03 模块出 2~3 题 |

**04_智能助教模块 — 不负责：**
- 大规模结构化训练会话
- 题库管理与标注
- 五力训练画像的持久更新（仅读取，不写入 `five_power_training_profiles`）

### 4.3 功能重叠处理规则

| 功能 | 当前重叠状态 | 裁决 |
|------|-------------|------|
| 错题复盘 | 03模块：RAG 解题思路 / 04模块：对话复盘 | **两者互补**：03 提供结构化解法框架，04 提供认知过程引导。学生先查看 RAG（03），如仍困惑可点击"与 AI 深入讨论"进入 04 对话 |
| 启发引导 | 03模块：RAG 引导 / 04模块：多维启发对话 | **03 为第一层（解法层），04 为第二层（认知层）**：03 的 RAG 不得使用苏格拉底提问风格；04 的对话不得直接给出解题步骤 |
| AI Token 消耗 | 两模块均有 Token 预算，同一学习会话内可能叠加 | 见第5章 Token 联合预算管理 |

## 5. AI调用协议

**（解决问题 C-001：答错后 RAG vs 对话 AI 触发冲突；C-002：Token 定义歧义）**

### 5.1 两类 AI 调用的角色定义

| 调用类型 | 模块 | 触发方式 | 风格 | 输出 |
|----------|------|----------|------|------|
| **RAG 解题指导** | 03_训练 | 学生答错后自动异步触发 | 直接、结构化 | 解题步骤框架（≤200字） |
| **对话启发引导** | 04_助教 | 学生主动提问 / AI 主动介入 | 苏格拉底式 | 启发性问题或引导（≤400字） |

**两类调用的内容禁区（避免重叠）：**
- RAG（03模块）：**禁止**使用"你觉得…""想想看…"等苏格拉底风格，**必须**给出思路框架
- 对话（04模块）：**禁止**直接给出解题步骤，**必须**通过提问引导学生自主推导

### 5.2 同一答题事件的 AI 触发流程

```
学生提交答案
      ↓
系统判题
      │
      ├── 答对
      │    └── 不触发任何 AI 调用（沉默原则）
      │
      └── 答错
           │
           ├── Step 1：03模块 RAG 触发（P0，必然发生）
           │    └── 异步入队 Queue-C
           │    └── 前端展示骨架屏 + "AI 正在生成解题思路…"
           │    └── RAG 完成 → 展示"查看解题思路"按钮
           │
           └── Step 2：04模块介入判断（P1，条件触发）
                满足 ALL 条件时触发：
                ① 同知识点连续答错 ≥ 2 次
                ② 当前 chat_session 非 silence_mode
                ③ 当前训练会话 proactive_count < 3
                ④ 距上次 RAG 完成 ≥ 90 秒（给学生消化时间）
                ⑤ 本次 RAG 未超时/失败
                      ↓（触发）
                04模块创建 / 更新 ai_chat_sessions
                前端：答题区域下方出现"AI 助教有话说"悬浮条
                学生点击展开 → 进入对话（Tab 2 风格浮层）
                      ↓（不触发）
                仅展示 RAG 结果，等待学生主动求助
```

### 5.3 Token 统一计费规范

**（解决问题 C-002：两模块 Token 上限数值差异且含义不清）**

#### 5.3.1 术语统一

| 术语 | 定义 |
|------|------|
| Prompt Tokens | 发送给 AI 的全部内容 Token 数（含系统 Prompt + 用户输入 + 检索结果） |
| Completion Tokens | AI 生成的回复 Token 数 |
| Total Tokens | Prompt Tokens + Completion Tokens |

#### 5.3.2 各模块单次调用 Token 预算

| 模块 | 调用类型 | Prompt 上限 | Completion 上限 | Total 上限 | 说明 |
|------|----------|------------|----------------|-----------|------|
| 03_训练 | RAG 解题指导 | 1300 Token | 400 Token | **1700 Token** | 原文档"1500"指 Prompt 上限（含系统 Prompt ~150 Token） |
| 04_助教 | 对话启发引导 | 1050 Token | 800 Token | **1850 Token** | 原文档"1200"指 Prompt 上限（含系统 Prompt ~200 Token） |
| 02_五力 | 画像文字解读 | 800 Token | 500 Token | **1300 Token** | AI 个性化分析段落 |

> **勘误说明：** 03 模块原文档"单次上下文输入上限 ≈ 1500 Token"应理解为 Prompt Tokens 上限（含系统 Prompt），实际内容配额 ~1300 Token；04 模块原文档"单次输入上限 ≈ 1200 Token"同理，实际内容配额 ~1050 Token。两模块文档均需在各自约束章节补充此说明。

#### 5.3.3 单次学习会话联合 Token 预算

```
training_session 初始化时分配联合预算：

总预算：5000 Token / 次训练会话（后台可配置）

分配规则：
├─ 03_RAG 专项预算：1700 × N（N 为题目数量，默认5题）= 8500 Token
│   （注：每题均可能触发 RAG，预算按实际消耗计）
└─ 04_对话 专项预算：1850 × M（M 为对话轮数上限，默认3次主动介入）= 5550 Token

实际控制方式（简化版）：
- 不做精确联合预算，各模块独立控制各自 Token 上限
- 记录每次 AI 调用成本至 ai_token_usage 日志表（用于后台成本分析）
- 当单次训练会话 Total Tokens > 10000 时，后续 AI 调用降级至静态兜底
```

#### 5.3.4 Token 裁剪优先级（04 模块 Prompt 超限时）

当 04 模块 Prompt 超过 1050 Token 时，按以下顺序裁剪：

| 裁剪顺序 | 裁剪内容 | 节省量 |
|----------|----------|--------|
| 1（最先裁剪） | 历史对话从 10 轮减少至 5 轮 | ~300 Token |
| 2 | 近期错题从 3 条减少至 1 条 | ~100 Token |
| 3 | 五力画像从"最弱2维度"减至"最弱1维度" | ~40 Token |
| 4（最后保留） | 系统 Prompt + 当前对话轮 | 不可裁剪 |

## 6. 跨模块数据流转协议

### 6.1 五力画像数据优先级（读取规则）

**（解决问题 B-001：五力画像数据结构不一致）**

各模块读取五力画像时，统一遵循以下优先级：

```
查询学生最新有效五力数据：

Step 1: 查询 five_power_training_profiles（训练画像）
   └── 若存在且 updated_at > 7天前 → 使用训练画像（最新反映学生状态）

Step 2: 同时查询 five_power_profiles（测试画像）
   └── 取 is_latest = true 的记录

Step 3: 综合计算
   └── 若两者都存在：综合得分 = training_score × 0.6 + test_score × 0.4
   └── 若仅有测试画像：直接使用测试画像
   └── 若仅有训练画像：直接使用训练画像
   └── 若两者均不存在：
       - 03模块：返回 ERR-TR-001，禁止进入训练
       - 04模块：进入通用模式（无五力定向，AI使用默认策略）
```

### 6.2 错题集跨模块状态机

**（解决问题 B-002：错题集状态流转在各模块定义不同）**

```
错题状态机（wrong_answer_records.review_status）：

[03_训练模块] 学生答错
      ↓
  unreview（默认状态）
      │
      ├── [04_助教] 学生点击"AI复盘"
      │        ↓
      │   reviewing（复盘进行中）
      │        │
      │        ├── AI 检测到理解突破
      │        │        ↓
      │        │   aha_achieved（已突破）← 终态
      │        │
      │        └── 复盘结束但未突破
      │                 ↓
      │         pending_consolidation（待巩固）
      │                 │
      │                 └── 再次复盘 → 重入 reviewing
      │
      └── [03_训练模块] 该知识点重复答错≥2次
               ↓
         系统在 04 模块智能助教界面推送"推荐复盘"通知
         状态仍为 unreview，不自动变更
```

**`wrong_answer_records` 完整表定义**（在 03 模块数据章节补充）：

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|

## 7. 五力评分统一阈值规范

**（解决问题 E-002：五力弱阈值混乱，B-001 的一部分）**

**本章定义全系统统一阈值，所有模块以此为准，不得各自定义。**

### 7.1 五力得分分级标准

| 分级 | 得分区间 | 等级标签 | 界面标色 | 业务含义 |
|------|----------|----------|----------|----------|
| 困难 | 0 ~ 49 | 重点强化项 | 🔴 红色 | 第一优先级训练，AI重点关注 |
| 需改进 | 50 ~ 64 | 次重点项 | 🟡 黄色 | 第二优先级训练 |
| 良好 | 65 ~ 79 | 正常训练 | 🟢 绿色 | 按选择训练，无特别加权 |
| 优秀 | 80 ~ 100 | 优势维度 | 💚 深绿 | 可用于迁移学习场景 |

### 7.2 各模块对阈值的使用规则

**02_五力认知测试模块：**
- 重点强化项：得分 < 50（红色标注，在报告中排序最前）
- 次重点项：50 ≤ 得分 < 65（黄色标注）
- 正常训练项：得分 ≥ 65

**03_个性化AI训练模块（选题权重）：**

```
FOR EACH 五力维度 power_i:
    base_weight = 0.20  // 五力均分基础权重

    IF score_i < 50:
        weight_i = base_weight + 0.40  // 红色维度，额外加权 40%
    ELIF score_i < 65:
        weight_i = base_weight + 0.20  // 黄色维度，额外加权 20%
    ELSE:
        weight_i = base_weight         // 绿色维度，无额外加权

// 归一化，确保所有权重之和 = 1
weights = normalize(weights)
```

**04_智能助教模块（AI对话倾向）：**
- "最弱维度"：得分最低的 1 个维度（无论分值，始终存在）
- "关注维度"：所有 score < 65 的维度（0~5 个，按 7.1 中"困难"+"需改进"分级）
- 当所有五力 ≥ 65（全部良好/优秀）时：AI 使用通用策略，不进行五力定向启发

> **勘误说明：** 04 模块原文档 §4.2.2 中"洞察力弱（<50分）"与 03 模块"薄弱五力（<65分）"定义不同，统一按本章 7.2 执行。04 模块的"关注维度"判定标准统一为 <65 分。

## 8. 跨模块错误处理与降级链路

### 8.1 前置依赖失败的处理规则

**（解决问题 A-002：05力测试前置依赖在 03 vs 04 中要求不一致）**

| 模块 | 无五力画像时 | 有五力画像但 AI 不可用时 |
|------|-------------|----------------------|
| 03_训练 | 🔴 强制拦截，展示测试引导页，禁止进入训练 | 降级：选题使用平均权重（各五力 20%），RAG 超时展示静态解析 |
| 04_助教 | 🟡 允许进入，进入通用模式（无五力定向），第一轮对话中提示学生完成测试 | 降级：展示静态知识卡片 + FAQ |

**差异设计说明：** 03 模块强制依赖五力测试，因为"个性化选题"算法的核心是五力权重；无画像则无法生成有意义的题卷，允许进入会损害核心价值。04 模块允许降级，因为"对话本身"仍有价值，五力数据仅用于增强指导精准度。

### 8.2 AI 服务全局降级策略

```
AI 服务可用性检测（每次调用前）：

IF AI API 不可用（5xx / 超时 > 5秒）：
    ├── 03_训练模块（RAG）：
    │    └── 展示题目 solution 字段的静态解析文本
    │    └── 标注"AI 助手暂时繁忙，展示参考解析"
    │
    └── 04_助教模块（对话）：
         └── 展示预置静态知识卡片（按当前知识点分类）
         └── 展示"AI 助教暂时休息，可以先查看这些参考内容"
         └── 提供"知识点 FAQ"预置回答（后台可维护）

两个模块降级时均：
    ├── 记录降级事件至 system_downgrade_log
    ├── 不计费（此次 AI 调用不记录 token 消耗）
    └── 不阻断主流程（学生仍可继续训练 / 对话入口可见但置灰）
```
